## 3. 裁决

### 3.1 主基准 = **gem5 Ruby**

**理由(按权重)**:

1. **M3 只由它满足** —— R7 的缓解必须是**独立于本仓维护者**的第三方资产;另两个选项都做不到
   (ArchForge 是同一作者、RTL 在外部团队手里且不可控)。
2. **可得且可复核** —— 上游可达、配置与 trace 可留档重跑 ⇒ 结论**可被第三方复现**。
3. **与 H7 的判据类型匹配** —— H7 比的是**延迟偏差**,需要一个**能跑真实 cache 层级**的参考实现;
   gem5 的 Ruby cache 模型正好提供「命中延迟 / 未命中延迟 / 容量 / 替换」四个可对齐的量。

### 3.2 **ArchForge 参考模型 ⇒ 降为「交叉验证」,不计作 M3**

- **同作者** ⇒ **不满足** M3 的独立性要件 ⇒ **不得**用它的延迟值来判定「H7 是否成立」。
- **保留用途**:① **结构 / 语义对照**(如 `09-coherence-protocol.md` 的协议阶段划分 vs 本仓 6 层);
  ② **追认债 #1 / #2 / #3 的对照材料**(跨仓语义问题本就归它)。
- ⚠️ 记入台账:凡「与 ArchForge 参考模型一致」的表述,**不得**被读作「已通过独立对拍」。

### 3.3 **RTL benchmark ⇒ 不作主基准**(保留为可选)

- 本地**无资产**、依赖外部团队排期 ⇒ 作为主基准会把 R7 的闭合绑定到**不可控**的外部依赖上。
- **不注销**:改绑触发条件(§6)。

### 3.4 三选项的共同边界

- **对拍基准只判定「性能模型的可信度」(H7)**,**不**判定协议语义正确性 ⇒ 语义正确性仍归
  **ArchForge 逐格追认**(per `ADR-CEP-12 §13` 权威分区 + 跨仓债 #1/#2/#3)。
- **对拍通过 ≠ 平台结论正确** —— 只说明「本仓的性能模型没有明显偏离第三方」。

## 4. 对拍手段说明(可执行规格)

### 4.1 访问流契约 —— 两侧**消费同一条离线 trace**

- **不用**两侧各自的 RNG:`TrafficGenTLM` 的 `rng_(42)` 是本仓内部种子 ⇒ 两侧**无法**各自生成同一条流。
- **规定**:由本仓侧脚本 `scripts/cep/parity_trace_gen.py`(待建)生成 **确定性访问序列**
  (`addr, is_write, size` 三列,固定 LCG 种子 + 可声明的地址分布),两侧**读同一文件** ⇒ 访问流**逐条相同**。
- **规模**:主对拍 **≥ 10⁵ 事务**(与 `verification_scope` 声明一致);命中/未命中比由 trace 生成器
  的**工作集大小**控制(见 4.2)。

### 4.2 模型对齐表(**对拍前必须先承认的差异**)

| 量 | CppTLM 侧 | gem5 侧 | 对齐要求 |
|---|---|---|---|
| 访问流 | 离线 trace 文件 | 同一 trace 文件 | **逐条相同**(§4.1) |
| 缓存容量 | ⚠️ `CacheTLM` 是**无限容量 + 精确地址 map**(无容量限制、无替换) | 有限容量 + LRU 等 | **显式声明为结构性差异** ⇒ 判据**分列**(下) |
| 命中判据 | 该地址曾被命中/写入 | 容量内命中 | 若不引入容量模型,则**命中率不可直接比** |
| 命中延迟 | 硬编码 **5 cycle** | 可配(`cache_latency`) | **配成同值** ⇒ 比的是**未命中路径 + 容量效应**,不是命中延迟 |
| 未命中延迟 | 硬编码 **50 cycle** | 可配 | **配成同值** |
| 时基 | cycle(每 cycle = 1 ns,per `docs/designs/dgpu-soc/timing-mode.md §2.4`) | `sim_freq` | 归一到**每事务周期数** |
| 协议开销 | TLM 事务级(无逐拍细节) | gem5 逐拍 | ⚠️ **协议开销不对齐** ⇒ 偏差**必须**按 §4.5 归因,**不得**直接判「模型不准」 |

⇒ **判据分两档**(防止把「容量模型错配」误判成「H7 不成立」):

- **主对拍(容量对齐档)**:本仓侧引入**等容量 + 同替换**的目录视图(可复用
  `HierarchicalDirectory` 的逐级位掩码 + 显式 LRU)⇒ 比 **命中率 ± 5 个百分点** + **延迟偏差 < 15%**;
- **辅助对拍(常数档)**:保持现有 `CacheTLM`(无限容量 + 5/50 固定)⇒ **只比未命中路径延迟常数**
  ⇒ 判据 = **偏差 < 15%**,且**命中率不参与判定**。

### 4.3 指标对齐与归一

| 指标 | CppTLM | gem5 | 归一 |
|---|---|---|---|
| 平均访问延迟 | `avg_latency_cycles`(metrics schema 已定义) | `system.cpu.numCycles` / 完成事务数 | **每事务周期数**;两侧同 `sim_freq` 折算 |
| 命中率 | `stats_hits_ / stats_requests_`(`CacheTLM` 内建) | gem5 stats | 百分比 |
| 总事务数 | `total_transactions` | 完成事务数 | 必须**相等**(trace 逐条相同 ⇒ 天然相等) |

### 4.4 判据(机器可判)

| # | 判据 | 阈值 | 失败含义 |
|---|---|---|---|
| **P-1** | 总事务数两侧相等 | **必须相等** | trace 消费不一致 ⇒ 对拍无效(**先查这个**) |
| **P-2** | 主对拍:平均访问延迟偏差 | **< 15%** | H7 **不成立** ⇒ 取舍判断不可信 |
| **P-3** | 主对拍:命中率偏差 | **≤ 5 个百分点** | 容量/替换模型未对齐 ⇒ 先修模型,再判 H7 |
| **P-4** | 辅助对拍:未命中路径延迟偏差 | **< 15%** | 时基或延迟口径不一致 |
| **P-5** | 每次对拍必须声明 `verification_mode` + `verification_scope` | 字段齐备 | 违反 `ADR-CEP-06 §3` ⇒ 结果**不得**表述为「已证明」 |

> **P-2 的分母与方向**:偏差 = `|cpp - gem5| / gem5`(gem5 为参考侧)。**gem5 侧为 0** 时
> 改用绝对差 + 相对阈值双判,避免除零。

### 4.5 失配归因(4 类,**必须**逐类排除后再判 H7)

| 类 | 现象 | 排查 | 处置 |
|---|---|---|---|
| **D-1 容量模型** | 命中率显著偏离 | 比 P-3 | 调工作集 / 引入容量模型 ⇒ 重跑 |
| **D-2 替换策略** | 命中率随工作集**非线性**变化 | 比不同工作集下的命中率曲线 | 对齐替换策略 ⇒ 重跑 |
| **D-3 时基归一** | 偏差**恒定比例**(如整 2×) | 比 `sim_freq` 与 cycle 假设 | 修正归一 ⇒ 重跑(**最易误判为「模型不准」**) |
| **D-4 协议开销** | 偏差随事务类型**系统性**偏移 | 按读写/命中拆分 | 本仓 TLM 不建模逐拍 ⇒ **登记为已知上限**,不据此判 H7 |

### 4.6 失配时的降级(per R8 口径)

若首轮对拍无法在合理成本内闭合(例如 D-4 不可消除、gem5 构建不可用):
⇒ **降级**为「**仅 CppTLM 内部对比**」(per `§8.1 R8` 的缓解口径)⇒ **显式登记**该降级 +
把 H7 标为「**未验证**」⇒ **不得**表述为「已验证」。

## 5. 本仓的已知结构性差异(**对拍前先承认**)

1. `CacheTLM` = **无限容量 + 精确地址 map + 硬编码延迟**(hit 5 / miss 50 cycle)
   ⇒ 与真实 cache 的命中率分布**结构上不同** ⇒ 判据必须分列(§4.2)。
2. 本仓是 **TLM 事务级**(无逐拍细节)⇒ 协议级开销**不对齐**(归因类 D-4)⇒
   **延迟偏差的合格线 15% 是「模型级」口径,不是「周期精确」口径**。
3. `TrafficGenTLM` 种子固定 `42` ⇒ 两侧**不共用 RNG**,必须走离线 trace(§4.1)。
