## 2. 发明背景与待解决问题

**应用场景**：应用经 API 发出 draw command（draw call）；图形驱动把 draw command 交给 GPU。draw command 含指向 index buffer 的地址；index buffer 是构成图形对象（点、线段、三角形、四边形、surface patch）的顶点指针列表。复杂对象含成千上万乃至数百万 index。

**现有技术**：GPU 把 index 分成工作单元 "batches" 分发给各图形管线；分发前由 GPU 内的 **primitive distributor 执行 index scan，逐 index 分析以消除重复 index**（相邻图元共享顶点造成重复）。

**三大不足（原文）**：
1. 计算强度："if the primitive distributor were to analyze M indices simultaneously, and... compare each index with the preceding N index to search for duplicates, then the index analysis process would be MxN in computational intensity."
2. 速率瓶颈："the graphics processing pipelines implemented within a GPU can typically process batches at a faster rate than the primitive distributor can analyze indices and create new batches, creating a performance bottleneck."
3. 带宽压力："the primitive distributor generally accesses M indices during every clock cycle"——每时钟生成 4 个三角形、每个需 3 个 index 即需 12 index/时钟；提升吞吐要增大并行分析数或对比深度，"increases the design complexity... and further increases the demand on memory bandwidth."

**结论**："what is needed in the art is [a] more effective approach for distributing work in a GPU."

## 3. 核心方案

### 3.1 整体架构（FIG. 1–4）

**PPU 202（FIG. 2）**：I/O unit 205 → host interface 206（读 pushbuffer）→ front end 212 → **task/work unit 207**（内含 "work distribution unit (not shown)"，接收编码为 TMD 的任务指针；task/work unit 207 保证 GPC 处于 valid state 后才发起任务）→ processing cluster array 230（C 个 GPC 208）；crossbar unit 210 路由 GPC 输出到 partition unit 215/DRAM 220 或其他 GPC。

**图形处理管线 350（FIG. 3）**：PD 355（primitive distributor）→ VAF 360（vertex attribute fetch）→ VTG 365（vertex/tessellation/geometry）→ VPC 370（viewport scale, cull, clip）→ tiling unit 375 → setup 380 → rasterizer 385 → PS 390（pixel shading）→ ROP 395；分为 **world-space pipeline 352**（PD 355→VPC 370，又分 alpha/beta phase）与 **screen-space pipeline 354**（setup 380→ROP 395）。

**primitive distribution system 400（FIG. 4，本发明落位）**：
- **central primitive distributor 410** + **GPC synchronization processor 420**：位于 FIG. 2 的 **task/work unit 207** 内（原文："The central primitive distributor 410, and GPC synchronization processor 420 reside within the task / work unit 207"）；
- **distribution crossbar unit 430**：位于 FIG. 2 的 **crossbar unit 210** 内；
- 各 GPC 208 内含 **GPC primitive distributor 440**（local primitive distributor）；
- 变体：synchronization processor 420 也可放进 crossbar unit 210（更靠近 GPC）；整个系统 400 可实现于 FIG. 3 的 PD 355 内。

数据流：front end 212 → central PD 410（切 work slice）→ distribution crossbar 430 → GPC 208；GPC PD 440 扫描后经 distribution crossbar 430 → synchronization processor 420 → publish 回各 GPC。

### 3.2 关键机制详解

**① 不访索引的切分**：draw command 携带 primitive 类型（line segment / triangle strip / triangle fan）、index buffer 首位置与总 index 数。central PD 410 把 draw command 切成大小近似相等的 **work slices**，每片含总 index 的一个子集，**切分时不访问 index 本身**（"without accessing the indices"）；每片可视作一个 sub-draw command。**相邻片重叠**若干 index：line segment 重叠 1 个、triangle strip 重叠 2 个，使下游 GPC PD 不必跨片取数。示例：896 个 index 的 triangle strip、每片 300 → WS0: 0–299，WS1: 298–597，WS2: 596–895。

**② 分配与路由**：策略可为 round robin / first available / priority-based；slice 数 ≤ GPC 数则一对一，否则一个 GPC 多片（3 GPC/7 slice → 2+2+3）。central PD 410 把 work slice 发给 distribution crossbar 430，并把标识被指派 GPC 的 **GPC identifier** 发给 synchronization processor 420（全局单元，记录 work slice ↔ GPC 日志）。

**③ 分布式 index fetch + scan**：各 GPC PD 440 **并行**从内存 index buffer 取回本片 index（"distributed index fetch"），fetch 同时执行 index scan，记录后续 GPC 所需特征：本片最后一个 **restart index** 的存在与位置（restart index 标记一条图元链的结束与下一条链的开始）；片内 primitive 类型变化（strip↔fan）；片末 primitive 的 **winding order**、**graphics primitive identifier**、**instance identifier**；片末 **vertex identifier**；triangle fan 的 **anchor vertex** 标识、片内最后一个 multi-vector primitive 的起始 index。

**④ 反馈发布与批处理**：scan 完成后 GPC PD 440 生成 **feedback packet** → 经 distribution crossbar 430 送 synchronization processor 420 → 420 依据日志 **publish** 给处理同一 draw command 的其他 GPC；GPC PD 440 收齐所需 published feedback packet 后，把 **work slice + published feedback packet** 交给 GPC 内其他单元做 primitive assembly、batch generation、vertex shading、tessellation、geometry shading、rasterization、pixel shading。

**⑤ 延迟隐藏（FIG. 8）**：GPC PD 440 的 fetch memory 为 multi-buffered，实施例为 **triple-buffered**（buffer 810/820/830），流水线三段 Idx Scan → Feedback + Publish → Batching；一条 draw command 生成 15 个 work slice（WS0–WS14）round-robin 分到 3 个 GPC（GPC0←WS0,3,6,9,12 等），三个 buffer 交错扫描，"the overhead for processing work slice indices... is, in large part, performed in parallel with batching and rendering."

**⑥ 实施例验证（FIG. 5–7）**：FIG. 5：strip{0..4(R),5..11}，WS1 即使不知道 WS0 中的 restart 4(R) 绕序仍正确；FIG. 6：restart 5(R) 落在影响 WS1 绕序的位置，不知 restart 会渲染出错误三角形{7,8,9}…，收到 feedback 后纠正为{8,7,9}…；FIG. 7：triangle fan 的 anchor 在 restart 后从 0 变为 5，不知则错误使用 anchor 0。三图说明 feedback packet 携带的特征恰好覆盖所有跨片依赖。

**⑦ 方法流程（FIGS. 9A-9B，method 900）**：902 central PD 收到 draw command → 904 切成多个 work slice → 906 为每片指派 GPC → 908 传送 → 910 GPC PD 接收 → 912 取回本片 index → 914 scan 识别特征 → 916 生成 feedback packet → 918 经 distribution crossbar 发给 synchronization processor → 920 接收 published feedback packet → 922 把 work slice + packet 交给 GPC 内其他单元继续处理。

## 4. 权利要求摘要

共 20 项，独立权利要求 1（方法）、9（primitive distribution system）、18（graphics processing unit）。

**独立权利要求 1（方法）**：① 接收与图形对象相关的 draw command（关联多个 index）；② 切成多个 work slice，每片对应 index 集合中不同子集；③ 扫描第一 work slice 对应的第一 index 子集，识别影响第二 work slice 图形处理的**第一组图形处理特征**；④ 扫描完成后对第一 work slice 执行图形处理，并**至少部分并行地**、基于第一组特征对第二 work slice 执行图形处理。

claim 9 为系统版（central primitive distributor + 第一 local primitive distributor）；claim 18 为 GPU 版（另含第一/第二图形处理管线，强调两管线并行处理两个 work slice）。

从属权利要求按主题分组：
- **特征内容**：restart index 位置（2/19）、triangle strip winding order（3/20）、triangle fan anchor point（4）、graphics primitive identifier（10）、instance identifier（11）、vertex identifier（12）；
- **并行扫描扩展**：扫第三子集识别第四子集所需特征（5）；第二 local distributor 并行扫第二子集（13）；
- **feedback/同步**：生成并发送 feedback packet（6）、从 synchronization processor 收第二 feedback packet（7/15）、synchronization processor 转发（14）；
- **基于 feedback 修正**：改 winding order（8/16）、改 anchor point（17）。

## 5. 与 WDU / Work Distribution Crossbar 的关系

1. **与通用 WDU 同居一室、分工并列**：全文 "work distribution unit" 仅出现一处——"front end 212 transmits processing tasks... to a work distribution unit (not shown) within task / work unit 207. The work distribution unit receives pointers to processing tasks that are encoded as task metadata (TMD)"。本发明的 primitive distribution system 400 与这个通用 WDU 同位于 task/work unit 207：WDU 分发 TMD 级计算任务，本系统分发图形 draw command 的 index 级 work slice——task/work unit 是"计算任务分发"与"图形工作分发"两条分发链的共同载体。
2. **distribution crossbar 430 是第三条 crossbar**：区别于 PPU 级 crossbar unit 210 与 GPC 内 work distribution crossbar 330，distribution crossbar unit 430 内嵌于 crossbar unit 210，专用于 work slice 下发与 feedback packet 回传；说明 NVIDIA 在片上互连中为前端几何分发开辟了专用通路。
3. **"batches" 术语的承继**：背景技术中 "the GPU usually divides the indices into units of work, referred to as batches" 与 US9594599B1 的 work batch 概念呼应；本专利把 batch 生成从中央串行 scan 改为分布式 scan + 本地 batching，batching 阶段下沉到各 GPC PD 440。
4. **扩展性结论（原文）**："The quantity of primitive distributors analyzing indices scales linearly with the quantity of graphics processing pipelines processing the indices"；"Each GPC can work at lower primitive rate, and hence the memory bandwidth requirement for each GPC is lower."

## 7. 评价与启示

**技术重要性**：
- 把前端几何处理的核心瓶颈（中央 index scan 的 MxN 复杂度 + 带宽集中）转化为"切分不访索引、扫描随 GPC 数线性扩展"的分布式流水，是 NVIDIA 图形前端从中央 primitive distributor 向 GPC 内并行几何管线演进的关键一环；
- 重叠区 + feedback packet 的设计优雅地解决了切分引入的跨片依赖（restart、winding order、anchor vertex），且 feedback 流量极小（每片一个 packet）；
- triple-buffered fetch 让 scan 开销与 batching/rendering 完全重叠，分发开销被掩盖。

**局限性（基于文本可推断）**：
- 切分按 index 数量均分而非按实际几何复杂度，tessellation/几何着色放大率差异大时各片负载仍可能不均；
- 依赖 synchronization processor 420 作为全局日志与发布中枢，超大规模 GPC 阵列下该单元可能成为新瓶颈（文本给出将其移入 crossbar 的布局变体作为缓解）；
- 原文小误：FIG. 9 框文 "INDLUDING"（INCLUDING）、"GPM synchronization processor"（GPC）、"W810"（WS10）、正文 "the VPC 450"（应为 370）。

**对本专题的价值**：本专利（2015 申请）展示了 task/work unit 207 内**第二条分发链**的完整形态——若说 WDU 340 管"计算任务去哪个 GPC/SM"，primitive distribution system 400 管"图形 index 工作去哪个 GPC、以什么顺序"；它与 US8941653B2（保序分布式光栅化）共同构成图形工作从 draw call 到光栅化的完整分发谱系。
