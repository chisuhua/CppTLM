## 2. 发明背景与待解决问题

**相关技术批评（0004 段）**：传统多处理器系统的计算任务优先级由应用程序或驱动决定，执行期间驱动与多处理器之间的交互（用于允许驱动调度任务）会延迟任务执行。

**需求陈述（0005 段原文）**："what is needed in the art is a system and method for dynamically scheduling compute tasks for execution based on the processing resources and priorities of the available compute tasks. Importantly, the scheduling mechanism should not depend on or require software or driver interaction."

即：把优先级调度从"驱动软件决策"下沉为"硬件电路动态决策"。这是 Kepler 世代 task/work unit 207 硬件化的组成部分，与 US20130198760A1（同附图族、晚 5 个月申请的姊妹案）共同构成 TMU 300 + WDU 340 的完整披露。

## 3. 核心方案

### 3.1 架构位置（FIG. 2/3）

PPU 202 内 host interface 206 读 pushbuffer → front end 212 → **task/work unit 207** → processing cluster array 230（C 个 GPC 208）；crossbar unit 210 与 memory interface 214（D 个 partition unit 215 + DRAM 220）。GPC 208 的处理任务由 task/work unit 207 内的 **work distribution unit** 送达：WDU 接收指向 **QMD（queue metadata）** 的指针，QMD 存于 PP memory 204 或 system memory 104，封装执行一个计算任务所需的状态（数据索引、状态参数、要执行的程序），每个 QMD 可指定调度优先级（0030 段）。

**task/work unit 207 = task management unit 300 + work distribution unit 340**（FIG. 3，0037 段）：

- **TMU 300（scheduler table 321）**：按优先级组织任务——每个优先级一个 QMD group，组内为指向 QMD 322 的**链表**；接收速率与调度速率解耦（0037 段）。
- **WDU 340（task table 345）**：槽位表，每槽被一个正在执行任务的 QMD 占据；有空槽才调度，无空槽时高优先级任务可**驱逐**低优先级在槽任务（0038 段）。

### 3.2 scheduler table 321 的组织（FIG. 4A，0040–0044）

每个 QMD group 存 head/tail 指针与 empty bit；新任务到达时默认插到链表**尾部**，QMD 中的特殊位（add-to-head flag）可令其插到**头部**——同优先级内链表头部即相对更高优先级（TABLE 1 例：task 413 置 TRUE 插到 group 400 头部，虽然与 task 411 同为优先级 0，但先被调度）。QMD group 是 QMD 结构的一部分，任务执行期间不可改组。

缓冲的意义（0044 段）：TMU 从多个 pushbuffer（来自不同应用）接收任务的速率快于 WDU 的执行吞吐，先入 scheduler table 再择机输出，使 TMU 能"看到后来者"——典型场景是先到一批低优先级任务、后到一个高优先级任务，缓冲使高优先级任务得以插队。

### 3.3 三种调度方案（0045–0066）

1. **round-robin（0046）**：各非空组按组轮转，每组取链表头。TABLE 1 序列的调度序为 413→410→411→412。
2. **priority（0047）**：严格优先级，总取最高非空组的头部。TABLE 1 序列为 413→411→410→412。
3. **partitioned priority（0060–0065，FIG. 5B）**：task table 345 的**每个槽位带一个掩码**，指明哪些优先级组可占据该槽——部分槽位被划给低优先级组，使低优先级任务可与在等高优先级任务**并发执行**（否则严格优先级下低优先级会被无限推迟）。多组均合格时先查最高优先级组。

### 3.4 槽位准入与驱逐（FIG. 5A method 500，0048–0059）

槽位状态三分：UNUSED（未用）/ ACTIVE（执行中）/ EMPTY（已完成待回收）。调度流程：

- step 505：选 scheduler table 中最高优先级任务；
- step 510：有 UNUSED 槽 → 直接入槽（540/545）；
- step 512：否则找 EMPTY 槽——**先回收已完成任务的槽**，把已完成任务状态交回 TMU 后槽位转为 UNUSED（535）；
- step 515/520：再无可回收槽，则找 task table 中**最低优先级**的 ACTIVE 任务比较——新任务优先级更高才驱逐（525），否则放弃本轮调度（550）；
- step 525/530/535：令 WDU **停止**被驱逐任务执行，把其重新加回 scheduler table 对应优先级组的**链表头部**，状态（执行上下文）一部分存 TMU 内、一部分写回该任务的 QMD；
- step 545：新任务转入 task table 槽位激活，多槽任务并发执行；并发任务数可随负载变化。

同优先级平局规则（0049 段）：两任务同级时，**最近转入 task table 者**视为较低优先级（优先被驱逐）。被驱逐任务重调度时从中断处继续执行（0050 段）。FIG. 4B–4E 用 2 槽 task table 演示了完整时序：410/411 先入槽 → 413 到达 → 驱逐最低优先级 410（回到 group 402 头部）→ 411 完成置 EMPTY → 410 回填补位。

### 3.5 QMD cache 605 与 hardware-only 分区（FIG. 6A/6B，0067–0071）

QMD 是大结构（**256 字节以上**，存 PP memory 204），访问带宽代价高，故 TMU 600 内置 **QMD cache 605**，只缓存调度所需的小部分；任务真正被调度（转入 WDU 640）时再从显存取回完整 QMD。

**QMD 复用的写回冲突（0069 段）**：任务完成后其 QMD 可被软件回收复用写新任务；但 cache 中可能还留着旧任务的脏项，flush 写回会覆盖新任务数据，且软件写入后立刻经 pushbuffer 提交、收不到 flush 确认。解法：QMD 划出 **hardware-only 分区**（仅 TMU 可访问）；发射 QMD 的命令可指定"首次装入 cache 时把软件区数据复制到 hardware-only 区"，用新任务数据覆盖残留的旧任务数据（FIG. 6B，step 602/612/620/625）。

## 5. 与本专题主题的关系

这篇是 **Kepler task/work unit 207 优先级调度机制的正本披露**，与 13 号专题既有条目互补：

1. **WDU 340 / Task Table 345 的机制出处**：综述第二节"WDU 340（Kepler）"行此前以 US20130198760A1、US8572573B2 为据，本件补上了三块关键细节——槽位三态机（UNUSED/ACTIVE/EMPTY）、先回收 EMPTY 后驱逐 ACTIVE 的准入顺序、同优先级平局按"最近转入先驱逐"；
2. **GK110 白皮书的硬件底本**：GK110 白皮书称每个 work distributor 维护 pending（32）/active（4）任务槽，本件的 scheduler table 321（pending 链表）与 task table 345（active 槽位）即其对应物；16 号专题 US20240036952A1 的 WDU 5214（32 pending/4 active per GPC）正是该结构的现代延续；
3. **实验侧直接印证**：libsmctrl（RTAS'23/ECRTS'25）观测到的"每优先级并发任务上限"、高优先级流抢占低优先级流并发额度，正是 partitioned priority（槽位掩码）+ 驱逐机制的可观测行为——综述第八节的印证链条由此从"结构对应"升级为"机制对应"；
4. **抢占语义的早期形态**：驱逐即任务级抢占（停止→保存状态→重入队→断点续执），为后续 US10552202B2（CTA 级抢占、排空 GPC）与 stream priority API 行为提供了前端侧源头；
5. **与姊妹案的分工**：US20130198760A1（2012-02-03）侧重 task/work unit 207 的总体结构与依赖任务入队，本件（2011-09-19）侧重优先级组织与槽位准入/驱逐策略，两案同附图族、互不引用。

## 7. 评价

**披露价值**：在 NVIDIA 任务前端专利群中，本件是"优先级如何影响 CTA 上 SM"这一问题最完整的早期答案——组链表 + 三态槽位 + 两阶段准入（先 EMPTY 后驱逐）+ 槽位掩码分区，四件套齐备且附图（4B–4E 时序图、5A/5B 流程图）可直接对应硬件状态机。QMD cache 与 hardware-only 分区则是少见的元数据缓存一致性细节，解释了"QMD 被软件复用"与"硬件缓存脏项"的冲突解法。

**局限**：US 申请中途放弃（2011 年申请、2013 年公开后未答复审查意见或主动放弃），权利从未在美生效，保护实际落在 TWI639118B 与 DE102012216568B4；权利要求措辞宽泛（claim 1 仅覆盖"头部选取 + 最低优先级替换"），若授权其先有技术抗辩空间亦不小。机制本身随 Volta 计算抢占（US10552202B2）与 stream priority 软件接口的公开而部分"去神秘化"，但 partitioned priority 的槽位掩码细节至今仍是理解 per-priority 并发上限行为的唯一一手文本。

**阅读建议**：与 US20130198760A1（结构）、US8572573B2（调试重入队）、US9710306B2（槽位节流）并读，构成 Kepler WDU 四件套；实验对照见 rtas23.pdf / ecrts25.pdf。
