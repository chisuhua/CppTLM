## 2. 发明背景与待解决问题

**API 保序要求**："The DirectX and OpenGL APIs require that the primitive order be maintained, that is to say, the primitives must be rendered in the order presented by the application program." 原因有二：相交图元必须确定性渲染以避免视觉伪影；后一图元的渲染结果可能依赖先前帧缓冲状态（尤其使用 blending 时）。

**现有技术的天花板**：传统 GPU "have processed primitives at a rate of up to one triangle per clock while maintaining the... API specified primitive order"；而 "systems capable of rendering more than one triangle per clock while processing from a single API input stream typically do not maintain primitive ordering at full speed."

**需求（原文）**："a system and method for exceeding a triangle per clock while maintaining API primitive ordering."

## 3. 核心方案

### 3.1 整体架构（FIG. 1–4）

**PPU 202（FIG. 2）**：I/O unit 205 → host interface 206（读 pushbuffer）→ front end 212 → **primitive distribution unit 200**（图元分发单元；注意与 US9594599B1 中同一附图标记 200 在该专利里指 work distribution unit——同一代号在不同代际图纸中的角色演变值得留意）→ processing cluster array 230（C 个 GPC 208）；crossbar unit 210 路由 GPC 输出到 partition unit 215/DRAM 220。

**GPC 208（FIG. 3A）**：pipeline manager 305、M 个 TPC 310（thread processing cluster，含 L1 cache 335、texture unit 315）、setup 321、rasterizer 322、preROP 324、network interface 328（地址映射）、**work distribution crossbar interface 330 + work distribution crossbar fabric 334**（合称 work distribution crossbar；文中亦直接称 330 为 "work distribution unit 330"）。

**work distribution crossbar interface 330 内部（FIG. 3C，保序核心）**：每个 TPC 310 对应一个 **WWDX 340**（world-space work distribution crossbar）；**aggregation unit 345**（可选）；**primitive order unit 342**（承载 GPC 顺序信息）；**screen-space unit 336** 内含 **GPC reorder buffer 344** 与 **SWDX 346**（screen-space work distribution crossbar）。

**图形管线（FIG. 4）**：primitive distributor 420（=primitive distribution unit 200）→ geometry processing unit 425 → viewport scale, cull, and clip unit 450 → rasterizer 455 → fragment processing unit 460 → raster operations unit 465。

### 3.2 关键机制详解

**① 两级并行分发框架**
- *object-space 分发*：primitive distribution unit 200 读 index buffer，把索引隐式定义的图元分组为 **batch**（"Batches may include 32 vertex pointers"；实施例 J=32 顶点、K=30 图元，占 1–4 个 32B data packets）；"the primitive distributer 420 works entirely with primitive indices — it does not touch the vertex data itself." batch 以 round-robin 或按当前负载分配给各 TPC 310 并行做 world-to-screen 变换、clipping、culling、vertex/tessellation/geometry shading，输出 **primitive descriptor**（type、flags、vertex indices、bounding box、attribute buffer address、**end of batch flag**）。
- *screen-space 分发*：render target 细分为 **screen tiles**（实施例 16×16 像素），tiles 划分为互不重叠的集合，**每个 GPC 静态负责一个 tile set**；tile 按 skewed interleaved 模式分给 4 个 rasterizer（行模式 0123/1230/2301/3012…），使足够大的 bounding box 必然覆盖所有 rasterizer，简化掩码计算。

**② 发送侧：WWDX 340 + aggregation unit 345**
- 各 TPC 处理速率不同，batch 完成顺序与 API 序不符；WWDX 340 把每个图元的 bounding box 与各 GPC 的 tile set 求交，置位 **GPC (distribution) mask**；
- **aggregation unit 345** 合并多个 WWDX 流并重排："accepting primitive descriptors from the TPC 310 corresponding to a current TPC identifier... until an end of batch flag is detected"（end of batch flag 是 batch 最后一个 descriptor 中的单个 bit），检测到后切换到顺序中的下一个 TPC 标识符；TPC 顺序由 pipeline manager 305 提供；aggregation unit 可省略（此时 fabric 流中另含 GPC mask）。

**③ fabric 传输与流控**：work distribution crossbar fabric 334 按 GPC mask 把图元送一个或多个 GPC；一实施例单时钟周期广播至 mask 内所有 GPC，另一实施例每时钟只发一个 GPC。采用 **credit/debit 流控**："A receiving GPC 208 outputs credits indicating the amount of primitive data that can be accepted"；同一时钟多个图元路由到同一 GPC 时做仲裁。fabric 中每图元携带：attribute buffer address、primitive descriptor、GPC identifier（做 object-space 处理的 GPC）、TPC identifier、end of batch flag。

**④ 接收侧：GPC reorder buffer 344 + SWDX 346**
- GPC reorder buffer 实现为 **multithreaded FIFO，每个 object-space GPC 一个 thread**；
- **SWDX 346** 按 primitive order unit 342 提供的 GPC 顺序序列从多线程 FIFO 中**按 API 序**取出 descriptor/属性地址/end-of-batch flag，压入 output FIFO，setup 321 从中弹出："Thus, the SWDX 346 pulls primitive descriptors... in the API primitive order."
- **部分流语义**：每个 GPC 只处理部分图元，"A reordered stream is considered to match the API primitive ordering when the primitive descriptors that are present in the reordered stream are in the same order that the same primitive descriptors appear in the API primitive ordering."

**⑤ 光栅化与属性回收**
- setup 321 计算 edge/depth plane equations、bounding box，执行 back-face 与 zero-area culling；rasterizer 322 含 coarse stage（找可能有 coverage 的大 tile）与 fine stage（逐 sample 测试），两级之间可插 hierarchical Z unit；利用 GPC↔tile 映射 "skip overtiles assigned for processing by other GPCs 208 in zero time"；每个 rasterizer 最高 1 triangle/clock 且互不同步；总吞吐 "up to C triangles per clock, where C is the number of GPCs 208"。
- 顶点属性存 **L2 cache 350** 的虚寻址 circular buffer（条目称 CBE，可标 no-evict）；**WWDX interface 330 负责释放 CBE**：对每个 CBE 记录使用它的 screen-space 管线计数，计数归零即释放。
- crossbar unit 210 无需全局保序，只需保证 "all data from a particular GPC 208 to a particular ROP 360 is conveyed in order"。

**⑥ 方法流程（FIG. 5，steps 500–550）**：500 按 API 序接收图元 → 505 生成 batch → 510 分发 batch 做并行几何处理 → 515 TPC 并行 object-space 处理 → 520 属性经 network interface 328 写入 L2、计算 bounding box → 525 计算 GPC mask → 530 经 fabric 334 路由（可经 aggregation unit 重排）→ 535 SWDX 346 重排回 API 序 → 540 setup/TPC 按 attribute buffer address 读属性 → 545 并行 screen-space 处理（setup、rasterizer 零时间跳过他 GPC tile、fragment shader 按需插值）→ 550 输出光栅化像素。

**⑦ tessellation 变体**：先分发 batch 做 tessellation，API 序恢复方式有二：用同一批 TPC 继续 object-space 处理；或 tessellation 后将 batch 重排回 API 序再分发。

## 4. 权利要求摘要

共 20 项，独立权利要求 1（方法）、11（非暂态计算机可读存储介质）、14（系统），均为同一六步方案：(a) 以第一顺序（API 序）接收图元；(b) 分发给一个或多个处理实体并行处理，产生多个含 processed primitive descriptors 的流；(c) 路由该多流，产生表示与屏幕**第一部分**相交图元的第一流与**第二部分**相交的第二流；(d)(e) 分别将两流中的 descriptor 重排以匹配第一顺序；(f) 并行光栅化两部分图元。

从属权利要求按主题分组：
- **batch 分组与分发**（2/3/12/16/17）：分组 batch、round-robin 分发、batch 编码顺序图元且路由只传顶点索引不传顶点数据（4/18）；
- **bounding box**（5/19）：路由前计算屏幕空间 bounding box；
- **多流合并重排**（6/13/20）：两流以上合并并重排为第一顺序；
- **路由/广播**（7/10）：第一/二流分别路由到负责对应屏幕部分的处理单元；同时相交两部分的图元向两个单元**广播** descriptor；
- **顶点属性存取**（8/9）：并行处理产生的属性存入存储器、光栅化时读回；
- **系统指令配置**（15）。

## 5. 与 WDU / Work Distribution Crossbar 的关系

1. **GPC 内 Work Distribution Crossbar 330 的权威定义文献**：本专利给出了 330 的完整内部结构——interface（WWDX 340 ×每 TPC、aggregation unit 345、primitive order unit 342）+ fabric 334 + 接收侧 screen-space unit 336（GPC reorder buffer 344、SWDX 346），并直接称之为 "work distribution unit 330"；"The combination of the work distribution crossbar interface 330 and work distribution crossbar fabric 334 implements a **distributed sorting structure** that routes primitive data between the GPCs 208."
2. **与 US9594599B1 的对照**：两件专利共享同一套图纸骨架（computer system 100 / PPU 202 / GPC 208），但分发对象不同——US9594599B1 的 unit 200 分发 work batch（计算/通用工作），本专利的 unit 200 是 primitive distribution unit（图元批）；且本专利的 GPC 内单元从 SPM 310 更名为 TPC 310，反映 Fermi→Kepler 过渡期的图纸复用与术语演化。
3. **"无单点汇聚"设计原则**："there is no single point after primitives pass through the primitive distribution unit 200 through which all primitives flow."——保序不靠中央排序器，而靠发送侧（end-of-batch + aggregation）、fabric（credit 流控）、接收侧（多线程 FIFO + SWDX 按序拉取）的分布式协作；这一原则也是理解 US10067768B2（convergence barrier 走 WDX 330）与 US11182207B2（L1→L2 flush 经 WDX 330）的基础。
4. **pipeline manager 305 是顺序信息的来源**：它记录 batch 到达的 TPC 顺序与 GPC 顺序，分别喂给发送侧 aggregation unit 345 与接收侧 primitive order unit 342/SWDX 346——GPC 内"分发"与"排序"的控制中枢在 pipeline manager，而非 crossbar 本身。

## 7. 评价与启示

**技术重要性**：
- 以"空间切分（tile set 静态归属 GPC）+ 时间重排（分布式 sorting structure）"解开了"多三角形/时钟"与"API 保序"的死结，吞吐上限 C triangles/clock 随 GPC 数线性扩展；
- end-of-batch 单 bit 标志 + 多线程 FIFO + credit 流控，全部是廉价硬件原语，却组合出全局保序语义；部分流（subsequence）保序定义是分布式光栅化正确性的关键抽象；
- CBE 引用计数释放（WWDX interface 负责）把属性缓冲生命周期管理与分发路径绑定，避免属性提前逐出或泄漏。

**局限性（基于文本可推断）**：
- tile set 静态归属 GPC，屏幕负载不均（如一半屏幕密集渲染）时无动态再平衡；
- 大图元 bounding box 覆盖所有 GPC 时产生广播放大，fabric 需以 C triangles/clock 聚合速率供给；
- 提取文本图内 OCR 严重乱码（FIG. 3C 部件名以正文编号为准）；原文另有 "same TPCs 208"（应为 310）、"setup 322"（应为 321）、claim 19 "configured to computing" 等笔误。

**对本专题的价值**：本专利（母案 2009 年提交）与 US9594599B1 同年启动，分别奠定"GPC 间计算工作分发"与"GPC 内图元分发 + 保序"两条线；其 WWDX/SWDX 命名与 330/334 结构编号被后续 Volta/Hopper 图纸沿用，是"work distribution crossbar"这一术语最完整的一手定义，可作为阅读 US10067768B2、US11182207B2 等引用 WDX 330 的专利时的结构参照。
