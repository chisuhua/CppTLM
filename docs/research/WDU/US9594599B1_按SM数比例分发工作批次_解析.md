## 2. 发明背景与待解决问题

**现有技术场景（FIG. 1）**：work distribution unit 14 向处理能力不同的 processing units 12-1…12-n 循环分发 work batches 16；"a 'work batch' includes a set of processing tasks to be performed by a particular processing unit 12"。

文本批评的三种现有分发方案：

1. **纯轮询（round-robin）**：WDU 按序循环分发，遇到尚未完成上一批次的处理单元即 stall。当各处理单元算力不等（如 12-1 只含 1 个 processor 而 12-2/12-n 含多个）时，WDU 会反复在弱单元处停顿，"reducing the processing throughput"；批次复杂度差异大时吞吐 "may be reduced dramatically"。
2. **load signal 方案**：每个单元完成后向 WDU 断言 load signal 20，未断言者被跳过。但 WDU 必须等待 load signal 传输完成，"These latencies correspond to idle cycles on the processors 18"。
3. **per-unit work FIFO 22 方案**：每单元内置 FIFO 缓存多批次，有空位即补充。虽减少空闲周期，但 "it allows work to complete massively out of order and it may leave one processor with a large queue of long work when the computer system 10 is waiting for idle"。

**需求陈述（原文）**："what is needed in the art is a more effective technique for distributing work batches to processing units that have different processing capabilities."

对应到 GPU 现实：GPC 内 SM 可能因制造缺陷或厂商刻意屏蔽（做低配版本）而部分禁用，各 GPC 使能 SM 数天然不等，均匀分发必然让弱 GPC 成为瓶颈。

## 3. 核心方案

### 3.1 整体架构（FIG. 2A–4）

**计算机系统 100（FIG. 2A）**：CPU 102、system memory 104、memory bridge 105（Northbridge）、I/O bridge 107（Southbridge）、display 110，parallel processing subsystem 112 经 communication path 113（PCI Express/AGP/HyperTransport）接入；device driver 103。

**PPU 202（FIG. 2B）**：I/O unit 205、host interface 206（读 pushbuffer）、front end 212（确保 GPC 处于 valid state 后才开始执行）、**work distribution unit 200**、processing cluster array 230（含 C 个 GPC 208）、crossbar unit 210、memory interface 214（D 个 partition unit 215，各接 DRAM 220）。数据流：CPU 102 写命令流至 pushbuffer → host interface 206 → front end 212 → **WDU 200 → GPCs 208**；"GPCs 208 receive processing tasks to be executed via a work distribution unit 200, which receives commands defining processing tasks from front end unit 212."

注意两级 crossbar 在本专利中的分工：**crossbar unit 210** 是 PPU 级数据路由互连（"route the output of each GPC 208 to the input of any partition unit 215 or to another GPC 208"，可用 virtual channels 分流），与任务分发无涉；**work distribution crossbar 330** 位于 GPC 内部（FIG. 3A），由 pipeline manager 305 控制，指定 SPM 310 输出数据的目的地。

**GPC 208（FIG. 3A）**：pipeline manager 305（"distributes processing tasks to streaming multiprocessors (SPMs) 310" 并配置 work distribution crossbar 330）、M 个 SPM 310、texture unit 315、preROP 325、MMU 328、L1.5 cache 335、work distribution crossbar 330。执行模型：warp/thread group（每 SPM 并发 G 个）、CTA（cooperative thread array，大小 m×k）。

### 3.2 关键机制详解：按使能 SM 数比例分发（FIG. 5–9）

**系统结构（FIG. 5，system 500）**：WDU 200 耦合 GPCs 208-0/1/2；WDU 内**每 GPC 一个 counter 514**（514-0↔208-0 等）；每个 GPC 含 **work FIFO 512**（存放收到的 work batches 506）与若干 SM 510（示例配置 SM count 分别为 2、1、1，另可有未示出的 disabled SMs）。**load signal 516**：当 GPC 的 work FIFO 中批次数低于预定量时向 WDU 发出，WDU 据此补发；备选实现为 GPC 发 "credit" 或 "done" 信号。

**总方法（FIG. 6，method 600）**：
- step 602：WDU 确定每个 GPC 的使能 SM 数（SM count）；
- step 604：确定所有 GPC 中的最大 SM count（max SM count）；
- step 606：基于各 GPC 的 SM count、max SM count 与 load signals 分发批次（三种策略之一）。

**调度框架**：WDU 执行 "scheduling round"（决定本轮哪些 GPC 应收到批次）+ 若干 "distribution round"（实际分发）；调度依据 = 当前 policy + counter 514 值。WDU 可**动态选择**策略："WDU 200 dynamically determines a specific policy based on the work batches 506 to be processed."

**策略一（FIG. 7，method 700，改进轮询）**：
- 702：对每个 GPC，把其 SM count 加到对应 counter 514；
- 704：该 GPC 的 counter ≥ max SM count？
- 706：该 GPC 是否在上一 distribution round 收到过批次（避免连续两轮发给同一 GPC）？
- 708：是否已收到该 GPC 的 load signal 516？
- 710：三条件全满足 → 分发一个 work batch；
- 712：该 GPC 的 counter 减去 max SM count；
- 714：仍有满足条件的 GPC 则继续分发轮，否则回到 702 重新累加。
- **掩码并行实施例**：WDU 维护 "greater than" mask、"not previous" mask、"load" mask 三个掩码并做按位 AND，AND 结果全零则回到 702；该方式允许对各 GPC 并行执行 704–712。

**策略二（FIG. 8，method 800，批次耗时显著变化、可容忍 stall）**：
- 802：每 counter 加 SM count；
- 804：任一 counter 超过 max ctr？
- 806/808：超限 counter 对应的 GPC 若未发 load signal，WDU **stall 对所有 GPC 的分发**，直到其发出 load signal；
- 810：识别 i) counter 值最高、ii) 已发 load signal、iii) counter ≥ SM total（全部 SM 总数）的 GPC；
- 812：向其分发批次；814：counter 减去 SM total。
- 效果：识别出"拿到了不成比例耗时批次"的 GPC，stall 等其 catch up。

**策略三（FIG. 9，method 900，批次耗时变化但不可 stall）**：
- 902：仅对 counter < ctr_cap（counter cap）的 GPC 累加 SM count；达上限者停止递增直至发出 load signal；
- 904：识别 counter 值最高、已发 load signal、且 counter ≥ SM total 的 GPC 并分发（图中分发动作标为 step 906）；
- 908：counter 减去 SM total。
- 特点：不停顿地适应批次耗时波动。

**效果总结（原文）**："each GPC receives an amount of work from the WDU that is proportional to the processing power afforded by the GPC"；"the WDU may abstain from distributing work batches to some or all of the GPCs in order to balance the workload."

## 4. 权利要求摘要

共 12 项，3 项独立（claim 1 方法、claim 4 非暂态计算机可读存储介质、claim 10 计算机系统）。

**独立权利要求 1（方法）**：向两个以上 GPC 分发处理任务批次：(a) 基于每个 GPC 内**使能的 SM 数量**递增各 GPC 的 counter value（每 GPC 对应一个不同的 counter）；(b) 基于第一 GPC 的 counter value **大于等于任一 GPC 中使能 SM 的最大数量**且**收到来自第一 GPC 的 load signal**，向其分发一批处理任务；(c) 从第一 GPC 的 counter value 中减去该最大使能 SM 数。

claim 4 与 claim 10 分别为同方案的 CRM 版本与系统版本（系统版明确 WDU 与 GPC 阵列的硬件结构）。

从属权利要求按主题分组：
- **隔轮分发限制**（claim 2/5/11）：当前轮向第一 GPC 分发后，紧邻的下一轮即使满足条件也不向其分发；
- **序列重排**（claim 3/6/12）：GPC 排成序列，后续分发轮中重排该序列；
- **上一轮未收批次条件**（claim 7）：分发还基于第一 GPC 在上一分发轮未收到何批次；
- **掩码**（claim 8/9）：生成指定 counter ≥ 最大使能 SM 数的 GPC 的第一掩码、指定上一轮未收批次的 GPC 的第二掩码，基于掩码执行分发。

## 5. 与 WDU / Work Distribution Crossbar 的关系

本专利是 **WDU 专题中年代最早、以 work distribution unit 为唯一发明对象**的专利（2009 年申请，Fermi 时代架构）：

1. **WDU 200 的命名与定位在此确立**：位于 front end 212 与 GPC 阵列之间，"may be configured to produce tasks at a frequency capable of providing tasks to multiple GPCs 208 for processing"。这与 12_Task_Management_Unit 专题中 Kepler 时代 WDU 340（US20130198760A1/US8572573B2）及 US9594599B1 被后续专利引用时"按使能 SM 比例分发 CTA"的描述完全对应——本专利即该原则的原始出处。
2. **分发粒度的演进坐标**：本专利的分发单元是 "work batch"（批次）+ 每 GPC work FIFO 512 + load signal 516 + counter 514；全文**没有 task table 术语**（0 次出现）。WDU 340 的 task table 345（CTA 槽位、高优先级逐出）是此后 US20130198760A1/US9710306B2 时代的结构，可见 WDU 从"批次 + 计数器调度算法"向"任务表 + 槽位管理"的演进轨迹。
3. **crossbar 术语辨析**：本专利同时出现 crossbar unit 210（PPU 级内存互连）与 work distribution crossbar 330（GPC 级，pipeline manager 305 控制的数据输出路径）——两者都不是本专利的发明对象，但佐证了"两级 crossbar"命名在 Fermi 时代已经成形（与 US8941653B2 中 work distribution crossbar interface 330/fabric 334 的保序光栅化用途对照阅读尤有价值）。
4. **与 US20230236878A1（WSDU）的呼应**：WSDU 时代"任务分发到 GPC 与使能 SM 数成比例"的表述，其机制源头即本专利的 counter/load signal 框架。

## 7. 评价与启示

**技术重要性**：
- 以极简硬件（每 GPC 一个加法计数器 + load signal 线）实现"算力比例分发 + 负载均衡 + 抗批次耗时波动"三重目标，三种策略（改进轮询/失速均衡/封顶不失速）覆盖不同负载特征，且可动态切换；
- 掩码 AND 并行实现把逐 GPC 串行判断变为单周期位运算，符合 WDU 必须高频产出任务（"produce tasks at a frequency capable of providing tasks to multiple GPCs"）的吞吐约束；
- 明确的失效模式分析（轮询 stall、load signal 延迟、FIFO 乱序完成）构成了后续 WDU 专利的问题清单——US20130198760A1 的 task table 槽位与高优先级逐出可视为对 "work completes massively out of order" 问题的结构化回应。

**局限性（基于文本可推断）**：
- 分发粒度为 work batch 而非 CTA/任务描述符，文本未描述批次内部的细粒度资源（寄存器/共享内存）准入控制；
- load signal 只是二值"低于预定量"反馈，未携带剩余容量/完成进度信息；
- counter 策略依赖 SM count 静态已知（step 602 一次性确定），对运行期动态禁用 SM 的再平衡未展开；
- 提取文本中 FIG. 3A/FIG. 5 图内文字 OCR 严重损坏，附图标记细节（如 FIFO 子编号）以说明书正文为准；原文另有 "counter 514-1 corresponds to GPC 208-2"、"load signals 512"（与 work FIFO 512 混淆）等笔误。

**对本专题的价值**：本专利是理解 NVIDIA "WDU 按使能 SM 比例分发"这一贯穿性设计原则的原始文献；其 counter + load signal 框架与后来 task table 345、WSDU 的比例分发构成一条清晰的技术演进线，是 13_Work_Distribution_Unit 专题时间轴的起点（2009-10 申请）。
