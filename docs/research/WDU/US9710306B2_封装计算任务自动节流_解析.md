## 2. 发明背景与待解决问题

**领域**：并行处理器中的资源管理，具体为"封装计算任务"（encapsulated compute task）的自动节流。

**"封装"的准确含义**：计算任务被封装为 **TMD（task metadata）数据结构 322** 存于 PP memory 204——"a compute program running on the CPU 102 or PPU 202 can create a TMD 322 structure in memory and then submit the TMD 322 for execution by sending a task pointer associated with the TMD 322 to the task/work unit 207."（提取文本中没有出现 "CUDA" 字样，图形-计算互操作体现为：图形管线与计算任务共享同一 shader local memory buffer 540，且任务可被硬件乱序调度。）

**待解决问题**：GPU 上每个线程都需分配 thread local memory（shader local memory）；能并发执行数百数千线程的处理器若按最坏情况为每线程静态分配，物理内存需求极大："the amount of physical memory available to the processor limits the number of threads that can be executed concurrently"；且静态分配利用率低（有的线程用满、有的只用一点）。

**关键约束**：驱动对硬件调度不可见——"Device driver 103 may not be able to control the order of execution of tasks or even have access to determine which tasks are currently scheduled on active SMs 310. Therefore, different techniques are disclosed herein that enable automatic reconfiguration of PPU 202 based on discrete throttling modes specified within the TMD 322."——这正是"auto"（硬件自动）节流的动机。

## 3. 核心方案

### 3.1 整体架构（FIG. 1–4）

**计算机系统 100 / PPU 202（FIG. 1–2）**：Kepler 时代前端链——I/O unit 205 → host interface 206（读 pushbuffer）→ front end 212 → **task/work unit 207** → processing cluster array 230（C 个 GPC 208）；crossbar unit 210（PPU 级内存互连）连 memory interface 214（D 个 partition unit 215 / DRAM 220）。

**task/work unit 207（FIG. 3A）**：即 12_Task_Management_Unit 专题所述 TMU 谱系的第二代形态，含：
- **task management unit 300**：按优先级组织任务，每优先级在 scheduler table 321 中存一条指向 TMD 322 的链表；接收速率与调度速率解耦；支持 round-robin/priority/partitioned priority 调度；
- **work distribution unit 340**：含 **task table 345**，槽位被正在执行的 TMD 322 占用；有空槽才调度新任务；高优先级任务可逐出低优先级任务；子任务（child task）由 processing cluster array 230 动态生成、不经 pushbuffer、不通知 CPU。

**GPC 208（FIG. 3B）**：pipeline manager 305、M 个 SM 310、work distribution crossbar 330、L1.5 cache 335、MMU 328、texture unit 315、preROP 325。**SM 310（FIG. 3C）**：warp scheduler and instruction unit 312、local register file 304、exec units 302、LSU 303、unified address mapping unit 352、shared memory 306、L1 cache 320、instruction L1 cache 370、memory and cache interconnect 380。

**TMD 322 结构（FIG. 4A/4B）**：Initialization Parameters 405（每线程内存参数：local memory 区域大小、寄存器数、单 CTA shared memory 等）、Scheduling Parameters 410、Execution Parameters 415（含 **throttle enable flag** 与本专利的 **TMD.Throttled** 标志）、CTA State 420、Hardware-Only Field 422、Queue 425（数据指针 Outer Get 430 / Inner Get 435 / Inner Put 440 / Outer Put 445）。grid TMD 启动固定数量 CTA，queue TMD 启动可变数量 CTA。

**shader local memory（FIG. 5A/5B）**：driver 分配的虚拟地址空间 510（基址 0x70000000，共 **256 MB**），物理后备为 PP memory 204 中的 buffer 540；三分区——local memory high 521（数据栈，0–512 kB/线程，16 B 步进）、local memory low 522（变量存储，同规格）、call return stack 523（程序栈，0–1 MB，bytes/warp，512 B 步进）。

### 3.2 关键机制详解：离散节流模式 + TMD 标志位

**为什么不能按最坏情况分配**：SLM per warp = k×(HighSize+LowSize) + CrsSize（Eq. 1）；SLM per SM = G × SLM per warp（Eq. 2）。实施例数字 k=32 线程/warp、G=64 warp/SM，最坏情况下每 warp 约 33 MB、**每 SM 超 2 GB**——显然不可行。

**被放弃的动态方案（FIG. 6，method 600，执行主体 WDU 340）**：610 接收待调度的 TMD 任务指针 → 612 对 task table 345 中每个 TMD 按 Eq. 2 计算所需 SLM → 614 取最大需求 → 616 用 256 MB ÷ 最大需求 = 可激活 SM 数 N → 618 激活 N 个 SM 并均分地址空间。放弃原因：需专用硬件持续监控 task table、频繁令 SM idle，且除法在硬件上昂贵（"determining the number of active SMs 310 requires a divide operation, which is expensive in hardware"）。

**发明核心（FIG. 7，method 700）**：
- **谁设标志**：device driver 103 在 TMD 的 execution parameters 415 中设置 **TMD.Throttled**：把每 warp 所需 SLM 与阈值比较，低于阈值清标志（任务两种模式皆可运行），高于阈值置标志（任务**只能**在节流模式运行）；
- **谁检测**：**WDU 340**。TMD 指针进入 task table 345 后，"Work distribution unit 340 is configured to OR all of the flag bits for each TMD 322 in task table 345 to determine whether any currently scheduled tasks require PPU 202 to be configured in the throttled mode."
- **节流什么**：节流对象是**活跃 SM 数量**。非节流模式 16 个 SM 全活跃、每 SM 分 16 MB（256/16）；节流模式 4 个 SM 活跃、每 SM 64 MB。切换动作：令所有 SM idle（完成当前 warp、保存续跑状态）→ 停用部分 SM → 按更少活跃 SM 重分 SLM → 重新分发任务（反向恢复亦由 WDU 340 执行）；
- **流程**：710 接收 TMD 任务指针 → 712 配置为非节流模式 → 714 OR 所有标志位判定是否需节流；无 → 回 710；有 → 716 切换节流模式 → 718 再判；仍有 → 等待带标志任务执行完并被逐出 task table 345；无 → 720 task table 是否还有 pending 任务？有 → 回 712 恢复非节流；无 → 结束；
- **多级节流变体**：如 16/12/8/4 活跃 SM 四档，用 2 bit 多比特标志（00/01/10/11），WDU 取所有多比特标志的**最大值**（最大节流档 = 最少活跃 SM）配置 PPU；
- **免重分配技巧**：SLM 地址由 SM index × warp index 因子计算（因子存 special registers），driver 可为每档**预分配**，"when the mode of PPU 202 is changed, the shader local memory is already allocated and does not require any type of reallocation by the device driver."

**另一层 CTA 级节流（说明书描述、非权利要求对象）**："the task/work unit 207 may limit (i.e., throttle) the number of CTAs that execute concurrently so the CTAs do not attempt to consume more memory than is available for access by the TMD 322"，由 execution parameters 415 的 throttle enable flag 控制。

## 4. 权利要求摘要

共 22 项，独立权利要求 1（方法）、10（处理器）、21（系统）。

**独立权利要求 1（方法）**：接收一个或多个待调度任务；处理器含多个并行处理单元，可配置为非节流模式（第一数量单元活跃）或节流模式（第二数量活跃，第二 < 第一）；确定至少一个已调度任务携带 throttled flag（表示该任务只能在节流模式执行）；响应之配置处理器激活第二数量的并行处理单元。

**独立权利要求 10（处理器）**：多个并行处理单元 + 与之耦合的 **work distribution unit**；WDU 接收待调度任务、确定 throttled flag、响应配置处理器。claim 21 为系统版。

从属权利要求按主题分组：
- **GPU/WDU 载体**（2/11/22）：处理器为含 WDU 的 GPU；
- **检测实现**（3/12）：任务存入 task table，对表中每个任务的 throttled flag 执行 OR 运算；
- **标志形式**（4–6/13–15）：TMD 数据结构字段；单比特语义；多比特对应 ≥3 个离散节流状态；
- **虚拟地址范围**（7/16）：节流模下每个活跃单元关联更大的地址范围；（8/17）driver 分配 buffer + memory mapping unit 地址翻译；（9/18）所需 local memory 超过阈值时 driver 置位标志；
- **切换动作**（19/20）：先 idle 第一数量单元再停用一部分；停用后再分配内存资源。

## 5. 与 WDU / Work Distribution Crossbar 的关系

1. **WDU 340 是本发明的唯一执行主体**：method 600/700 全部步骤由 WDU 340 执行；节流检测（OR task table 345 标志位）、模式切换命令、重分发都落在 WDU——本专利把 WDU 的职责从"分发任务"扩展为"依据任务元数据重配置整颗 PPU 的活跃 SM 拓扑"。
2. **task table 345 的角色再次凸显**：与 US20130198760A1/US8572573B2 中 task table 作为 CTA 槽位池的用途叠加，这里它是节流判定的信息源（表中所有 TMD 的 throttled flag 集合）；被节流任务完成后的"逐出 task table"（evicted from the task table 345）是触发模式恢复的事件。
3. **与 TMU 谱系的关系**：task/work unit 207 = TMU 300 + WDU 340 的 Kepler 命名形态；本专利说明 TMU/WDU 分工——TMU 管优先级与就绪队列，WDU 管执行槽位与（本专利新增的）资源配置决策。
4. **两级 crossbar 依旧在场**：crossbar unit 210（PPU 级数据路由）与 work distribution crossbar 330（GPC 内，pipeline manager 305 控制）在架构描述出现，但非本专利发明对象。

## 7. 评价与启示

**技术重要性**：
- 用"驱动静态判断（阈值比较）+ 硬件动态执行（WDU OR 标志位）"的极简分工，回避了硬件除法与持续监控开销，是"把复杂决策推给软件编译/驱动期、硬件只做廉价聚合"的典型 NVIDIA 设计哲学；
- 离散模式 + 预分配消除了模式切换时的内存重分配，切换代价仅剩 SM drain/idle；
- 与 US9594599B1（WDU 按使能 SM 数分发）构成互文：那件专利假设使能 SM 数是静态给定的，本专利则让 WDU **动态改变**使能 SM 数本身——分发策略与资源拓扑共同成为 WDU 的控制变量。

**局限性（基于文本可推断）**：
- 模式切换粒度粗（整颗 PPU 级别），所有 SM 先 idle 再重配置，切换期间无任务执行；
- 节流标志是 per-TMD 静态值，任务运行中内存需求变化不能反映；
- 提取文本中发明人第二人姓名 OCR 损坏；原文另有 "may not have be able"（语法笔误）、FIG. 5B "L1 cache 32"（应为 320）等小误。

**对本专题的价值**：本专利是 WDU 职责边界扩展的关键节点（2012 申请，Kepler 时代）：WDU 不仅决定"任务去哪个 SM"，还决定"哪些 SM 醒着、每个 SM 拿多少内存"；其 task table 345 + TMD 标志位 + OR 聚合的实现细节，是理解 US10552202B2（抢占）与 US20230236878A1（WSDU）中 WDU 侧行为的基础。
