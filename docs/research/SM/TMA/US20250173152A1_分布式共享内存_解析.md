## 2. 发明背景与待解决问题

**SM 间共享内存隔离**：旧架构中每个 SM 的 on-chip read/write memory（register file/scratchpad/L1 中划出的 "shared memory"）仅对该 SM 内线程可见，LDS/STS/ATOMS 只能访问本 SM；跨 SM 交换数据必须经 global memory/L2 cache——说明书比喻为"邻居借书必须先把书还回图书馆"。此类访问既贵，又占用本应用于 off-chip 主存的 L2 带宽。

**cluster 通信需求**：DL/HPC 需要 strong scaling（问题规模不变、靠加核提速），但 FIG. 6/7 显示 math bandwidth 指数增长而 data/interconnect bandwidth 跟不上。

**软件方案不足**：Cooperative Groups API 纯软件、无硬件并发保证，跨 CTA 共享只能冗余取数，造成带宽瓶颈。

**需求陈述（原文意译）**：需要"a new hardware model that exploits low latency local memory to enable memory sharing and direct communications between groups of processing cores or SMs"，且不推翻现有 cache/互连层级。

## 3. 核心方案

### 3.1 CGA 与 DSMEM 地址空间

- DSMEM = 分布在多个 SM 上的本地共享内存块 + 使其互通的硬件：GPC_CGA（即 thread block cluster）内每个 CTA 把自己在 SM 本地 shared memory 中的段暴露为逻辑地址空间的连续分段，段间留洞。
- CGA 层级可嵌套：GPU_CGA / μGPU_CGA / GPC_CGA；DSMEM 作用域限定于 GPC_CGA 域——FIG. 17C（已核对）示出两个 GPC_CGA 互不可见对方的 DSMEM 与 CGA linear shared memory。
- 地址空间见 FIG. 18（已视觉核对）：generic address 中开出一个 4GB 的 DSMEM 窗口（SWin64），按 CTAID（CTA ID within CGA，0…256）切成每段 16MB 的槽，段内实际可用 SMemSz 由软件按 8/16/32KB 等配置。
- 地址格式：[0 | DSMEM/SMEM | CTA ID within CGA | SMEM Offset]，aperture 值由硬件寄存器读出；CTA ID=0 时退化为传统 LDS/STS 本地访问，保持向后兼容；新的通用 LD/ST/ATOM（及 TMA、SYNC）才跨 SM 访问 DSMEM。
- 并发保证由 CGA 硬件提供：CWD 420 投机式 launch 确认所有 CTA 有槽才发射（all-or-none）；GPM 分配 gpc_local_cga_id，并在 CGA 结束、DSMEM flush 完成后回收；S2R 寄存器向 shader 暴露 CGA_CTA_id 与 CGA slot。
- 窗口数按 CGA 实际 CTA 数动态分配（32 个 CTA 开 32 个窗口），可随 launch/complete 动态增删。

### 3.2 跨 SM 访问路径（GPCARB/GXBAR，FIG. 19/21A–21D）

**源 SM 侧两级查表**（FIG. 19，已核对）：warpId → SmCgaSlot 表 5002（64 entry）得 sm_cga_slot；再查 SM2SM Routing Table 5004（8 entry，cga_cta2sm_dir：gpc_local_cga_id + 每 CTA 的 tpc_id/sm_id_in_tpc）得目的 SM 物理 id；经 32:1 mux 5006 注入互连 5008。MPC 在每次 CTA launch 时向 GPC 内所有 SM 广播以同步更新这些表。

**目的 SM 侧**：ShMemBase CAM 5010（8 entry）以 {gpc_local_cga_id, cta_id_in_cga} 匹配出 shared_memory_base/size（DSMEM 可重定位，故用 CAM 而非固定偏移），做越界检查后执行 read/write/atomic；CAM 未命中或越界则向源 SM 发错误包。

**SM2SM 包族**：xx2shmem_rd_cmd / byte_wr_cmd / full_wr_cmd / red_cmd / concat_red_cmd / atom_cmd / concat_atom_cmd / wr_data / ack / rd_data；短写包字段含 wdat[4]、we_、mask、dst_sm、src_sm、gpc_local_cga_id（U008）、cta_id_in_cga（U005）、cgamem_offset（U011）、phase_id、barrier_addr。

**物理互连**（FIG. 21A/21B，已核对）：SM→TPCARB→GPCMMU uTLB（只做 address hash 以均摊 GXBAR 多路径、防 camping，不做虚实翻译）→GPCARB IG 处分叉——global/L2 流量走 MXBAR→L2（黑色路径），SM2SM 流量走 GPC 内部专用 GXBAR（点线路径）。GXBAR 由 k×k（示例 k=6，构成 12×12 全连接）的 GX0/GX1 开关组成以防协议死锁；出口经 GPCARB EG0–EG5 送达目的 SM。

**隔离与工程细节**：SM2SM 不占用 MXBAR 带宽，与 L2 流量物理隔离（一个 GPC 做低延迟 SM2SM 时另一个 GPC 可打满 L2）；FIG. 21A 标注位宽（SM2SM 4/12、L2 RESP 24、L2 REQ 6/18、3 tex2gnic、12 gnic2tex、6 mmu2gpcarb）；总线编码限 toggle rate、固件可关 GX0/GX1 降半带宽、按 SM 限带宽、支持 TPC/CPC floorsweep。

### 3.3 Multicast、屏障与 MEMBAR 优化

- 说明书载明的特性清单：DSMEM 支持 read/write/atomic、programmatic multicast 与 TMA、CGA_id 分配回收协议、CGA 创建/上下文切换期的硬件屏障、退出与错误处理协议。
- FIG. 20（已核对）两道"铁路道口"屏障：入口屏障保证所有 CTA 的 DSMEM 段分配完毕前任何 CTA 不得访问他人 DSMEM；出口屏障拦住先完成的 CTA 直至全体就绪，防止段被提前释放。ISA 新增 CGABAR.ARRIVE（不阻塞到达）/ CGABAR.WAIT（阻塞至屏障清除）。
- MEMBAR 优化：源 SM 用 outstanding transaction counter 跟踪未决请求（LD 等返回数据、ST 等 ack）；目的 SM 按源 SM 累计 ack、合并发送（coalesced write acks）；遇 MEMBAR 时 phase 0/1 翻转，只停旧相位请求而不停其他 CGA 流量，旧相位计数归零即屏障完成；该计数亦用于 CTA 退出时判定未决事务清空。
- 退出协议：Warp_exit → 通知 MPC 并等待退出许可 → inval_cta_entry 使 CAM 失效 → cta_complete 报 GPM/CWD → 全 CGA 完成后发 DSMEM flush → dsmem_flush_done → GPM 回收 gpc_local_cga_id → cga_complete 报 CWD。
- 错误处理：目标侧检测的错误（CGA/CTA not found、offset 越界）由目标 SM 报回源 SM，源 SM 归因到 CGA 而非 warp/PC（PC FIFO 可能已滑出）；源侧可检测错误（cta_id 超限、无效 SM_id、offset 超最大共享内存）则可直接归因 warp/PC。

## 4. 权利要求分析

共 24 项，2 项独立（claim 1 "graphics processing chip package"、claim 13 "graphics processing unit"），均为装置权利要求，措辞刻意泛化为 "processor / local (L1) cache memory / signaling path" 而非 SM/DSMEM/GPC。

**Claim 1**：L2 cache + 第一/第二 processor（各含处理核阵列、调度硬件、本地 L1 cache）+ 使第一 processor 能写第二 L1、反之亦然的 signaling path——即 DSMEM 的最小硬件骨架。**Claim 13** 扩展至第 n 个 processor（n>2）且三者互访对方本地 cache。

从属项两组镜像（1 系：2–12；13 系：14–24），按主题分组：

- **精度混合核**（2/14）与 **tensor core**（3/15）；**SM 限定**（4/16）；
- **写访问以同 CGA 为条件**（5/17）+ **硬件并发保证**（6/18）——把 CGA 并发发射写入保护范围；
- **read/write/atomic**（7/19）；**低延迟 processor 间网络**（8/20）；**coalesced write acks**（9/21）；**低于 global/L2 访问延迟**（10/22）；
- **memory barrier 硬件同步共享使用**（11/23）+ **屏障确保数据先可用后被引用**（12/24）。

权利要求收录了并发保证、coalesced ack、屏障语义等核心语义，但地址窗口/CAM 路由/GXBAR 拓扑等实现细节留在说明书与母案族中。

## 5. 与专题主题的关系

DSMEM 正是 Hopper thread block cluster（= 本案 CGA/GPC_CGA）的核心硬件：cluster 内 CTA 经 SM2SM 网络互访对方 shared memory，对应 PTX 的 DSMEM/mapa 类能力；Blackwell 沿用该互连并服务 tcgen05/CGA 场景（cluster 内跨 SM 供数、UMMA 的 producer-consumer 流水）。

与同日族应用的配合（说明书明示）：TMA multicast（17/691,276/288，"DSMEM supports programmatic multicast and the TMA unit"）、mbarrier/arrive-wait 硬件屏障（17/691,296，CGABAR.ARRIVE/WAIT 即其 ISA 体现）、快速同步（17/691,303）、cluster 负载均衡（17/691,872）。

说明书两个动机例子直接对应 Hopper/Blackwell GEMM kernel 用法：Split-K reduction 由"在 L2 做"变为"一个 SM 直写另一个 SM 的 shared memory"；GEMM 内循环每 64–256 周期需全 CGA 同步，低延迟 SM2SM 网络使同步不再成为计算限制器。对 17_Blackwell_SM_Internals 专题而言，本案是 SM 间互连（GPCARB/GXBAR 拓扑、tex2gnic/gnic2tex 位宽、uTLB hash、MPC/GPM 职责）最详细的公开实现资料。

注：说明书现有技术仅举至 Volta GV100/Ampere，未直接点名 Hopper/Blackwell；CGA↔Hopper thread block cluster、DSMEM↔cluster shared memory 的对应系本专题基于公开架构资料的推断，非本案原文。

## 7. 评价与启示

**技术重要性**：

- 本案把"跨 SM 共享内存"这一 Hopper 标志性特性完整硬件化；其安全前提不是缓存一致性协议，而是 CGA 的 all-or-none 并发发射保证，使本地内存可无一致性开销地对外暴露。
- 4GB/256×16MB 窗口 + CTAID 分段地址既扩容又向后兼容（CTAID=0 即传统 SMEM）；源侧路由表 + 目的侧 CAM 把"逻辑 CTA→物理 SM→段 base/size"两级解耦。
- GXBAR 与 MXBAR 物理隔离使 SM2SM 低延迟流量不与 L2 争带宽；phase 翻转 MEMBAR + coalesced ack 把同步开销压到硬件计数级。

**局限性（基于文本可推断）**：

- DSMEM 域限于 GPC（cluster 规模受 GPC 内 SM 数约束，跨 GPC 不可用）；
- DSMEM atomic 的硬件运算支持可能弱于 global memory（说明书承认原子指令集可能 more/less/different）；
- 目标侧检测的错误只能归因到 CGA 而非 warp/PC；每 SM 仅 8 entry 路由/CAM，限制同时活跃 CGA 数。

**对专题的价值**：与母案 US12248788B2 同说明书，是解读 Blackwell SM 内部（SM2SM 网络位宽、GPCARB/GXBAR 拓扑、MPC/GPM 职责、S2R 寄存器、CGA 退出/flush 协议）的基准文献；建议本案 FIG. 16A–21D 配合同日族 17/691,288（multicast）与 17/691,296（屏障）互参。
