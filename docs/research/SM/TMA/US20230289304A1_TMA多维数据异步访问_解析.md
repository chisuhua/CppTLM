## 2. 发明背景与待解决问题

**场景**：GEMM（C=αAB+βC）是神经网络与科学计算的基本构件，现代 GPU 将矩阵切 tile 并行计算；tensor core 大幅提升算力，但 "memory access speeds have not kept pace"。

**现状批评**：传统 global→shared 路径要经 cache line→寄存器→SMEM 多级搬运，大块传输时寄存器可被占用数千周期，"tied up and unavailable for any other purpose"。

**LDGSTS 的不足**：US11080051 的 LDGSTS 绕过 L1/RF 直写 SMEM，但每个子块的地址计算与同步仍由 SM 线程自担，大量小请求 + 逐块同步带来显著处理与功耗开销。

**量化痛点**：多维地址计算消耗 RF 带宽/容量、OOB 处理、bank conflict、指令调度困难；多种 DL 网络实测平均性能损失超 10%；"up to 90% of developer time is spent on writing and testing data access code"。

**需求**：SM 近耦合的专用硬件（TMAU）接管地址计算、大块搬运与完成同步——说明书以"主厨只负责煎肉、commis 负责取料切配"类比；单线程即可为整个 CTA 发一条请求，其余线程异步继续计算。

## 3. 核心方案

### 3.1 整体架构（FIG. 1、2、10–12；Sheet 1/2 已视觉核对）

**GPU 100（FIG. 1）**：SM 102a–n，各含 functional units 104（含 tensor core）、register file 106、L1 108、shared memory 110（可与 L1 统一、可加入 DSMEM）；每 SM 一对一紧耦合 TMAU 112a–n，经 global memory interface 114 访问 global memory 116（L2/DRAM）。备选实施例为单个 TMAU + 硬件 arbiter 服务多 SM。

**拷贝引擎流程（FIG. 2）**：204 SM 发单条请求（tensor：描述符指针 + 坐标 + SMEM 地址；非 tensor：源/目的地址 + 字节数）→ 206 TMAU 拆成多条不超 L2 cache line 的子请求发往 L2 202 → 208 响应 → 210/212 写入 SMEM 110 → 214 与 SM 同步。拷贝方向含 g2s、s2g、g2g、s2s（含经 DSMEM 跨 SM）。

**附图核对**：Sheet 1/2 视觉核对确认 FIG. 1 标记 102(SM)/104(功能单元)/106(RF)/108(cache)/110(SMEM)/112(TMAU)/114(全局内存接口)/116(全局内存) 与 FIG. 2 标记 102/112/110(SMEM)/202(L2) 及操作编号 204–214 均与说明书一致。

**落点（FIG. 12）**：SM 1140 的 LSU 1254 可包含 TMAU 112，亦可独立于 LSU。

### 3.2 tensor map 描述符结构（FIG. 3–5；Sheet 2–5 已核对）

**三层参数（FIG. 5A/5B）**：① tensor descriptor 参数（tensor H、W、W stride、element size；stride = 尺寸 + padding）与 ② access descriptor 参数（block H、block W、out-of-boundary value）存于全局内存中的描述符数据结构；③ 指令级参数仅块起点坐标 (x,y)（n 维为 n 元组）。FIG. 3A 另给出 traversalStride（遍历步长）与 boxSize 的关系。

**描述符缓存**：描述符可 host 侧或 GPU 侧建立；TMAU 设专用 descriptor cache 608，以描述符全局地址为 tag；处理当前请求时并行检查下一请求描述符驻留性，miss 则经 GCC 622 预取，隐藏全局内存延迟。

**OOB 处理（FIG. 4A/4B）**：块可越界；越界元素填零或填格式相关的特殊 NaN 常量（服务 normalization+conv 融合等场景，引姊妹案 17/497,507）。

### 3.3 地址翻译与 tile/im2col 模式（FIG. 6–9；Sheet 6 已核对）

**流水线（FIG. 6）**：MIOC 604 → request queue 606（FIFO）→ descriptor cache 608 → setup 610（参数补齐/校验，Table 1 伪代码）→ request generator 616（主引擎：多维坐标迭代、坐标→地址映射、OOB 检查、SMEM/global 地址计算、按 L2 cache line 上限拆请求）→ completion tracking 618；对外经 GNIC 614/620。注：说明书两处误写 "request generator 716"，图中为 616。

**遍历算法（FIG. 7A/7B）**：5 层嵌套循环对应 5 个维度；最内层按 traversalStride 递增、越 boxSize 即退出，外层以 tensorStride 推进 base 地址；anchor/base/current element 三地址模型。FIG. 7C 给出 implicit-GEMM 卷积的 tensorBlockLoad/computeGEMM/tensorBlockStore 用法。

**tile 模式**：boundingBox = boxSize[]，通用、无数据复制，但有 tile-quantization 损失（FIG. 8E：任一时刻仅 36/64 像素参与计算）。

**im2col 模式（FIG. 8A–8K）**：boundingBox 维数比张量少 1；改用 rangeNDHW、rangeC、boxBaseCornerDHW、boxFarCornerDHW（带符号偏移、可在界外，公式 boundingBox{D,H,W}=tensorSize−boxBaseCorner+boxFarCorner）；指令另带 coordinate offsets（全部打包进 16 位寄存器；3×3 filter 的 filter base 可被 9 条请求复用）；支持 traversalStride 与 dilation（FIG. 8I/8J：dilation 只影响 box 位置不影响大小）；可避免量化损失。interleaved 布局（16B/32B slice）下 C 坐标以 slice 为单位。

**swizzle（FIG. 9A–9D）**：swizzle_128B 模式；L2 cache line 的 4 个 32B sector 映射到 SMEM 的 4 个 bank group（每组 8 bank），16B 半 sector 可交换；bank 分配用 8×8 表编码、按目的 SMEM 地址低 3 位选行；目标是读写均无 bank conflict，并按 GMMA 的 8×8 tile 视图供数（FIG. 9D 右侧）。

### 3.4 异步拷贝与 mbarrier 事务计数配合（FIG. 2 之 212/214）

- **TMAU 内部计数**：专用计数器对已发 L2 请求加、对返回减，归零即整块完成；可对一组背靠背事务共用一个计数器、只对组内最后事务报完成。
- **SMEM 侧 arrive/wait barrier**：每条 load 请求携带 SMEM 中 barrier 结构地址并随每个 L2 请求下发；数据到达目的 SM 时由内存系统直接按接收字节数更新 barrier，"The TMAU itself is not involved in the barrier update"——即 mbarrier 带事务计数 arrive 的硬件原型（对应姊妹案 17/691,296 "Hardware Accelerated Synchronization With Asynchronous Transaction Support"）；SM 以同步电路监控计数器，另有专用指令检测此前全部 TMAU 请求完成。
- **multicast（姊妹案 17/691,288）**：单条 load 写多个 SM 的 SMEM，目的 CTA 用 16-bit mask 编码（可藏于目的地址）；各接收 CTA 自更新 arrive/wait；为支持抢占，请求方 TMAU 经跨 TMAU ack 机制统计所有接收方完成。
- **效果**：204 发请求到 214 同步之间可隔数千周期，SM 全程异步计算；single thread 一条指令即可为全 CTA 取数。

### 3.5 其余请求类型与编程模型

- **prefetch**：DRAM→L2，无需完成跟踪；tensor prefetch 不做 SMEM/global 对齐、按 sector/cache line 粒度处理（指令形 `prefetch_tensor.mode.dimensionality`）。
- **store/reduction**：SMEM→global，源为线性 SMEM、目的按张量处理；支持 tile/im2col、interleaved、swizzle、traversal stride 与 OOB ZFILL/CFILL；reduction 含 AND/ADD/XOR/MIN/MAX/DEC/OR/INC（shared→global 或 shared→shared）。
- **descriptor-less 请求**：数据视为预定大小（默认 16B）块的连续数组，指令级参数仅源/目的地址 + 块数，块数为零即 NOP；支持 g2s/s2g/s2s（另有实施例 g2g）、reduction 与 prefetch——免描述符简化编程模型。
- **编程模型**：TMA 指令的标量性使其适合 Uniform Data Path/Uniform Register File 执行；PTX 层以 `_warpsync.exclusive.one mask, L1` 修饰符、CUDA 层以 `__one_sync(mask)` 一致地选出单线程发请求（warp elect-one 语义）；并提供 tiled/im2col × 有/无描述符四组 C 风格函数与 `copy_tensor...{.multicast}{reduction_op}`、`copy_block...` 等指令形。

## 4. 权利要求分析

**独立权利要求 1（并行处理器）**：三要素——① memory interface + 多个处理器 + 每处理器耦合的 memory access hardware circuit；② 接收指定多维数据结构**坐标**的访问请求；③ 将坐标翻译为多个内存地址并**异步**传输该数据结构的至少一部分。claim 26 为同方案方法版；claim 27 直接请求该硬件电路本身（外部内存接口、MIOC、指向本/他处理器 SMEM 的接口、处理流水线），是最接近"TMAU 作为独立部件"的权利要求。

**重要从权分组**：
- 传输方向：2（外存→外存）、3/4（外存↔SMEM）、10（三方向直写）、21（load/store）；
- 描述符机制：5（坐标定位块）、6（描述符提供基址）、7（setup 电路预取描述符入 descriptor cache）；
- OOB：8（检测越界）、9（写 SMEM 时以预定值编码越界位置）；
- 异步/拆分：11（单条消息触发、与块大小无关）、19（逐子块更新 SMEM 计数器 + SM 同步电路监控预定值）；
- 模式与布局：12（tensor vs non-tensor）、16（tile）、17（im2col）、13/14/15（swizzle 写入、预定 pattern、pattern 信息随响应带回）；
- 硬件构成：18（request queue + descriptor cache + setup + request generation + completion tracking 五件套）；
- 扩展：20（写多处理器 SMEM=multicast）、22（reduction）、23（multicast）、24（异构精度核共享指令缓存）、25（arbiter）。

## 5. 与专题主题的关系（TMA 在 Hopper/Blackwell SM 数据通路中的位置）

- **硬件实体**：TMAU 即 PTX `cp.async.bulk.tensor` 的硬件基础，位于 SM/LSU 与 SMEM、L2 之间，接管 global→SMEM 的"最后一英里"；FIG. 12 将其画入 LSU 1254 正符合 Hopper SM 中 TMA 挂在 LS 通路的布局。
- **描述符 ↔ CUtensorMap**：driver API `cuTensorMapEncodeTiled/Im2col` 的字段（rank、globalDim、globalStrides、boxDim、elementStrides、interleave、swizzle、oobFill）与本案 tensorSize/stride/boxSize/element size/interleaved/swizzle/out-of-boundary value 一一对应；指令坐标即 cp.async.bulk.tensor 的 coordinate 操作数；说明书的 `copy_tensor.mode.dimensionality...{.multicast}{reduction_op}` 指令形与 PTX 形态同构。
- **同步三件套**：SMEM barrier 地址 + 字节计数累加 = mbarrier 事务计数语义，与姊妹案 17/691,296/303 构成 Hopper 异步拷贝同步闭环；multicast + DSMEM（17/691,690）使 A/B tile 可跨 CTA/SM 共享，压低 L2 带宽。
- **对 Tensor Core/wgmma 供数**：TMA 把 tile（含 swizzle 排布）载入 SMEM，GMMA/wgmma（姊妹案 17/691,406）按 8×8 tile 读取计算——FIG. 9D 直接以 GMMA 视图收尾，证明 TMA 的 swizzle 设计以 tensor core 供数为目标；单线程发请求（`.one`/`__one_sync`，warp elect-one 语义）走 UDP/URF，节省 RF 带宽与功耗。
- **专题坐标**：本案是 2022-03-10 Hopper 申请集群（CGA/DSMEM/multicast/mbarrier/wgmma 等）中定义 SM 内部数据供给通路的核心专利，也是 Blackwell 沿用并扩展 TMA 的原始文献。

## 7. 评价与启示

**技术重要性**：首个把 TMA 固化为 SM 级专用硬件的专利；"描述符 + 坐标"三层参数划分使请求只携带坐标，带宽最优；地址迭代、OOB、swizzle 全部硬件化，直接兑现"释放 RF、释放开发者时间"两项承诺；异步 + barrier 事务计数 + multicast 与 CGA/DSMEM/wgmma 姊妹案咬合成 Hopper 数据供给闭环。

**设计亮点**：descriptor cache 利用时间局部性并并行预取；tile/im2col 双模式覆盖通用 GEMM 与卷积且量化了各自代价（FIG. 8D–8K 对照实验式举例）；barrier 更新下沉到内存系统、TMAU 退出同步路径；swizzle 表与 GMMA 8×8 供数视图联合设计。

**局限与观察**：部分实施例维度限 1–5；descriptor cache 逐出策略、multicast 跨 TMAU ack 开销未展开；im2col 偏移精度与维数成权衡；原文笔误（616/716 混用、FIG. 8F 段误引 FIG. 8B、"SM 112" 应为 SM 102）。

**对专题的价值**：与 CGA(17/691,621)、DSMEM(17/691,690)、multicast(17/691,288)、mbarrier(17/691,296/303)、wgmma(17/691,406) 共同构成 2022-03-10 Hopper 申请集群；是 17_Blackwell_SM_Internals 专题中理解 SM 内部 TMA 数据通路的起点文献。
