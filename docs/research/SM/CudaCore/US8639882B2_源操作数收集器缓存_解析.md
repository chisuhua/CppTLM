## 1. 这件专利解决什么问题

[US7834881B2](US7834881B2_操作数收集器架构_解析.md) 建立的 OC 结构有一个致命弱点：**每条指令的每个源操作数都要从寄存器堆重新读一遍**，即使上一条指令刚读过同一个寄存器。这导致：

- **寄存器堆 ↔ OC 的带宽被重复消耗**；
- **bank 读端口被反复占用** → 冲突概率上升。

本件的解法：**把 OC 从"收集容器"升级为"带 cache table 的复用缓存"**——已经在 OC 里的操作数，后续指令可以直接复用，不必回寄存器堆。

这与 20 年后（2020）在 Volta SASS 控制字里发现的 **`.reuse` 标志位** 是同一机制的两个世代表述：
- 专利口径（2011）：**cache table + storage elements**，命中/失效由硬件根据 cache table 判定；
- 实测口径（2020）：**reuse flags + 4 个 source operand slot**，命中/失效由**编译器显式置位**。

详见 [arXiv:1804.06826 解析](arXiv1804.06826_Volta微基准_寄存器复用与bank冲突_解析.md)。

## 2. 摘要（逐字引用）

> Methods and apparatus for source operand collector caching. In one embodiment, a processor includes a register file that may be coupled to storage elements (i.e., **an operand collector**) that provide inputs to the datapath of the processor core for executing an instruction. **In order to reduce bandwidth between the register file and the operand collector, operands may be cached and reused in subsequent instructions.** A scheduling unit maintains a **cache table** for monitoring which register values are currently stored in the operand collector. The scheduling unit may also configure the operand collector to select the particular storage elements that are coupled to the inputs to the datapath for a given instruction, **allowing operands for two or more instructions to be cached concurrently**.

**摘要已经点明了三个可量化参数**：

| 参数 | 值 |
|------|-----|
| storage elements 数量 | 6（说明书给出） |
| 每周期可载入的操作数 | = 寄存器堆 bank 数（说明书给出 4 bank → 4/周期） |
| 可并发缓存的指令数 | 2（摘要与权项 7） |

## 3. 结构解析

### 3.1 SM 层级（FIG. 3C / FIG. 4）

```
Streaming Multiprocessor 310
├── Warp scheduler and instruction unit 312
│   ├── Decode unit 450             ← 全译码：opcode 类型 + 源/目的寄存器索引
│   └── Dispatch unit 470           ← 实现 FIFO；写 decoded values 到 local register file 304
│                                     并负责"避开 bank 冲突"（选择哪些 storage element 接哪些 datapath 输入）
├── Local register file 304
│   ├── bank0 422 / bank1 424 / bank2 426 / bank3 428
│   └── (经 Crossbar 420 连接)
└── Execution unit 302
    ├── Operand collector 440       ← ★ 本件主体
    │   ├── storage elements 441–446 (×6)
    │   ├── ALU 452
    │   └── Result FIFO 454
    └── LSU 303
```

原文（逐字）：

> Decode unit 450 receives the next instruction to be dispatched to execution unit 302. The decode unit 450 performs a full decode of the instruction and transmits the decoded instruction to the dispatch unit 470 ... In some embodiments, **instructions may be dual or quad issued** and decode unit 450 may implement separate decode logic for each issued instruction.

> **Dispatch unit 470 implements a FIFO** and writes the decoded values to local register file 304 for execution. In embodiments that issue multiple instructions simultaneously, dispatch unit 470 may issue each instruction to a different portion of the functional units of SM 310.

> In one embodiment, local register file 304 includes **four banks of registers (bank0 422, bank1 424, bank2 426, and bank3 428)**.

> Crossbar 420 is configured to connect the various registers in each of the register banks to an operand collector 440 in an execution unit 302.

### 3.2 Operand Collector 440（FIG. 5）★核心

原文（逐字）：

> Execution unit 302 implements a datapath for performing an operation. The datapath includes the **operand collector 440**, the **arithmetic logic unit (ALU) 452**, and a **result FIFO 454**. Operand collector 440 includes a number of **storage elements 441-446** that may be coupled to the inputs of the ALU 452. Each storage element 441-446 may be a **flip-flop, latch**, or any other technically feasible circuit component capable of temporarily storing a value to supply as an input to the ALU 452. The outputs of the storage elements may be hardwired to the circuit elements that comprise the ALU 452 such as an adder circuit or a floating point multiplier circuit. As shown, **operand collector 440 includes six storage elements 441-446**. In other embodiments, any number of storage elements 441-446 may be implemented in execution unit 302.

**这是一个"寄存器堆读端口 → 收集缓存 → ALU 输入"的二级结构**：

```
RF bank0/1/2/3 ──Crossbar 420──► OC 440 storage elements 441..446 ──► ALU 452
```

### 3.3 带宽与时序的关键数字（原文逐字）

> The number of operands that may be written into the operand collector 440 during each clock cycle is equal to the **number of register banks in local register file 304**. As shown, local register file 304 includes **four register banks**, thereby allowing up to **four operands** to be written into operand collector 440 during a single clock cycle. However, because operand collector 440 includes **six storage elements 441-446** for providing inputs to ALU 452 during each instruction, the operands may need to be loaded in **two consecutive clock cycles (4 operands in the first clock cycle and 2 operands in the second clock cycle)**.

> In addition, care must be taken to avoid register bank conflicts by storing operand values needed for the same instruction in different register banks 422, 424, 426, and 428. **For example, if all six operands are stored in bank0 422, then six clock cycles are needed to load the operands into operand collector 440.**

> In one embodiment, **dispatch unit 470 includes logic that is configured to avoid bank conflicts** by ensuring that operands for each instruction are stored in different register banks 422, 424, 426, and 428. In another embodiment, **driver 103 may include implement instructions that cause driver 103 to check and avoid bank conflicts during compilation** ...

**这段给出的是一个完整的时序模型**：

| 项 | 值 | 推导 |
|----|-----|------|
| RF bank 数 | 4 | 说明书直接给出 |
| 每周期 OC 可载入操作数 | 4 | = bank 数 |
| OC storage element 数 | 6 | 说明书直接给出 |
| 典型装载时间 | **2 拍**（4 + 2） | 6 元素 / 每拍 4 |
| 最坏装载时间 | **6 拍**（全落 bank0） | 1/拍 |
| 冲突规避责任方 | ① dispatch unit 470 硬件逻辑 ② **driver 编译期** | 说明书明确二选一 |

> **注意**：这是 **Kepler 世代口径**（4 bank × 1 读口的时代），不是 Volta+ 口径。引用时必须标注世代。

### 3.4 Cache Table 与失效语义

原文（逐字）：

> ... cache table is searched to determine whether an index corresponding to that register is currently stored in the operand collector 440. If the operand collector 440 includes an entry corresponding to that register, then the cache table is updated to **remove that index from the slot** (i.e., the value in that slot of the cache table is set to zero **to invalidate the data in the operand collector 440**). Thus, if that register is then specified as an operand in a subsequent instruction, **dispatch unit 470 will reload the value from the local register file 304 into the operand collector 440**, ensuring that invalid values are not provided to the ALU 452.

**失效语义总结**：

| 事件 | cache table 动作 | 后果 |
|------|-----------------|------|
| OC 载入操作数 | 关联 `寄存器索引 ↔ storage element` | 后续指令可命中 |
| **寄存器堆被写入** | **移除该寄存器相关条目（失效）** | 后续指令必须重新载入 |

> **这是本件与 2020 年实测的最重要差异点**：专利口径是"**写回即失效**"（硬件自动）；实测口径（arXiv:2503.20481 §5.3.1）是"**读一次即失效**"（无论命中与否，只要有读请求打到同一 bank 的同一操作数位置，缓存值即失效）——**两者不是同一个机制**，说明 NVIDIA 在 Kepler 之后重新设计了 RFC 的失效策略。

## 4. 权利要求（本次完整取得，逐字引用关键项）

### 4.1 独立权利要求 1（方法）

> 1. A method for executing instructions on a processor core implemented with a **source operand collector cache** coupled to at least one input of a data path residing within the processor core, the method comprising:
> - decoding an instruction to determine a plurality of operands specified by the instruction;
> - **for each operand in the plurality of operands, determining that the operand is not stored in the source operand collector cache**, loading the operand into the source operand collector cache from a local register file; and
> - configuring the processor core to execute the instruction across the operands stored in the source operand collector cache.

### 4.2 从属权利要求（参数化点）

| 权项 | 内容 | 抽取的硬参数 |
|------|------|-------------|
| 2 | 载入时更新 cache table，关联寄存器索引与存储单元 | 索引↔槽位映射 |
| 3 | 检测到寄存器堆被写入 → 更新 cache table 移除相关条目 | **写回即失效** |
| 4 | 寄存器堆由多个 register bank 组成 | bank 化 |
| 5 | crossbar 把第一 bank 的寄存器连到第一 storage element | crossbar 必需 |
| 6 | **crossbar 每周期每 bank 只连 1 个寄存器**进缓存 | **1 R / bank / cycle** |
| 7 | **缓存容量需同时容纳两条已译码指令**的操作数 | **2 条指令并发** |
| 8–13 | 并行处理单元（装置）版本，与 1–7 对称 | — |
| 14–19 | 计算机系统版本，与 8–13 对称 | — |

### 4.3 权项结构解读

```
权项 1  （方法）        ← 核心：decode → miss 则 load → execute
  ├── 2 （cache table 维护）
  │     └── 3 （写回失效）
  ├── 4 （多 bank）
  │     └── 5 （crossbar）
  │           └── 6 （每 bank 每周期 1 个）
  └── 7 （容量 ≥ 2 条指令）
```

**值得注意的权项布局**：权项 1 **没有**限定 storage element 数量、**没有**限定 bank 数量、**没有**限定命中条件的细节。数量（6 个 storage elements、4 个 bank）都只出现在**说明书**，而非权利要求。这意味着：

- NVIDIA 视"复用缓存"这一**概念**为可主张的核心；
- 具体容量是**可调的工程参数**，不是发明点。

这对我们建模的含义：**可以自由选择条目数/容量来对标某代硬件，而不必声称"符合专利"**。

## 8. 对 CppTLM 的可借鉴点

1. **cache table = 一个"寄存器索引 ↔ 槽位"的映射表 + 写回失效钩子**。CppTLM 的 `RegFileUnit::write()` 是唯一写入口，在此处挂失效逻辑成本极低（这是本件最容易照搬的部分）。
2. **"6 个槽位 / 每 bank 每周期 1 个"是一组可直接落地的建模参数**。若 CppTLM 引入 RFC，建议用：`entries_per_bank = 3`（对应 3 个源操作数）× `num_banks = 2`（现代口径）= **6 个子条目**，与实测的现代 NVIDIA RFC 结构完全对齐。
3. **"每 bank 每周期 1 个"是节流点**（权项 6）。这与"每 bank 1 个 1024-bit 读端口"（实测）在语义上等价——**一个 bank 每周期只能服务一个 OC 槽位**。
4. **失效语义必须二选一并显式建模**：写回即失效（专利）vs 读一次即失效（实测）。二者对数据冒险与时序的影响不同，**不能混用**；建议 CppTLM config 提供开关。
5. **bank 冲突规避可以放在 dispatch 侧也可以放在编译侧**（本件明说 dispatch unit 470 或 driver 二选一）。CppTLM 若有 PTX-EMU 上行链路，可在 dispatch/issue 侧做"把同指令的多个源分到不同 bank"的静态重排。
