## 2. 发明背景与待解决问题

**强缩放需求**：DL/HPC 用户要的是单一应用随 SM 数增加而线性加速（strong scaling）。FIG. 2A 旧架构仅 16 SM（4×GPC），FIG. 2B 新架构已达 128+ SM，SM 占芯片面积比从"大块"降到"<1%"；软件侧 CUDA 9 的 Cooperative Groups API 用软件调度提供"并发"，无硬件保证，占用率评估留给应用，跨 SM 数据共享/同步缺乏高效硬件机制。

**加油站类比**：说明书以加油站定义负载均衡——目标是让每个油泵近 100% 占用；油箱大小、付款方式不同使各车占用时长不一，车辆会换队；CGA 则像"需同时占用多个油泵的项目"，比单车 first-come-first-served 难得多。

**带宽动机**：FIG. 6 显示各代 GPU 的 math bandwidth（TF32/FP16/BF16/INT8/INT4/binary、稀疏/稠密）指数增长，而右侧数据带宽需求未同步；FIG. 7 给出 interconnect→DRAM→L2→L1/shared→math 单元的端到端数据流。说明书在背景结尾点题："once a new hardware platform is provided that solves such data bandwidth problems, it would be highly desirable to provide efficient load balancing of work across the hardware platform's concurrent parallel processing resources"——本案即该"新平台上的负载均衡"之答案。

**传统 CWD 的三个扩展性问题**（原文对既有 compute work distributor，引 US20200043123 / US10,817,338 为先前技术）：

1. **负载均衡不可扩展**：每个 CTA 逐个送往"最闲 SM"，CWD 每发一个 CTA 都要比较全部 SM 的利用率再重头开始；SM 数上百后该串行流程极低效，且旧 CWD 无法处理分层硬件域（GPC/μGPU/GPU）的分发范围。
2. **光栅化吞吐瓶颈**：负载均衡解决后，集中生成大量多维 CTA ID（grid rasterization）的数学运算成为瓶颈。
3. **CTA 传输带宽瓶颈**：CUDA 的 CTA ID 为 32b-16b-16b 三维组元（64b），向数百个物理上远离 CWD 的 SM 逐个发送需要巨大带宽。

原文量化举例：若每 SM 可容 8 个 CTA，旧 CWD 填满 128 个 SM 需 1000+ 周期。**新增复杂度**：CGA（Cooperative Group Array，=cluster）要求"一个 CTA 占一个 SM 空槽"的并行资源分配——类比"跨多个团队调度项目"而非"向单个工人派任务"，使均衡难度高于普通 CTA 的 first-come-first-served。

## 3. 核心方案

**被均衡对象：CGA 新层级**。硬件在 Grid 与 CTA 之间插入 Cooperative Group Array（"CGA" 与 "cluster" 同义，CTA 是一种 thread block）：grid 是 CGA 的数组、CGA 是 CTA 的数组（FIG. 10B/11B）。CGA 携带硬件域指定（GPC_CGA/μGPU_CGA/GPU_CGA/ABC_CGA，可嵌套），硬件保证同一 CGA 的全部 CTA 并发启动于该域内——"either the whole CGA is launched or none of it"，并为每 CGA 分配硬件 barrier（引姊妹案 17/691,296）以自举确认全部 CTA 已启动。FIG. 12 列举四类 grid：legacy CTA grid、GPC_CGA grid（如 6×6×1 CGA、每 CGA 3×2×1 CTA）、GPU_CGA grid（替代软件 Cooperative Groups API 但并发由硬件保证）、两级 GPU_CGA-of-GPC_CGA grid。负载均衡即以 CGA 内的 CTA 为粒度、以 CGA 指定的硬件域为范围展开。

### 3.1 负载均衡单元的位置与层级（FIG. 13–15）

负载均衡**集中于单一单元 CWD 420**（"because the CWD is centralized, it can compare the workload of all SMs at once"）。FIG. 14（视觉核对 p020）：Task/Work Unit 207 内含 Scheduler 410 与 CWD 420；CWD 内含 **CGA Load Balancer 422**、resource trackers **TRT 425(0)…425(N−1)**（各与对应 TPC 340 通信）、TPC Enable Table 430、LMEM Block Index Table 432、Credit Counters 434、Task Table 436、Priority Sorted Task Table 438。

FIG. 15（视觉核对 p021）给出**两级（可扩展）分发层级**：GPU2GPC WD 420a（面向 GPC0–GPC7）+ 每 GPC 一个 GPC2SM WD 420b(0)…420b(7)（各管 SM0–SM39）；第一级把 GPC_CGA 分到 GPC，第二级把 CTA 分到 GPC 内 SM；可向上加 μGPU 级、向下加 CPC 级，或递归复用硬件以省面积。设计哲学：**决策集中、执行分布**——CWD 做负载均衡决策，SM 侧 MPC 404 分布式完成 ID 光栅化等记账。

### 3.2 负载信息的收集与传播：free slots 与 mock GPC 查询模型

- **free slots 指标**：CWD 先查询所有 SM 的空槽数，定义为"SM 剩余资源（共享内存、寄存器、warp ID，引 US 9,921,873）还能容纳多少 CTA"；SM 在 grid 光栅化开始时上报，计数存于 Task Table 436。空槽越多＝未来 CTA 竞争越小＝预期"速度"越快。
- **避免长距离查询**：CWD↔GPC 往返延迟大，故 CWD 在内部实例化一组 **mock GPC（query model）**，以 SM 上报的 free slots 建模当前负载；样本 CGA 发给 mock GPC 试装，装不下回 "failure"，装下则按两种模式之一分布 CTA 并回报 **speed = 接收 CTA 的 SM 中最小剩余空槽数**（最慢 CTA 决定 CGA 速度）。
- **双模型**：CWD 维护一个持续更新的 live 模型 + 一个快照 shadow state 模型，投机启动对着快照做；只要投机会话足够短，快照过时风险可忽略。
- **遗留结构 CGA 化**：TPC Enable Table 430、LMEM Block Index Table 432、Credit Counters 434、Priority Sorted Task Table 438 与 TRT 均为既有 CWD 结构（旧操作引 US10,817,338、US20200043123、US20150178879、US10,217,183、US9,921,873）；说明书的"功能增强表"列出为适配 CGA 而被增强的单元横跨 CWD、GPM、MPC、SM、Compute Pipe 与 CTXSW（含分布式光栅化、新 launch packet、更宽 bundle/新 QMD、并行负载均衡器、CTA complete 带宽、CGA 跟踪与 barrier、DSMEM flush、新 S2R 寄存器、SM2SM 错误处理、新 GPC/TPC 编号、计算指令级抢占变更）。

### 3.3 分配决策：注水算法、投机/影子状态启动、分层速度查询

**注水（lake-filling）**：把 CTA 比作水、free slots 比作湖深，从空槽最多的 SM 先填（FIG. 21 翻页动画，视觉核对 p066 之 FIG. 21GG 可见 SM0–SM31、freeslots 1–10、final level/max freeslots 标线）。实现二选一：① 二分搜索水位（N/2→N/4/3N/4 迭代至均衡）；② 自最大空槽向下扫描，末层用 **popcount + SM 优先级**、经 bottom-up reduction/top-down accumulation 以 O(log N) 时间**同时选中一批 SM**（FIG. 22/23），而非逐个选。

**投机/影子状态启动（all-or-nothing 并发保证）**：Pass I 对 query model 做投机启动，每 SM 用 free slot register + launch slot register 记录，后续迭代以 "free−launch" 扣减；全部 CTA 装下才生成 **sm_masks**（附 GPU CGA 序号、end_of_CGA 位，一个 launch packet 可含多条 CTA 启动指令）并广播到所有 SM work scheduler；装不下则整组不发射、稍后重试或改发更小 CGA（FIG. 16-1/16-2，视觉核对 p023：502 收 CGA 任务→504 scheduler 送 CWD→506 GPU2GPC→GPC2SM→508 投机启动→510 Fit?→512 Launch→514 Finished?→516 Flush DSMEM/Linear Memory→518 Release resources）。Pass II 复位 launch slot 后真实启动。

**分层速度查询（FIG. 28A–C，视觉核对 p082 之 FIG. 28B）**：顶层向各 mock GPC 查询 GPC_CGA 的 speed，把 CGA 发给"最快"GPC；同速 GPC 可同时各收一个 CGA；GPC0 试装失败（no valid speed）、GPC1 speed=0、GPC2/3 speed=1=MAX SPEED 的示例与正文一致。该查询-启动过程可递归嵌套（GPU_CGA→GPC_CGA→CPC_CGA），速度取最后一次查询值；接受则提交预留，否则取消。

**GPC 内两种分布模式**：LOAD_BALANCING（CTA 任意放置，同 CGA 多 CTA 可同 SM）与 **MULTICAST**（同 CGA 每 SM 至多 1 CTA，以享用 TMA 多播内存加载，引姊妹案 17/691,276 与 17/691,288）。

**分布式光栅化**：CWD 只广播启动包、不传 64b ID；各 SM 的 MPC 观察全部启动序列独立推导 XYZ 进度，平时只计 delta、需要时才分解（delta/(gridDim.X*gridDim.Y) 等廉价除法），峰值 CTA 启动吞吐较集中式 **提升 36×**。

**翻页动画 II（FIG. 24–27）**：另一实施例不逐 CTA 而**逐行/逐层**填湖——每轮对当前空槽值的 SM 做投机启动、一次装满一整行；二进制搜索同样适用，且"multiple CGAs are launched at once"。

**分层结尾场景（FIG. 28C）**：示例中 GPC0 过满、任何 GPC_CGA 都装不下；GPC1 能装但会耗尽全部资源；GPC2/3 装下后仍有富余，故算法选 GPC2/3 以最大化速度；最终 CWD 把 CGA2 也发到 GPC2，使同一 GPC 上并发跑两个 CGA。三层嵌套（grid→GPC CGA→CPC CGA→CTA）时，mock GPC 再向内递归查询各 CPC 的 speed，GPC CGA 速度取最后一次查询值；顶层接受则**提交**投机预留、否则**取消**——即两阶段提交式的资源预留。

### 3.4 与 GPC/SM 资源准入的关系

- **每 GPC 计数器**：CWD 可为每 GPC 设计数器，按该 GPC 的 SM 数初始化，记录可同时执行的 GPC_CGA 数；发射新 CGA 递减、收到 cga_complete 递增——与 US9,594,599B1 "按使能 SM 数比例分发"的计数器思想同源（见 §5）。
- **SM 侧准入与跟踪**：MPC 404 跟踪每 CTA 槽位；GPM 分配 barrier 槽与 CGA id、计数活跃 CTA；新 S2R 寄存器暴露 gpc_local_cga_id / CGA_CTA_id 供 DSMEM 寻址与 barrier 引用；SM 维护映射表 5002（warp→CGA slot）、5004（CTA_ID→CGA_ID/SM_ID/TPC_ID，CAM）、5010（目标侧 shmem base/size CAM）。
- **回收协议**：CTA 退出后 MPC 发 cta_complete 并标记需 flush；全 CGA 完成后 GPM 向相关 SM 发 DSMEM flush，收齐确认才回收 gpc_local_cga_id，防止新 CGA 读写已死 CGA 的 DSMEM。
- **可移植性上限**：假设任何平台至少有 1 个含 4 TPC 的 GPC，则保证跨架构兼容的最大 CGA 尺寸为 **8 CTA**。

## 4. 权利要求分析

共 20 项，3 项独立（claim 1 处理系统、claim 14 方法、claim 20 启动测试+启动电路系统）。

- **Claim 1**：处理器集合 + work distributor，配置为 (a) 跨处理器**均衡线程块负载**，且 (b) **保证线程块并发执行**；各线程块被分配标识符坐标。从属：2/3 各处理器各自光栅化 grid 之部分（3D grid）；4 SM + 硬件电路；**5 第一级 WD 跨处理器集合分发 + 多个第二级 WD 分到个体处理器**（即 420a/420b）；**6/7/8 query model + shadow state 投机测试、live+snapshot 双模型、迭代/递归多层级**；**9 同时选中多于一个处理器发射**；10/11 CGA + 同阵列线程块每处理器至多一个（MULTICAST）；12 各处理器硬件独立推导唯一线程块 ID；13 依据负载水平判定哪些处理器最快。
- **Claim 14**（方法）：接收代表 CGA 的 grid→基于占用率投机启动含负载均衡→若投机揭示可并发则真实启动。从属 15/16 分布式光栅化（广播+全局多维 ID 推进）、17 硬件电路、18 跨处理器均衡、19 三维 grid/ID。
- **Claim 20**：launch test circuit（判定线程组数组能否在部分已忙的处理器集合上并发）+ launch circuit（条件满足时并发发射全部线程组并均衡负载）——最贴近"影子状态准入测试"的装置表述。

**撰写策略**：独立权利要求刻意使用通用术语——claim 1 用 "thread blocks"、claim 14 用 "cooperative group array of thread blocks"、claim 20 用 "thread group array"——把 CGA 专有名（claim 10）、MULTICAST 约束（claim 11）、分布式光栅化（claim 2/12/15/16）与双模型（claim 7）全部压入从属项，使独立项覆盖面不绑定 Hopper 的 CGA 实现；claim 20 的 "launch test circuit + launch circuit" 对偶即 shadow-state 准入测试的装置化表述，"at least some of which are already executing other tasks" 一语点明其针对的是动态负载下的并发准入。三类法定类别（系统 1–13、方法 14–19、带测试电路的系统 20）完整覆盖。

## 5. 与专题主题的关系

1. **与 13_Work_Distribution_Unit 的对照**：US9,594,599B1（2009）是 WDU→GPC 的**推侧比例分发**（每 GPC 计数器按 SM 数递增、load signal 准入）；本案是 CGA 时代的 CWD→SM **准入+均衡合一**：集中查询 free slots、all-or-nothing 并发保证、批量选 SM。本案"每 GPC 计数器按 SM 数初始化、cga_complete 递增"的段落，是 US9,594,599B1 计数器原则在 CGA 并发准入场景的直接回声。
2. **两级分发的硬件化身**：420a（GPU2GPC）/420b（GPC2SM）即"两级分发"在 Hopper 的实现，且声明可任意加层（μGPU/CPC）——与专题 16 的两级分发叙事互为印证；Blackwell 双 die 进一步放大层级需求。
3. **SM 侧接收与资源准入视角**：本专题（17）关注 SM 内部；本案给出 SM 的"接收面"——TRT/MPC/GPM、free slots 抽象（共享内存/寄存器/warp ID）、DSMEM flush 与 barrier 槽分配、S2R 寄存器，与 TMA/DSMEM/mbarrier 姊妹案共同构成 SM 间协作的调度层底座。
4. **SM 数增多的可扩展性动机**：说明书以 128+ SM（FIG. 2B）、"8 GPC×18 SM" 与 FIG. 15 每 GPC 40 SM 为例，说明逐 CTA 串行均衡在 Hopper/Blackwell 规模下失效；批量并行选择、popcount O(log N)、分布式光栅化 36× 吞吐均为 SM 阵列扩张后的扩展性答案。
5. **从软件 API 到硬件保证的完成态**：CUDA 9 Cooperative Groups API 以软件调度提供 grid.sync() 等并发原语，需应用自行评估占用率、无并发保证；其硬件化前夜是 US20200043123（说明书引为旧 CWD/MPC 先前技术）。本案把 cooperative group 思想固化为 CGA 层级 + all-or-nothing 硬件启动保证 + 负载均衡三合一，完成"软件 API→硬件契约"的过渡，也解释了为何姊妹案集群需要同时布局 DSMEM/mbarrier/多播等配套硬件。
6. **命名与图纸的延续性**：本案 scheduler 410 自 front end 212 收任务（FIG. 16-2 之 502/504，视觉核对），front end 212 的编号与 US9,594,599B1 中向 WDU 200 供任务的 front end 212 同源，属 NVIDIA 专利图纸套话的延续；分发器命名则从 WDU（2009）演进为 CWD 420（Hopper 时代，置于 Task/Work Unit 207 内）。这条命名线可把 13_Work_Distribution_Unit 专题的时间轴直接接到 17 号专题。

## 7. 评价与启示

**技术重要性**：本案把"负载均衡"从软件启发式/逐 CTA 贪心升级为**硬件保证并发性的准入-均衡联合机制**：集中决策（CWD 看全 SM 状态）+ 分布执行（SM 自光栅化 ID）的分工、shadow-state 投机启动（先试装后提交，sm_masks 预留）、注水+二分/popcount 的并行化实现，构成 Hopper cluster launch 的微架构蓝本；每 GPC 按 SM 数初始化计数器的做法把 US9,594,599B1 的比例分发原则延续到 CGA 时代。

**局限性（基于文本）**：free slots 是静态资源抽象，不感知运行期带宽/缓存竞争；shadow 快照正确性依赖"投机会话极短"假设；all-or-nothing 使大 CGA 在碎片化负载下可能饥饿（文本仅给"重试/改发小 CGA"）；mock GPC 与双模型增加面积（文本以递归复用硬件缓解）。

**启示**：shadow-state "先试装、后提交、可取消"的两阶段预留模式可推广到任何 all-or-nothing 资源准入场景（多 die/chiplet 调度、MIG 分区、CGA 跨 GPC 嵌套）；free slots 作为"共享内存/寄存器/warp ID 剩余量"的抽象，是占用率（occupancy）指标的硬件化祖先，可与同目录 arXiv Hopper/Blackwell 微基准论文测得的 cluster launch 延迟、cluster 尺寸上限（Hopper 每 GPC 并发 cluster 数受限）对照阅读——说明书"8 CTA 保跨架构兼容"的断言正对应公开文档中 cluster size 与并发 cluster 数的权衡。

**对专题的价值**：与 TMA/DSMEM/mbarrier/wgmma 姊妹案同日成簇，本案提供簇内唯一的"SM 间调度层"视角；CWD 420a/420b 两级结构、free slots 准入与 DSMEM flush 回收协议，是解读 Hopper/Blackwell SM 数持续增长后 launch 延迟、cluster 占用率与 SM 间通信微基准（arXiv 系列）的钥匙。
