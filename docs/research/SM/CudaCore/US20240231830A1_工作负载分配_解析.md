## 2. 发明背景与待解决问题

**领域（FIELD）**：并行计算中线程间负载均衡；"pertains to processors or computing systems used to perform two or more instructions in parallel"。

**问题陈述（BACKGROUND 原文）**："Assigning balanced workloads to threads based on data structures that contain both zero and non-zero values can be difficult. Techniques to assign workloads to threads can be improved."

**具体痛点**：稀疏矩阵以 CSR/CSC 压缩格式存储时，每行非零元（nonzero）数量极不均匀；若按行把 local offset 一一指派给线程（FIG. 1 中 t0–t7 先各拿一个 offset，t0–t2 再补拿 x8–x10），则"two or more rows may contain different numbers of nonzeros to be operated on"，线程间负载失衡——SpMV（稀疏矩阵-向量乘）等内核在 SIMT 硬件上的经典问题。

**目标**：fine-grained workload balancing——让一组线程中每个线程被分配到**相等数量**的 items（非零元），且分配过程本身可并行、开销低；应用场景点名机器学习、计算流体力学、GraphBLAS、Krylov 子空间方法等。

## 3. 核心方案

### 3.1 两级分配框架（FIG. 1–2）

**粗粒度级（coarse-grained search 104/204）**：对 CSR/CSC offsets 106（rowptr/colptr 数组，可含数百万元素）做二分查找，把偏移数组切分为 portions（行块/列块/grid 块），分配给不同 thread block 或 kernel；划分粒度可基于单 kernel 可承受的 items 数。

**细粒度级（offset expansion module 130/230）**：每个 thread block 拿到一块 local offsets 110/210（示例 x0…x10，比线程数多 3 个），在 scratchpad/shared memory（示例容量 32 items，"shared by all threads in that block"）内执行偏移展开，把不规则行边界转换为每线程等量的显式非零元索引。

**注意**：分配对象始终是**线程**（thread/warp 级），不是 SM 或 GPC。

### 3.2 细粒度均衡四步（FIG. 3–5，核心算法）

1. **部分填充（FIG. 3，array 312）**：执行 `shared_mem[offset]=pos 722`——把每个 local offset 对应的行号写入以其非零元序号为下标的数组位置（如 offset=7 处填行号 3）；空行不写（row 1，arrow 307）；其余空位概念上代表"各行首非零元之间的非零元个数"。array 312 均分给 threads 308a–h，每线程最多 4 items。
2. **段内最大值（FIG. 4，identify maximums 414）**：每线程在自己 range 内求最大行号，得 maximum values 416a–h = {0,3,4,5,7,8,9,−1}；空 range（如 positions 28–31）记 −1，后续搜索遇 −1 前跳。
3. **前段最大值（FIG. 5，identify previous maximums 518）**：用 reduction/scan 求"前一线程 range 的最大值"，复杂度 O(log(#threads))；得 previous maximum values 521a–g。
4. **传播填充（propagate previous maximums 522）**：每线程对 range 迭代 `max(current, prev)`，把空位填满，得 filled array 512；此后**每个位置对应一个非零元、其值即行号**，每线程恰好等量（FIG. 5 中 t0–t7 各 4 个，视觉核对与封面图一致）。该步亦称 offset expansion / finding explicit indices。

### 3.3 SpMV 三阶段流程与工程优化（FIG. 6–7）

**process 600**：602 偏移值入数组 → 604 各 range 求最大 → 606 求前段最大 → 608 前缀和并行传播（"propagating maximum values uses a prefix sum… performed in parallel"）。

**block diagram 700**：phase one 706（load column indices 712、load CSR values 714、load input vector values 716、计算 A*X 719）→ phase two 708（load coarse-grained bounds 719、load local offsets 720、shared_mem[offset]=pos 722、find previous max 724、**generate explicit row indices into registers 726**）→ phase three 710（**segmented reduction by key 728** + 基于 warp-bound 值与原子操作存储输出向量 730）。

**配套优化清单**：
- 首行行索引跳过均衡、直接 uniform reduction；
- ≤32 行：local offsets 复制到每 warp 寄存器，做 **shuffle-based binary search**（warp 内线程互读寄存器）；
- 行索引位宽自适应：≥256 行用 uint8_t、≥65536 用 uint16_t、>65536 用 int32_t；
- 稀疏矩阵只读一次入 SM cache；输入向量多次读、可驻 edge cache；
- 最终 warp 级多值 segmented reduction 视 range 大小落在 shared memory（大于 L1 且放得下时）或 global memory；
- kernel 参数存 constant memory，自动调优 thread block size、nonzeros/thread、每 SM 最小 block 数；
- 利用矩阵聚类模式调度多个 thread block 组成 **CGA（thread block cluster）**，以 **distributed shared memory** 代替 L2；
- 128-bit 原子操作单次处理复数；coarse kernel 经 **dynamic parallelism / fast dependent kernel launch** 直接启动 fine kernel。

### 3.4 分层前缀和（FIG. 8）与处理器模块（FIG. 9）

thread-level prefix sums 802 → warp-level prefix sums 804 → 写入 shared memory 806（经 syncthreads() 807 同步，克服 thread divergence 造成的写入时差）→ reduce_add() 得 block-level prefix sums 808 → down-sweep 传播 thread-level sums 810。

设计约束：reduction 的共享内存访问、同步点、warp 级数各不超过一次（up-sweep + down-sweep 结构）。

FIG. 9 的 processor 902 含四个功能模块：offset expansion module 930、identify maximums module 932、identify previous maximums module 934、prefix sums module 936；"module" 定义为软件/固件/硬件逻辑任意组合，可分布于多处理器。

## 4. 权利要求分析

共 20 项，3 项独立：claim 1（processor）、claim 8（computer-implemented method）、claim 15（system）。

**独立项主体**（三者同构）："perform two or more instructions in parallel based, at least in part, on one or more locations of one or more non-zero values within one or more operands"——只锚定"依据非零元位置并行执行"这一结果，不绑定具体算法步骤，保护范围极宽。

**从属项分组**：
- 数组存储非零元变量 + 行指示：claim 2/9/16/18；
- 操作数为稀疏矩阵 / 压缩稀疏格式（CSR 或 CSC）：claim 3/10/17；
- 行首非零元（first nonzero in a row）：claim 4/11；
- **prefix scan/sum 等量分配到线程**：claim 5/12/16；
- offset values 表征非零元位置：claim 13/19；
- maximum / previous maximum values：claim 7/14/20。

真正的方法学护城河在从属项点名的"offset 展开 + 分层前缀和"组合；独立项的泛化措辞则覆盖任何"按非零元位置做并行分配"的实现。

## 5. 与专题主题的关系（客观评估）

**相关度：低—中（间接）**。本案"workload assignment"的分配对象是**线程**（thread block 内等量 items），属于 SpMV 内核的**软件/算法层负载均衡**，而非 SM 之间或 SM 内部硬件单元之间的工作分发；全文不涉及 WDU/GPC 调度、warp 发射、SM 分区等硬件机制。

与 SM 内部的间接接触点：
1. 算法全程以 SM 资源为舞台——shared memory/scratchpad、寄存器、warp shuffle、L1 cache、原子操作；
2. 明确点名 Hopper 世代特性 **CGA/thread block cluster 与 distributed shared memory**、dynamic parallelism，反映 2023-01（Hopper 发布后）申请时 SM 能力对软件设计的约束；
3. FIG. 26–28 的 PPU/GPC/SM 图（含 SM 2500 等）系 NVIDIA 模板化 boilerplate，仅用作实施环境，**非发明对象**。

结论：本案对 17_Blackwell_SM_Internals 的价值在于"软件视角的 SM 资源使用模型"（共享内存容量、shuffle、cluster DSMEM 如何被稀疏内核消费），而非 SM 硬件实现披露；归入本专题应视为外围背景文献。

## 7. 评价与启示

**技术价值**：把 CSR 不规则行划分转化为"每线程等量非零元"的 offset expansion，全程用 fill-max / previous-max / prefix-sum 等并行原语完成，避免串行 compaction 与原子计数器争用；O(log(#threads)) 前段最大值扫描与"单次共享内存访问/单同步点"分层 scan 是 warp-SIMT 友好的算法设计范本；位宽自适应、shuffle 二分、CGA+DSMEM、128-bit 原子等优化清单，实质是 Hopper 世代稀疏内核的工程手册。

**局限**：说明书为 NVIDIA 模板化巨篇（FIG. 10–41 全为 boilerplate 系统/软件栈图），核心算法仅 FIG. 1–9；独立权利要求纯功能性措辞，稳定性依赖从属项；均衡前提是非零元数 ≥ 线程容量，尾部不足情形着墨不多；文本有笔误（如 "thread- level sums 801" 与 810 混用、FIG. 7 中两个 719 编号重复）。

**对本专题的启示**：与 13_Work_Distribution_Unit 专题"硬件按 SM 算力比例分发"形成对照——本案是"软件按数据非零结构向线程等量分发"，二者构成 NVIDIA 工作分配技术的软硬两面；其 CGA/DSMEM/shuffle 用法可作 Blackwell SM 内部资源被软件消费的参照样本。
