## 2. 发明背景与待解决问题

**应用驱动**：深度学习/HPC 需要 strong scaling（强扩展）——单应用不改变负载而随 SM 数量增加获得近线性加速（FIG. 1A–1C 以 DL 网络按 output-activation tile 切分、每 SM 一块 tile 为例）。文本以"修路工程"类比 weak scaling（每个 crew 干更多活）与 strong scaling（增加 crew 数、每 crew 工作量不变），指出 DL 训练等问题规模固定、只适用 strong scaling。FIG. 2A/2B 对比老 GPU（16 SM、4 GPC×4 SM，SM 占芯片面积大头）与新 GPU（128+ SM、每 SM 占比小但内部数学硬件更多，如 Volta GV100 的 4 processing blocks×16 FP32/8 FP64/16 INT32/2 tensor core、64 KB 寄存器堆）；FIG. 6/7 进一步指出：每代 GPU 的数学吞吐指数增长，而数据带宽（memory/interconnect bandwidth）未同步跟上，必须从算法 locality 与硬件协作模型中挖潜力。

**现有技术的不足**（按文本表述）：
1. **共享内存被限制在 SM 内**： prior "shared memory"（LDS/STS/ATOMS 访问的 SM 私有 local memory）只能被同 SM 线程访问；跨 SM 的 CTA 间数据交换必须经 L2/全局内存，"expensive in terms of resources and also took up bandwidth"（col. 5–6）。
2. **Cooperative Groups API 纯软件**：CUDA 9 的 Cooperative Groups 把同步扩展到 grid 级（grid_group、grid.sync()），但用软件而非硬件提供并发执行；无硬件并发保证时，软件需额外调用评估 occupancy 才能预测 grid group 能否 launch，且缺乏跨 SM/跨设备高效共享数据带宽的机制，导致冗余取数、带宽瓶颈（col. 4）。
3. **prior CTA grid 无协作语义**：每个 CTA 独立被调度到最空闲 SM，CTA 间能否并发 residency 取决于平台与负载，跨 CTA 线程无法通信/同步（col. 9–10）。

### 3.2 关键机制详解

**CGA 层级与硬件域亲和**：CGA 是 CTA 的 grid（cooperative thread arrays 的集合），在 Grid 与 CTA 之间插入新层级：Grid → GPU_CGA → µGPU_CGA → GPC_CGA → CTA（FIG. 10B），可嵌套（GPU_CGA 由 µGPU_CGA 组成、µGPU_CGA 由 GPC_CGA 组成……），各级绑定对应硬件域（同 GPU / 同 µGPU / 同 GPC 的 SM 集合），以匹配内存访问与通信能力（col. 13–14）。

**并发执行的硬件保证（co-scheduling）**：GPU 硬件不允许 CGA 的任何 CTA launch，除非该 CGA 全部 CTA 在其硬件亲和域内有足够资源同时 launch——"either the whole CGA is launched or none of it"；任何单个 CTA 不会无限期等待。每个 CGA 配有硬件 barrier，硬件维护 running CTA 计数，供 barrier 同步与 bootstrap 确认全部 CTA 已 launch（col. 14）。

**Speculative launch（投机启动）**：work distributor 硬件电路在真正 launch 之前，先把 CGA 投机性地跨多个处理核"试 launch"以判定全部 CTA 能否并发驻留，仅当判定时通过才实际 launch（claim 1/8/14）；launch 同时在硬件级对并发 CGA 的 shared memory 用量做 throttling（claim 9），并以 CGA linear memory slot 的可用性阻止 launch（col. 25–26：硬件跟踪已分配 buffer 数，阻止第 N+1 个 CGA 直至有 CGA 完成释放）。

**两级 work distributor**：FIG. 15B 的 GPU2GPC WD 420a 把 CGA/CTA 先分到 GPC，GPC2SM WD 420b 再分到 GPC 内 SM0–SM39——即多级 work distribution 架构（claim 17），实现"CGA launch on associated hardware affinity/domain"。CWD 420 的内部表项（430/432/434/436/438）与 CGA Load Balancer 422、TRT 425 资源跟踪器对应 claim 18；CWD 可查询并 launch 多个 CGA 的 CTA 但一次只处理一个 CGA（claim 20）；grid launch packet 可广播到多个处理器（claim 7）。完成路径：SM 向 GPM 报告 CTA 完成，GPM 收齐全部 CTA 完成（块 514）且内存 flush（块 516）后通知 CWD 420 释放 CGA 槽（块 518）。

**DSMEM（distributed shared memory）**：把各 SM 的 local memory 以"带洞的连续段"形式暴露为统一地址空间，同 CGA 内任一 CTA 可被另一 SM 直接 LD/ST/ATOM 访问；地址格式为 [DSMEM/SMEM Aperture | CTA ID within CGA | SMEM Offset]，CTA ID 置零即退化为本地 SMEM，保持向后兼容；每 CTA 可配 8/16/32 KB。路由经 GPCARB/TPCARB 与 GXBAR（k×k 开关，示例 k=6 构成全连接 12×12，地址哈希路由防 camping），请求/响应可走不同路径；配套硬件 barrier、MEMBAR 处理、CGA_id 分配/回收协议、context switch 时 DSMEM flush/restore、CAM 路由表与错误/trap 处理（col. 27–28、39–42）。

**DSMEM 请求/响应硬件流程（FIG. 22、23A–23B）**：源 SM core 产生带地/内存槽（gpc_local_cga_id 与 sm_id）的 DSMEM 访问请求（块 6002/6004，查表确定目标 SM 共享内存）→ 互连排队转发（6006/6008）→ 目标 SM 仲裁并校验 DSMEM base/size（6010/6012）→ 目标 SM 共享内存执行（受 barrier 阻塞约束，6014）→ 读数据或写 acknowledge 入队（6016/6018）→ 经 Tex2gnic 返回响应/合并写 ack（6020/6022）→ 源 SM 用 tracking/transaction counters 做 credit 校验（6024/6026）→ 数据呈现给 core（6028）。GXBAR 用多组 k×k 开关避免协议死锁（如 SM1 等 SM2 应答而 SM2 同时等 SM1 的场景）。

**CGA 共享内存的两种形态**：(1) DSMEM——物理上分布在各 SM local memory 内、逻辑上统一的低延迟共享空间；(2) CGA linear shared global memory——位于 L2/（cached）DRAM 的线性池（FIG. 13/14A/14B），按 CGA_linear_memory_slot 分成 N 段、每段 S 字节，shader 以 CGA_linear_mem_base + CGA_linear_mem_size*CGA_slot 计算地址；API 扩展参数 CgaLinearSlotLowerLimit/UpperLimit/LimitEnable 供软件限定槽范围，硬件在槽不可分配时阻止 GPC_CGA launch，从而把共享内存总量纳入并发 throttling。

**硬件能力清单（col. 9）**：
- SM-to-SM 直达同 CGA 内任一 CTA shared memory 的通信；
- DSMEM 支持 read/write/atomic 指令；
- 基于 CTA_id_within_CGA 的分段寻址；
- CGA_id 分配与回收协议；
- 供远程 SM 寻址 DSMEM 的 CAM 结构；
- GPCARB 内新低延迟 SM2SM 通信网络；
- DSMEM 合并写 ack 与优化的 Membar 处理；
- CGA 创建与 context switch 期间同步 DSMEM 的硬件 barrier（含 switch 前 flush、restore 后再放行访问）；
- CGA/CTA exit 与错误处理协议。

## 5. 与专题主题的关系（WDU→Crossbar→GPC→SM 链路）

本专利正是 Hopper 时代 thread block cluster 的硬件专利，直接落在「WDU→Work Distribution Crossbar→GPC→SM」链路的分发语义上：

1. **分发单位从 CTA 升级为 CGA**：传统 WDU/work distribution crossbar 以独立 CTA 为单位做负载均衡；本专利的 Compute Work Distributor 420（FIG. 15A）以 CGA 为单位做 co-placement——必须把一组 CTA 按硬件亲和（同 GPC/同 µGPU/同 GPU）协同放置到多个 SM，且提供 all-or-none 的并发驻留保证。CGA Load Balancer 422 与 TRT 425 跟踪的是 TPC/SM 级资源信用（credit counters 434、TPC enable table 430），即 crossbar 下游各 GPC/TPC 的容量账本。
2. **两级分发对应 crossbar 两级**：FIG. 15B 的 GPU2GPC WD 420a → GPC2SM WD 420b(0..7) 与 NVIDIA GPU 中 work distribution crossbar（GPU 级）+ GPC 内分发（TPCARB/SM 级）的拓扑一一对应；claim 17 的"multi-level work distribution architecture"即该链路的权利要求化。
3. **speculative launch 是 occupancy 检查的硬件化**：把 prior Cooperative Groups 软件做的"grid 能否并发驻留"评估前移到 WDU 硬件，在 CTA 进入 GPC/SM 之前完成跨 SM 的资源试算，避免 cluster 部分驻留死锁。
4. **CGA 还拉动下游互连**：CGA 的 DSMEM 依赖 GPC 内 SM-to-SM 网络（GXBAR/GPCARB，FIG. 21A–21D），即 cluster 放置到同一 GPC 后才能享受低延迟分布式共享内存——放置决策与互连拓扑强耦合。
5. **AMD 侧对应**：AMD 的对偶思路是 workgroup 拆分/跨 CU 协作，如 EP3785113B1 的 split workgroup——把 workgroup 拆分为可在多个 CU 上协同执行的片段以突破单 CU 驻留限制；但其方向是"拆分以适应资源"，而本专利是"硬件保证整组共驻并提供跨 SM 共享内存"，两者在并发保证与共享内存层级上路线不同。
6. **与公开软件栈的对应（分析推断）**：本专利的申请日（2022-03）与 Hopper 发布同期，CGA 即 CUDA 12/Hopper 编程指南中 thread block cluster 的硬件侧描述：GPC_CGA 对应 cluster 内 CTA 共驻同一 GPC 以使用 distributed shared memory 与 cluster 级同步（__cluster_* / cudaLaunchKernelExC 的 cluster 属性），GPU_CGA 对应 device-wide cooperative launch；说明书对 DSMEM、cluster barrier、speculative launch 的描述与 Hopper 公开特性一一吻合，但"CGA"命名与具体表项结构（430–438、425）属专利独有披露。

## 7. 评价与启示

**技术重要性**：
- 本专利把 Hopper thread block cluster（CGA）的三根支柱——并发驻留硬件保证、speculative launch、跨 SM 分布式共享内存——写成独立权利要求，是理解 cluster/DSMEM 硬件实现的钥匙；与同族 11 件申请（DSMEM、硬件 barrier、多播、负载均衡等）构成完整专利包。
- "all-or-none" co-scheduling 把 occupancy 评估从软件（Cooperative Groups 的 grid group 探测）移入 work distributor 硬件，消除了 grid.sync() 类全设备同步的死锁隐患，也为 cluster 级 tensor 并行（如 split-K、flash-attention 跨 SM 归约）提供确定性时序。
- FIG. 15A/15B 罕见地公开了 NVIDIA compute work distributor 的内部账本结构（TPC enable table、LMEM block index table、credit counters、priority-sorted task table、TRT 资源跟踪器）与 GPU2GPC→GPC2SM 两级拓扑，对还原 Hopper 前端分发硬件极具价值。
- GXBAR k×k 开关 + 地址哈希路由的 SM-to-SM 网络，是 GPC 内分布式共享内存的物理基础，可视为"GPC 内小 NoC"的公开描述。

**局限性**：all-or-none 保证在资源紧张时依赖 throttling（限制并发 CGA 数/共享内存槽），大 CGA 可能降低利用率；CGA 规模受硬件域容量（GPC/µGPU SM 数）约束；claim 13 中 "GPC, µGPU, GPC, or TPC" 的 GPC 重复疑为笔误；扫描件个别小字（如 FIG. 15C 流程块号）视觉辨认有限，以原文为准。

**启示**：与 AMD EP3785113B1 split workgroup 对照可见两条路线——"拆分组以适应硬件" vs "硬件保证组共驻并配共享内存"；NVIDIA 路线以更强硬件承诺换取编程模型确定性，代价是分发硬件（WDU/crossbar）复杂度上升。对国产 GPU 设计，CGA 式协同放置与 DSMEM 路由是值得评估的强扩展使能技术。
