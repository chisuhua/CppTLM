## 2. 发明背景与待解决问题

**应用场景**：编译器把通用语言（如 C++）写成的软件应用文本编译为面向目标处理设备的优化机器指令序列；目标可以是并行处理单元（PPU），其通过大量小型并行执行线程在可编程硬件处理引擎上获得高性能。部分 PPU 采用 SIMT（single-instruction, multiple-thread，单指令多线程）技术：用公共指令单元向 PPU 内的处理引擎集合发射指令，支持大量大体同步的线程并行执行。PPU 内部把线程组织为相关线程组，称为 "thread groups"（线程组）或 "warps"（线程束）：warp 内每个线程在不同数据上并发执行同一程序、各占一个处理引擎，且从同一程序地址开始执行。

**分歧问题**：程序中的条件指令会使同一 warp 内不同线程走上 divergent execution paths（分歧执行路径）。

**现有技术的做法与缺陷**（按文本表述）：许多 PPU 以 warp 为粒度、用硬件 call return stack（CRS，调用返回栈）以 push-pop 方式管理执行——每个 warp 只关联单个 active program counter（活动程序计数器），任一时刻只有一个路径在执行，分歧路径被埋没在 CRS 里；PPU 把各 warp 的分歧路径**串行化**，屏蔽不在当前路径上的线程；若某条指令嵌在分歧路径内，只有该路径执行期间活跃的线程才会遇到它；所有路径顺序执行完毕后线程收敛回单一路径。

**待解决问题**：串行化会扭曲原始软件语义并产生不良后果。典型例子是 barrier（屏障）、spinlock（自旋锁）等按 warp 求值条件的指令：由于 PPU 每 warp 只执行单一路径，这类指令会 gate（阻塞）整个 warp 的程序推进；某些线程可能永远得不到满足条件的机会，程序可能 **deadlock（死锁）**。因此本领域需要一种在并行架构中管理线程与线程组的更有效技术。

**任务分发路径（本专利所处链路上游）**：CPU 102 将命令流写入数据结构并把指针写入 pushbuffer；Host Interface 206 读取 pushbuffer 并把命令流传给 Front End 212；Front End 212 把处理任务传给 Task/Work Unit 207 内的 work distribution unit（WDU）——WDU 接收的是指向以 Task Metadata（TMD，任务元数据）形式存于存储器的处理任务的指针；TMD 含待处理数据索引、状态参数与命令（如指定执行程序），可带优先级，并可带参数控制该任务加入任务列表的头部或尾部；task/work unit 207 在启动每个 TMD 指定的任务前保证 GPC 208 处于有效状态。GPC 208 内由 Pipeline Manager 305 把来自 WDU 的任务分发给 SM 310，并控制 Work Distribution Crossbar 330 指定 SM 310 输出数据的去向；SM 处理完的任务经 Work Distribution Crossbar 330 送往其他 GPC 208 或经 Crossbar Unit 210 存入 L2/PP Memory 204/系统内存图形数据还可经 preROP 325 送往 Partition Unit 215 内的 ROP。

**SM 的执行组织**：每个 SM 310 处理一个或多个 thread group/warp（一个线程占一个执行单元）；线程组可少于执行单元数（部分执行单元空闲）或多于它（跨连续时钟周期执行）；每个 SM 最多同时支持 G 个线程组，故 GPC 内最多 G*P 个。多个在 SM 310 内同时处于不同执行阶段的相关线程组构成一个 CTA（"thread array"），其规模 = p*k（k=每线程组线程数，通常为执行单元数的整数倍；p=SM 内同时活动的线程组数）。

### 3.2 关键机制详解

**(1) 树形分歧管理总览（FIG. 4）**：与传统按 warp 串行化分歧不同，SM 310 在保留 warp/CTA 层次的同时把执行管理细化到**线程粒度**：为每个 CTA 维护一棵执行节点树，存于 TDT 410——TDT 的每一行表示一棵**展平的（flattened）**节点树，对应一个在 SM 上执行的 CTA（替代实施例中可对应一个 pixel sub-tile，像素子块）。CTA 启动时 SM 生成 root node（根节点，指定 CTA 全部活跃线程）并初始化该行；随后按各节点中的 program counter 为每个活跃线程执行指令。若某指令导致活跃线程分歧，SM 为每条执行路径创建单独的 child node（子节点）加入 TDT 行，并链回执行节点（此时成为 parent node，父节点）：每个子节点被赋予不同的 PC 和父节点活跃线程的一个**互不相同、互斥的子集**。之后 SM 暂停父节点、开始执行子节点；执行中可再次分歧，SM 递归创建更下层子节点。处于树最底层的节点是 leaf node（叶节点），否则为 internal node（内部节点）；SM 可**并发执行所有叶节点**——若叶节点活跃线程总数超过执行单元数，则跨连续时钟周期执行，调度方式任意可行；叶节点执行完毕后从 TDT 移除（pruning，剪枝；替代方案是禁用）。FIG. 4 示例：SM 同时执行 CTA0 402（root+leaf0+leaf1）与 CTA1 404（root、内部节点 node0/node1、叶节点 leaf2~leaf5），阴影节点为正在执行者。

**(2) 节点格式（FIG. 5A/5B）**：Node 500 表示 1–256 个线程（组织为 8 个 warp），共 16 字节 = Header 510（4B）+ Program Counter 520（4B）+ WIA 530（8B，8 个 warp index，另 2 字节未用）——**恰与一个 CRS 栈项等量**。每个 32 线程 warp 最多可关联 64 个节点，故 WIA 值域 0~63。Header 字段：VA 512（valid/active，取值 "unable to execute"/"executable"，通常缓存在硬件中以提升效率）；Token 514（"none"/"SYNC"）；Refcount 516（直接子节点数：分歧时按新增子节点数递增，非根子节点完成时在 parent 518 所指父节点中递减）；Parent 518（指向直接父节点；根节点自指，部分实施例可为 null）；Unused 515。SM 依 Header 操作节点：active 则为节点的每个活跃线程执行 PC 520 指定的指令；不活动的父节点其 PC 520 指向特定同步点（synchronization point），待子节点收敛后重新激活并从该点恢复。Token="none" 时正常执行；Token="SYNC" 表示该节点是同步操作目标、PC 即同步点；线程重新收敛时 SM 将 VA 置 "executable"、Token 置 "none" 并恢复执行。Quad Node 550（FIG. 5A）同理但表示 1–1024 线程（组织为 8 个 quad-warp，每个 quad-warp = 4 个 warp），Quad Header 560 位分配为 VA 2 bit、Token 4 bit、Refcount 10 bit、Parent 12 bit、Unused 4 bit；每个 32 线程 quad-warp 最多 256 个 quad 节点（WIA 值域 0~255）。替代实施例中 WIA 条目可关联单个 warp、quad-warp 或 pixel sub-tile。

**(3) 辅助表 WMT/WDT 与活跃线程判定（FIG. 6、FIG. 9）**：为压缩节点存储，WIA 不内嵌掩码，而是引用两个可在多节点间共享的 CTA 级辅助表：**WMT 610**——CTA 启动时创建，每条目是一个物理 warp id（wid），记录分配给该 CTA 的 warp；执行期间内容不变；为兼容 quad-warp，每个 warp index 占 4 个条目；WIA(0:2) 指定的地址对应 WMT，WIA 中的数据对应 WDT。**WDT 620**——二维表，行=warp id、列=warp index，每条目为 32 bit warp mask（每 bit 对应 warp 内一个线程，'1'=活跃）；启动 CTA 时按 WMT 添加初始掩码；warp 分歧时 SM 向对应行添加新掩码并更新子节点 WIA，收敛时删除无用掩码。方法 900 给出判定流程：902 置节点级活跃线程列表为空、index=0 → 904 wix = WIA[index] → 906 wid = WMT[index] → 908 warp mask = WDT[wid 行, wix 列] → 910 掩码作用于该 warp 得到 warp 级活跃线程列表 → 912 并入节点级列表 → 914 到 WIA 末项则结束，否则 916 index+1 回到 904。

**(4) 实例（FIG. 7，context 710）**：SM 以 2 个满员 warp（wid 2 与 wid 5，即 warp 2、warp 5）启动 CTA0 402：根节点 WIA(0:7) 前两项置 warp index 0，WDT 第 0 列两行均为 0xFFFFFFFF。随后一条指令使 warp 2 分歧：warp 2 的一个线程子集走一条路径，warp 2 其余线程与 warp 5 全部线程走另一路径。SM 创建子节点 leaf0 与 leaf1，向 warp 2 行新增掩码 0xAAAAAAAA（wix 1）与 0x55555555（wix 2）；leaf0 的 WIA 指定 warp 2 用 0xAAAAAAAA、warp 5 用 0x00000000（即 warp 5 在 leaf0 无线程活跃）；leaf1 指定 warp 2 用 0x55555555、warp 5 用 0xFFFFFFFF。WIA 未用条目置 warp id 63，引用掩码 0x00000000。（掩码取值仅为解释示例。）

**(5) CTA 管理流程（FIGS. 8A–8B，方法 800）**：802 创建并执行节点 500（设 WIA、按 WMT 更新 WDT，启动 CTA）→ 804 某指令导致活跃线程分歧，该点成为父节点 → 806 为每条路径创建子节点：在 WDT 中写入新掩码并设置子节点 WIA，使每个子节点指定父节点活跃线程的一个互斥子集，且各子节点 PC 520 指向不同指令 → 808 子节点加入父节点所属 CTA 的 TDT 行 → 810 父节点 VA 置 "unable to execute"、Token 置 "SYNC"、PC 置同步点（子线程收敛的回归目标），Refcount 按子节点数设置，子节点 Parent 指回父节点，子节点 VA 置 "executable"、Token 置 "none" → 812 父节点暂停，叶节点并发执行（掩码保证无线程被两个叶节点重复执行）→ 814 有节点结束？（判定方式任意可行，如遇到使分歧路径回归父路径的 pop-synchronization 指令）是 → 816 删除已完成叶节点，并相应更新 WDT（移除掩码）、TDT（移除节点）、父节点 Refcount → 818 父节点的全部子节点都完成？（如 Refcount=0）否→回 812；是 → 820 父节点 VA 置 "executable"、Token 置 "none"，从其 PC 指定的同步点恢复执行。子节点在完成前若再分歧，则被视为新一层父节点递归处理。

**(6) 存储优化**：共享 WDT 显著省存储——上例 root/leaf0/leaf1 三节点只需 5 个活跃掩码，若每节点独立存掩码则需 6 个（每节点 2 个）；某些实施例中 SM 按掩码上限分配 WDT 存储：64 warp × 64 掩码 = 每个 TDT 4096 个掩码，对比"每节点 4096 个掩码"的独立存储方案。

## 4. 权利要求摘要

共 22 项权利要求，3 项独立权利要求（claim 1 方法、claim 12 非暂态计算机可读存储介质、claim 21 系统）。

**独立权利要求 1（方法）要点**：访问 TDT 中的第一节点（TDT 用于管理处理实体内的线程执行；其每一行表示一棵不同的节点树；每个节点表示至少一部分 warp 的执行信息；第一节点含第一 warp index array，各 warp index 对应至少一个 warp）；将第一 warp index 置为该 WIA 中与第一位置对应的首条目值；将第一 warp ID 置为 warp mapping table 中与同一位置对应的首条目值；基于第一 warp index 与第一 warp ID，将第一 warp mask 置为 warp divergence mask table 中对应条目的值；将该掩码施加于第一 warp ID 所指 warp 的线程以确定第一活跃线程集；经由该第一活跃线程集执行与第一节点关联的一条或多条指令。

**独立权利要求 12（存储介质）**：与 claim 1 相同的操作步骤，以非暂态计算机可读存储介质形式保护。

**独立权利要求 21（系统）**：包含存储 TDT 的存储器与耦合的处理单元，处理单元执行 claim 1 式的访问节点/置 warp ID/置掩码/施加掩码/执行指令操作。Claim 22：处理单元为 PPU 或 PPU 内的 SM。

从属权利要求按主题分组：
- **WDT 寻址细化**（claim 2 / 13）：按 warp index 定列、按 warp ID 定行，取交叉点条目值为掩码；
- **多 warp 关联**（claim 3 / 14）：TDT、WMT、WDT 关联两个以上 warp；
- **节点内并行**（claim 4 / 15）：第一活跃线程集中两个以上线程并行执行第一节点中的指令；
- **同节点跨 warp**（claim 5–6 / 16–17）：取 WIA 第二位置的 wix/wid/掩码确定第二活跃线程集，两集合共同执行同一第一指令（claim 6/17：并行执行同一指令）；
- **跨节点同 warp 分歧**（claim 7–9 / 18–20）：访问含第二指令与第二 WIA 的第二节点；用第二 WIA 第一位置条目与第一 warp ID 从 WDT 取第二掩码、确定第二活跃线程集；第一集执行第一节点指令、第二集执行第二指令；claim 8/19：两集为同一 warp 内互斥子集；claim 9/20：两集并行执行不同指令；
- **quad-warp 模式**（claim 10）：WMT 将 warp index 映射为单个 warp ID 条目，或在 quad-warp 模式下映射为一组 warp ID 条目；
- **WDT 结构**（claim 11）：二维表，第一维对应 warp index、第二维对应 warp ID，条目为标识 warp 内活跃线程集的 warp mask。

## 5. 与专题主题的关系（WDU→Work Distribution Crossbar→GPC→SM 链路）

**链路定位——WDU 下游的 SM 资源组织层**：本专利自身 FIG. 2/3 完整画出了上游链：Front End 212 → Task/Work Unit 207（含 WDU）→ Work Distribution Crossbar 330 → Pipeline Manager 305 → SM 310。专利方案**不改动上游分发**，而是回答 SM 收到 CTA/warp 之后的问题：

1. **接收**：WDU 把 CTA（以 TMD 指针形式）经 work distribution crossbar 330 送达某 SM 310；CTA 启动时 SM 建立该 CTA 的 TDT 行、root node、WMT 610（冻结记录分配到本 CTA 的物理 warp id）与 WDT 620 初始全 1 掩码——即 warp 组在 SM 侧的落地登记；
2. **分组**：节点 500 的 WIA 530（8 个 warp index 槽位）把 CTA 的 warp 按执行路径重新切分——一个节点 = 一个 PC + 一组 (wix, 掩码) 对，可横跨多个 warp 取各 warp 的线程子集（FIG. 7 中 leaf1 同时含 warp 2 的一半线程与 warp 5 全部线程）；quad-warp 模式则把分组粒度放大到 4 warp 一组（节点覆盖最多 1024 线程）；
3. **调度**：VA/Token 决定节点可调度性——只有 "executable" 的叶节点可被发射，SM 并发执行所有叶节点（超出执行单元数时跨周期轮转，调度策略任意可行），父节点挂起在 "SYNC" 同步点；叶节点完成即剪枝、Refcount 归零后父节点恢复。这实质是把 SM 的 warp 执行状态从传统"每 warp 单 PC + CRS 隐式栈"变为"每 CTA 一棵显式节点树、多 PC 并行"。

与 WDU 的分工：WDU 决定**哪些** CTA/warp 落到**哪个** SM（空间分发），本专利的 TDT/WMT/WDT 机制决定这些 warp 在 SM 内部**如何组织与并发**（执行资源组织）；两者解耦。

**AMD 侧对应（分析者对比评述，非专利文本内容）**：AMD GPU 中 wavefront（GCN 时代 64 线程）是与 NVIDIA warp 对等的执行单元，由 SPI（Shader Processor Input）分派到 CU（Compute Unit），在 CU 内按 SIMD 单元组织、由 SQ（Sequencer）在多个就绪 wavefront 间选择发射；wavefront 内分支分歧传统上靠 EXEC mask（执行掩码）屏蔽非活跃 lane 并逐路径串行执行，分歧状态以 wavefront 为粒度隐式维护，并不存在跨路径并行的树形节点结构——本专利所述"叶节点并行 + 掩码互斥 + 显式树收敛"正是 NVIDIA SIMT 侧对 divergence 管理的差异化硬件方案，可视为后来"独立线程调度"类特性的早期专利化形态（此为分析者推断）。

## 7. 评价与启示

**技术重要性**：
- 把传统 CRS 的隐式 push-pop 栈**显式化**为 TDT 中的节点树，使分歧路径成为一等公民（first-class）的可调度对象：每条路径拥有自己的 PC、自己的活跃线程集（warp mask）与独立的可调度状态（VA/Token），从而让分歧路径**并行**而非串行执行；
- 直接消解背景中所述 barrier/spinlock 死锁类语义问题——文本称由此可获得更可靠的程序前向推进（forward progress），且原本无法在常规 SIMT 下正确实现的算法可被翻译为确定性执行的机器指令；
- 成本设计精巧：节点恒为 16 字节、"equivalent to a CRS stack entry"，即树节点的存储开销与传统 CRS 栈项持平；线程归属信息通过 WMT/WDT 共享而非每节点复制掩码（文本给出 5 vs 6、4096/表 vs 4096/节点的对比）；
- 对 WDU→SM 链路而言，本专利补全了"SM 侧如何消化 WDU 送来的 warp"这一环：接收（WMT 登记）、分组（WIA+掩码）、调度（叶节点并发/剪枝/收敛）全部由 SM 硬件闭环。

**局限性（基于专利文本可推断）**：
- 关键规模参数为固定值：每 warp 最多 64 节点（quad 模式 256）、节点最多 8 个 warp 槽位、WDT 上限 64×64=4096 掩码；深度嵌套分歧的溢出处理文本未述及；
- 叶节点调度仅表述为 "any technically feasible fashion"，未给出具体仲裁/公平性策略；TDT/WMT/WDT 的物理实现（片上 SRAM 还是 PP memory）文本亦未明确；
- 提取文本存在多处附图标记笔误/冲突：如 "SM 420"、"SM 520"、"WMT 310/620"、"WIA 570"、步骤 816 处 "parent nodes 550" 等，均应以说明书上下文确定的 310/500/530/610 为准；另有 "a valid/active 516 value"（应为 512）等小误；
- 节点树以 CTA 为行组织，跨 CTA 的分歧协同（如 grid 级同步）不在本专利范围内。

**启示**：本专利是理解 NVIDIA SIMT 执行模型从"warp 级单 PC"向"线程级多路径并行"演进的关键文献，其树形节点 + 共享掩码表的设计为后续架构中独立线程调度、per-thread 并发等特性提供了硬件组织基础；与 AMD 侧 EXEC mask + wavefront 串行分歧路线对照，可清晰看到两家在 divergence 管理上"显式树并行" vs "掩码串行"的两条技术路线分野。
