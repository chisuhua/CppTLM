首页摘要（Abstract）要点：SPI 从 thread group 向 shader engine 提供 work items；CP 基于 thread group 尺寸与 shader engine 内 cache 的 cache line 格式选择性分发，tile mode 下以对应 cache line 格式的多维 block 调度；cache line 格式可由 texture surface format 与 swizzle mode 决定；SPI（或对应 driver）基于 thread group 尺寸、UAV surface format 自适应选择 wave size、tile size、wave walk mode 并据此 launch/调度 waves，以改善 cache 局部性、减少内存访问并优化地址模式（与独立权利要求 1/10 对应）。

## 2. 发明背景与待解决问题

**应用场景**：分层执行模型把 3D workgroup grid 划分为 thread group（workgroup），每个 thread group 含一个或多个 wavefront，wavefront 含一个或多个 thread（work item）。硬件层级为 SIMD unit ⊂ compute unit (CU) ⊂ workgroup processor (WGP) ⊂ shader array  shader engine。command processor (CP) 把 compute dispatch request 分解为有序的 thread group 请求序列，以 round-robin 分发给各 shader processor input (SPI)，SPI 再把 wave 分发到 shader engine 内的 SIMD；display mode 下 SPI 通过 unroll 线程 3D 索引顺序扫描 thread group。

**待解决问题**（说明书 "Detailed Description" 开篇列出）：

1. **负载均衡式均分与负载不匹配**：CP 与 SPI 按 load-balancing 把 thread group 均匀散布到所有 CU，即使 workload 很小；不同 CU 使用不同 cache，导致 cache locality 差、cache thrashing；小负载本可在一个/少数 CU 上无性能损失地执行，但均分使 power management 算法无法关闭多余 CU，浪费功耗。
2. **1D wave 几何与 2D/3D cache line 格式失配**：SPI 按序 walk 线程索引，wave 是 1D 线程集合（如 32×1 行），而 texture cache 的 cache line 按 swizzle mode 存为 2D/3D 格式（如 4×4）；wave 只用到 cache line 中一部分像素，产生 partial write（部分写）——需整行读回、修改、整行写回，带来大量内存带宽开销与延迟。FIG. 4 进一步显示 compressed partial write 400 在 TCP 405 → GL1 410 → GL2/CM 415 → EA 420 → DF 425 → UMC/DRAM 430 链路上引发多次压缩/解压缩数据交换，放大了该浪费；uncompressed partial write 401 开销较低但仍是无谓带宽与功耗。

**核心方案一句话**：command processor 依据 thread group 尺寸与 shader engine 内 cache 的 cache line 格式（由 texture surface format + swizzle mode 决定）选择性地把 work items 以匹配 cache line 格式的多维 thread group block 分发给 SPI（tile mode），SPI/驱动侧再自适应选择 wave size、tile size 与 wave walk mode，从而提升 cache 局部性、消除 partial write，并允许把空闲 shader engine 置入低功率模式。

### 3.2 关键机制详解

**自适应分发的依据**：两级输入。(1) CP 侧：thread group size / grid size（TGx,TGy,TGz 与 Tx,Ty,Tz）+ cache line 格式；cache line 格式由 texture surface format（BPP：16/32/64/96/128 BPP 等）与 swizzle mode（S/D/R、S3/D3）导出，如 128B cache line、32 BPP、swizzle R → 4×8 排布（Table 3 给出 BPP/swizzle → 128B shape (X×Y×Z) → 像素数的完整映射）。(2) SPI 侧：wave controller 730 依据 thread group size 与 UAV surface resource descriptor 自适应选择 wave size（Wave16/32/48/64 等）、tile size（tile 完全覆盖一个 wave，使 wave 的读写请求完全覆盖一条 cache line）与 wave walk mode。

**索引生成（FIG. 5 对应）**：SPI 为每个 thread（work item 505）生成索引并组 wave，索引生成算法按 X→Y→Z 的重复递增模式 unroll 各维度（各分量达到指定尺寸后进位）；部分实施例中 SPI 以 round-robin 方式选择 work item 索引。该顺序 walk 正是"1D wave vs 2D/3D cache line"失配的根源，也是 tile/Morton walk 所要替换的对象。

**分发策略如何切换**：(a) thread group controller 715 执行 method 800：TG size < 阈值（示例 256 或 1024 线程）→ block size = 1×1（815）；否则 TG block size = ROUND(阈值/TG size)（820），再查 LUT 830 选出 block shape（FIG. 9）。(b) compute dispatch 720 以 thread group walk mode（display / tile）扫描 grid；tile mode 下把连续索引线程组成 2×2 等多维 block（如 FIG. 10 的 1001），把多个小 thread group pack 进一个 thread group block 作为 dispatch 基本单元，发往同一 SPI、同一 CU 子集（如 SPI 310 只调度到 CU 330/331），其余 CU（332–337）置低功率模式；仍可用 round-robin 在 SPI 间分配。(c) SPI 侧 wave launch/scheduling 735 在三种 wave walk mode 间切换：display mode（行优先线性，FIG. 10-1000）、tile mode（2×2 tile 顺序排列，FIG. 12-1200：tile 集 0= tiles 0–3、1= 4–7、2= 16–19、3= 20–23）、Morton mode（Z 序，FIG. 13-1300：tile 集 0=0–3、1=4–7、2=8–11、3=12–15）。(d) Table 1（TG 32×32）与 Table 2（TG 8×8）给出策略切换表：如 32×32 时 wave walk 用 Tile、tile size 随 BPP 取 8×8 或 16×4/8×8；8×8 时 thread group walk 用 Tile 2×2（8 BPP 为 Tile 2×2/2×4）、wave walk 用 Display、tile size 8×8 或 8×8/8×4。SPI 725 分发时还依据目的 SIMD 的资源可用性（register files、local data share (LDS) memory、wave resource lots）。

**对 wavefront 占用率的影响**：原文未直接使用 "occupancy" 一词，但机制直接作用于占用率管理——(a) wave size 自适应（Wave16–64）改变每 CU 可并发驻留 wavefront 数；(b) 小 batch 聚集到 CU 子集（330/331）使这些 CU 的 wave 占用集中、cache 复用提高，其余 CU 可 power-gate；(c) SPI 按 register file / LDS / wave resource lots 可用性分发，即把占用率约束前移到分发级。（据视觉阅读的归纳，原文未量化。）

**效果示例**：FIG. 6 中 32×1 的 wave 611 映射到 8 条 4×4 cache line 620 且每条只用 4×1 → 大量 partial write；FIG. 11 改为 4×8 的 wave 1105–1108 后，每 wave 恰好完全覆盖两条 cache line（1110/1111 等），partial write 被减少或消除。

## 4. 权利要求摘要

共 20 项权利要求，3 项独立权利要求（claim 1 装置、claim 10 方法、claim 19 方法）。

**独立权利要求 1（装置）**：一种装置，包含：至少一个 scheduler circuit（即 SPI），配置为调度并启动 thread group 中的 work items 以在至少一个 shader engine 上执行；以及 command processor，配置为基于 thread group 的尺寸（对应于 shader engine 内 cache 的 cache line 格式）选择性地把 work items 分发给该 scheduler circuit，其中 cache line 格式与 texture access pattern 相关联。

**独立权利要求 10（方法）**：从 command processor 基于 thread group 尺寸（对应 cache line 格式、且格式关联 texture access pattern）选择性分发 work items 到至少一个 scheduler circuit；并由该 scheduler circuit 调度 work items 在 shader engine 上执行。

**独立权利要求 19（方法）**：command processor 把具有连续索引的 work items 加入对应于 cache line 格式的多维 block；把多维 block 中的 work items 分发给 scheduler circuit；scheduler circuit 把含这些 work items 的 thread group launch 到 shader engine 执行。

从属权利要求按主题分组：

- **tile mode 与块几何**（2、3 / 11、12）：CP 工作于 display mode 或 tile mode；cache line 为 m×n 二维格式时以 k×l 二维 block 调度（m 为 k 的整数倍、n 为 l 的整数倍）；
- **surface format / swizzle 驱动**（4、5 / 13、14 / 20）：cache line 格式由 texture surface format 与 swizzle mode 决定；CP 或 GPU driver 据此确定 wave size 与 tile mode，并据此把 work items 分组为 thread group blocks；
- **连续索引归同一 scheduler**（6 / 15）：把连续索引 work items 加入 thread group block 并提供给同一 scheduler circuit（保 cache 局部性）；
- **小批量聚集 + 低功率**（7、8 / 16、17）：work items 数小于阈值的 batch 聚入提供给同一 scheduler circuit 的 thread group blocks、仅在 shader engine 子集上调度；子集外 shader engine 置低功率模式；
- **SPI 侧自适应**（9 / 18）：scheduler circuit 基于 thread group size 与 texture surface format 自适应选择 wave size、tile size、wave walk mode，并据此自适应 launch/调度 thread group 内的 waves。

## 5. 与专题主题的关系

本专利属于专题「AMD GPU 前端全链路（CP/IB/PM4 + doorbell/HQD + SPI/SQ wave 分发）」，与 NVIDIA TMU 上游模块研究对照。

**(a) 在 AMD 前端链路中的位置**：本专利落在前端链路最下游、紧邻 CU 执行阵列的 SPI/SQ wave 分发环节。链路为 CP 305/710（compute dispatch 720，做 thread group block 化与 tile/display walk）→ SPI 310/311/725（thread group block → CU 分发，round-robin + 资源可用性判定）→ wave launch and scheduling 735（SQ 功能级）→ SIMD 740/CU 330–345。与专题内上游专利（CP 侧 IB/PM4 命令处理、HQD/doorbell 队列接入）相比，本专利把"分发几何"（block shape、tile size、wave walk mode）的决策权显式拆分到 CP 与 SPI 两级，并以 cache line 格式（texture surface format + swizzle）作为决策输入，是前端链路中"几何感知分发"的权利要求化表达。

**(b) 与 NVIDIA 的对应关系**：AMD 的 SPI/SQ 分发对应 NVIDIA 的 TMU 234 + WDU 236 两级——TMU 负责任务就绪与优先级、WDU 负责把 CTA 分发到 SM。本专利的"自适应线程组分发"可对照本库 13_Work_Distribution_Unit 专题中的 WDU 按 SM 容量/比例分发专利（US9594599B1、US9710306B2、US10332310B2 等按容量分发/自动节流机制）：两者都依据下游执行单元的容量/状态调整 thread group（CTA）的分布密度；差异在于 NVIDIA 侧侧重 SM 间吞吐与节流，AMD 侧侧重 cache line 几何匹配、partial write 消除与 shader engine 级 power gating。

## 7. 评价与启示

**技术重要性**：本专利是 AMD 上海团队对 RDNA/CDNA 世代前端 wave 分发机制的权利要求化描述，把"dispatch 几何 – cache line 几何 – 功耗管理"三个杠杆统一在 CP+SPI 两级自适应框架下：tile/Morton walk 本质是 swizzle-aware 的硬件化 dispatch，与 NVIDIA 在 TMU/WDU 上做容量感知分发形成路线对照；小 batch 聚集 + 子集外 shader engine 低功率的写法，把 power gating 与分发策略直接绑定，是前端专利中少见的"功耗-几何"联合权利要求。

**局限性**：自适应规则主要靠静态映射表（Table 1–3、LUT 830）与驱动预配置，缺乏基于运行时 cache miss/命中反馈的闭环调节；阈值 256/1024、block 形状等仅为示例值；小 batch 聚集到少数 CU 可能在时延敏感场景造成热点，文本未讨论；cache 命中率/带宽收益无量化数据；个别图号疑误（FIG. 2 中 VGPR 与 CACHE 同标 207；正文 "triangle 203" 应为 211；FIG. 10 之 1000 部分格内数字扫描/印刷不清）。

**对理解 AMD SPI/SQ 分发与 wave 占用率管理的价值**：本专利明确了分工——CP 决定 thread group block 的几何与跨 SPI 分布，SPI 决定 wave size/wave walk 并依据 register file、LDS、wave resource lots 的可用性把 wave launch 到 SIMD；这正是 occupancy 管理在分发级的具体形态：wave size 与 tile 选择同时约束了 cache line 利用率与每 CU 并发 wavefront 数，为解读 AMD 开源内核驱动中 SPI/SQ 寄存器配置（wave size、thread group dimensioning、swizzle mode）提供了专利层面的设计依据。
