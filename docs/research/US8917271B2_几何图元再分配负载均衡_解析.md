## 2. 发明背景与待解决问题

**应用场景**：图形管线中 tessellation shader（细分着色器）与 geometry shader（几何着色器）在执行时会在 GPU 内部生成几何图元（internally generated primitives，几何图元/geometry primitives）。本专利针对 surface patch（表面面片）经 hull shader（壳着色器，即 tessellation control shader，细分控制着色器）产生 tessellation data（细分数据，含 LOD 值）后，由 domain shader（域着色器，即 tessellation evaluation shader，细分求值着色器）逐顶点处理的过程。

**待解决问题**（按文本表述）：

1. 早期图形系统采用 single pass（单遍）方案：多条图形管线（graphics pipeline）并行处理图元，但内部生成的图元一直停留在同一条管线内直至光栅化步骤；
2. tessellation/geometry shader 产生的图元数量高度可变且可能巨大（例如按高 level-of-detail（LOD，细节层次）把一个表面细分为大量小图元），这种工作量的膨胀（expansion of work）若在单级内处理，会因资源限制导致多条图形管线串行化（serialization），降低性能；
3. 即使资源限制未造成串行化，不同管线间工作量的差异也会使整体性能退化到最慢管线的水平（reduce performance to that of the slowest graphics pipeline）。

**本专利目标**：提供一种在多条图形管线之间均衡 tessellation 与 geometry shader 所生成图元的处理负载的系统与方法。

### 3.2 关键机制详解

**Alpha/Beta 两级划分**：为均衡 hull shader 把面片膨胀为不定量图元带来的负载，SPM 310 被划分为两个不相交集合——Alpha 与 Beta。Stage 1（Alpha 级）由 Alpha SPM 执行 vertex shader 与 tessellation control shader（hull shader），处理面片批次、生成工作单元 task；Stage 2（Beta 级）由 Beta SPM 执行 tessellation evaluation shader（domain shader）与 geometry shader，做逐顶点处理。两级在不同 SPM 上并发运行；Alpha/Beta 的 SPM 数量可以相等、也可以不等，可按处负载裁剪（tailored）——由于一个 Alpha SPM 执行 tessellation control shader 可能产生数据膨胀，它可为多个 Beta SPM 生成工作。

**TGA 任务切分（资源受限批量化）**：每个 SPM 310 内的 **TGA 510** 单元把生成的几何图元切成更小的批次 task 以便再分配；每个 task 代表 M 个（细分后）顶点，单个表面可产生多个 task；task 尺寸按 SPM 310 的并行处理能力与资源限制确定，保证每个顶点由线程组中一个线程处理，从而不超过资源上限、避免停顿与串行化。切分依据是 hull shader 输出的 LOD 值（FIG. 5A：表面 500 分为外部区域 501–504 与内部区域 505，各关联不同 LOD 值；LOD 越高，产生的顶点与图元越多）。

**跨 GPC 再分配路径**：Work Distribution Crossbar 330 把第一组 SPM 550（Alpha）中的每个 SPM 连接到第二组 SPM 560（Beta）中的每个 SPM；一个 task 可被分发到与产生它的 Alpha SPM 位于**不同 GPC 208** 的 Beta SPM——即经 Work Distribution Crossbar 330 与 Crossbar Unit 210、通过 TDU 207 实现跨 GPC 再分配。几何图元与细分参数经 L2 Cache 350 中的 alpha circular buffer（存于 CBE 358）与 Work Distribution Crossbar 330 从 Alpha 路由到 Beta。

**TDU 收集与 API 顺序重排**：TDU 207（collector block）接收任务，并可借助其他单元把任务重排 API order（应用程序提交表面时的原始顺序）：先由某单元对每个 Alpha SPM 输出的任务做局部重排，再由 TDU 207 对各 GPC 输出的任务做全局重排；例如当 WDU 200 以 round-robin（轮询）方式分发面片时，TDU 207 把已成 task 的面片恢复到轮询分发之前的顺序。Pipeline Manager 305 向 TDU 207 提供 API 顺序信息，WDU 200 也直接向 TDU 207 发送信息。

**数据驻留策略（L1/L2 而非片外）**：Surface Data 555（面片数据）存于 L1 Cache 320 由第一组 550 读取（位置由 Pipeline Manager 305 提供）；Tessellation Data 570 由 Alpha SPM 写入 L2 Cache 350 的 CBE 358，再由 Beta SPM 从 CBE 取回存入 L1 Cache 320——重要的是细分数据驻留在 L1/L2 而非 PP Memory 204（片外存储），减少读写时钟周期。一个 Alpha SPM 可为单个面片写一个 CBE 358，该 CBE 可被多个 Beta SPM 读取；task 用 task-specific start and end values（任务专属起止值，对应 CBE 内的偏移/位置）定义，每个 Beta SPM 据此只读写处理 CBE 的相应部分（提取文本此处一处误作 "CBE 348"，应为 358）。

**图元实例化**：当 geometry shader 使用 primitive instancing 时，TGA 510 只需复制（duplicate）一个或多个 task 即可实例化生成的图元（FIG. 6B 步骤 620 判定 instancing? → 625 复制任务），实例化工作同样分摊到第二组 SPM 560。

**方法流程（FIG. 6A）**：605 第一组 SPM 执行 hull shader 产生细分数据 → 610 TGA 510 生成任务 → 615 细分数据写入 CBE 358 → 655 把任务再分配到第二组 SPM → 660 TDU 207 按 API 顺序全局重排任务 → 665 Beta SPM 从 CBE 读取细分数据（到 L1）→ 670 对每个任务执行 domain shader 产生输出顶点 → 675 几何着色、光栅化与像素着色 → 680 存储图像像素。由于各顶点对应步骤在不同时刻完成，Beta 级在 Alpha 级持续输出的同时即开始执行（流水并行）。

**动态重配置与过渡协议**：Device Driver 103 配置第一/第二组并下载 hull/domain shader。当 SPM 从 Beta 重部署为 Alpha 时，由 Pipeline Manager 305 以 WDU 200 生成的 alpha SPM mask 与 TDU 207 生成的 beta SPM mask 协调过渡；在 API 顺序中位于某 alpha 工作之前的所有 beta 工作被 TDU 启动完毕前，新的 alpha 工作绝不分配给该 SPM，随后 TDU 向 SPM 发 transition signal（过渡信号）。反向（Alpha→Beta）由 Pipeline Manager 305 停发工作并发过渡信号，TDU 随后开始向其发 Beta 工作。单 SPM 系统则时间复用（alpha/beta 模式切换），需保证各模式输出足够小以免死锁，且重部署开销引入隐含串行化；一种实施例用多个 SPM timeslice（时间片）交替充当 Alpha/Beta。

**独立权利要求 13（存储介质）**：与 claim 1 实质相同的步骤，载体为非暂态计算机可读存储介质。

从属权利要求按主题分组：

- 数据驻留路径（claim 2、3、4 / 18、19、20）：细分数据存于第一组写入、第二组读取的 L1 cache；生成任务时把数据从 L1 拷入 L2 中的 circular buffer entry；分发任务时再从 CBE 拷回 L1；
- API 顺序重排（claim 5 / 14 / 21）：分发任务后把任务重排为面片被接收处理的 API 顺序；
- 图元实例化（claim 6 / 15 / 22）：生成任务包括复制任务以产生所生成几何图元的多个实例；
- 任务定义（claim 7 / 16 / 23）：任务由对应面片部分细分数据的起止值定义，第二组各 SPM 处理该部分；

- 集合划分策略（claim 9、10、11、12）：基于处理负载决定哪些 SPM 属第一/第二组；两组互斥；第一 SPM 产生的工作可分发到第二组的多个 SPM；第二 SPM 执行 domain shader 的同时第一 SPM 并发执行 hull shader。

## 5. 与专题主题（WDU→SM 与 SPI→SQ）的关系

**在 NVIDIA「WDU→Work Distribution Crossbar→GPC→SM」链路中的位置**：本专利恰好覆盖了该链路上的**动态再平衡环节**。链路的正向首段是 WDU 200 从 Front End 212 接收批次并把 surface patch 经 Work Distribution Crossbar 330 分发到各 GPC 208 的 SPM 310（第一级、静态意义的工作分发）；但 hull/geometry shader 执行后工作量发生不可预知的膨胀，原有分发不再均衡。本专利的方案是在链路的同一组分发设施上叠加第二级动态分发：TGA 510 把膨胀后的几何图元切成资源受限的 task，TDU 207 作为 collector block 收集这些 task，再经 Work Distribution Crossbar 330 与 Crossbar Unit 210 **在多个 GPC 之间再分配**给 Beta SPM 处理。因此它属于 WDU/crossbar 向 GPC 分发工作的动态再平衡机制——分发单元（WDU/TDU）、互连（两级 crossbar）不变，被分发的对象从「输入面片批次」变为「生成的几何图元任务」，并附加 API 顺序重排保证语义正确。

**与 compute CTA 分发的同构性**：虽以图形 tessellation 管线为语境，本专利的负载均衡思想与 compute 域 WDU 向 GPC/SM 分发 CTA 同构：(1) task 相当于图形语境的 CTA——尺寸按 SPM 资源限制确定（如同 CTA 尺寸受寄存器/共享内存约束），"每个顶点一个线程、每线程组处理一个 task" 对应 CTA 的线程组织；(2) TDU 207 的跨 GPC 再分配相当于 WDU 把工作动态摊给负载较轻的 GPC/SM；(3) Alpha/Beta SPM 数量的负载裁剪与动态重部署，正是后来 GPU 在图形/计算工作间弹性调度执行资源的雏形。与同目录 US8112614B2（CTA 并行数据处理）对照可见：前者确立了 CTA→SM 的静态分发框架，本专利则补上了「工作生成后再分配」的动态一环。

**AMD 侧对应**：AMD 链路中对应职责由 SPI（Shader Processor Input，着色器处理器输入）承担——把 workgroup（工作组，CTA 的 AMD 等价物）分发到 shader engine（着色器引擎）内的 CU（compute unit）并做负载均衡，如本目录 US20230206382A1（Dynamic Dispatch for Workgroup Distribution）：command processor 的 dispatch controller 基于各 shader engine 经 SPI 上报的可用资源指示（active CU 数量、进度、可用槽位）动态指派 workgroup。差异在于触发方式：NVIDIA 本专利的再平衡由**工作膨胀**（tessellation/geometry 生成图元）这一图形特有事件驱动、经 TDU/crossbar 硬件闭环完成；AMD 该专利的再平衡由**运行时资源遥测**驱动、以 CP→SPI 上报回路完成。两者共同印证「分发层必须支持生成后/运行时的再均衡」这一共识。

## 7. 评价与启示

**技术重要性**：

- 精准命中 tessellation/geometry shader 的结构性问题——工作膨胀的不可预知性使任何静态分发失效，整体性能退化到最慢管线；本专利以"收集→切小→摊匀"的再分配闭环直接消除该瓶颈；
- 两级 Alpha/Beta 划分使 hull 与 domain 处理在不同 SPM 上并发流水，且两组规模可按负载裁剪，是"同一硬件池内按比例划分流水级"的弹性设计；
- task 尺寸与 SPM 资源限制挂钩（每顶点一线程），把"不超过资源上限"作为任务生成的硬约束，从根源避免串行化；
- API 顺序重排（局部重排 + TDU 全局重排）在乱序并行执行之上恢复提交顺序，保证图形语义正确，是"乱序执行、顺序退休"思想在工作分发层的体现；
- 细分数据经 L1→CBE(L2)→L1 的片上驻留路径规避片外存储往返，CBE 的 "evict last" 黏滞策略保证其在 L2 中的驻留；
- 过渡协议（alpha/beta SPM mask、"先清旧 beta 再入新 alpha" 的顺序约束、transition signal）使 Alpha/Beta 配比可在运行时重配置而不破坏顺序语义，为图形/计算工作间的资源弹性切换铺路。

**局限性（基于专利文本可推断）**：

- 文本未给出 TDU 207 选择目标 Beta SPM 的具体负载均衡算法（轮询、最短队列或基于占用率），权利要求亦停留在"分发"层面；
