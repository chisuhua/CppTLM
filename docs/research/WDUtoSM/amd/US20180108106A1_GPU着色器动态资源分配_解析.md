## 2. 发明背景与待解决问题

**应用场景**：GPU 包含多个处理元件，专利称为 shader（着色器），用于执行指令、生成待显示图像。输入的 graphics workload（图形工作负载，一组图形指令，如渲染一帧或帧的一部分）会对不同 shader 提出差异很大的计算需求；shader 可以是 2D 的 pixel shader（像素着色器），也可以是 3D 的 vertex shader（顶点着色器）、geometry shader（几何着色器）、tessellation shader（细分着色器）或其组合，并行执行工作负载所需的操作。

**待解决问题**（Background，[0001]、[0012]）：同一工作负载内各 shader 的任务量不均衡——例如工作负载可能要求 SH1 做大量计算、SH2 只做少量计算，于是 SH1 完成时间远长于 SH2，这种 workload imbalance（负载失衡）会在 GPU 上形成 processing bottleneck（处理瓶颈），损害整体处理效率。

**解决思路**（[0012]）：在各 shader 之间重新分配 supplied voltage（供电电压）、clock frequency（时钟频率）与 memory allocation（内存配额）等资源，使重负载 shader（如 SH1）以更快的速率完成计算，从而降低瓶颈出现的概率或缩短其持续时间。

**二次问题——测量开销**（[0017]）：performance monitor（性能监视器）记录性能信息与 resource allocation module（资源分配模块）生成分配方案本身会消耗功耗、拖慢 GPU 执行速度。因此专利进一步提出：把每个工作负载的资源分配方案连同其 workload identifier（工作负载标识符）存入 memory 140，下次收到相同或相似工作负载时直接套用存档方案，避免重复测量。这是本专利区别于一般动态调压调频方案的关键点。

### 3.2 关键机制详解

**机制一：按工作负载画像（performance profiling）**。performance monitor 102 记录 GPU 各模块（含每个 shader）的性能特征：cache hit rate（缓存命中率）、cache miss rate（缓存缺失率）、instructions or operations per cycle（每周期执行的指令/操作数）、stalls（停顿）等，形成横跨 shaders 150–156 的 performance profile（性能画像）。支持 "per-workload"（按工作负载）模式：driver 110 每次交付新工作负载时，performance monitor 102 复位已存性能信息，保证任一时刻存的都是当前/最近一个工作负载的特征。

**机制二：按需生成分配方案**。resource allocation module 104 基于上述性能信息生成 resource allocation 132，原则是给性能信息显示需求更高的 shader 更多资源：为每个 shader 指定 voltage、clock frequency、memory 资源配额；例如某 shader 产生大量内存访问请求，就分给它更多内存资源。[0008] 还提到可调资源包括 "engine configuration"（引擎配置），但提取文本未展开。三个执行模块分工：
- voltage module 122：给每个 shader 单独提供参考电压，shader 用该参考电压设置其晶体管等组件的阈值电压；各 shader 电压可互不相同；
- clock module 124：给每个 shader 单独供给时钟信号，频率可逐个设定；
- memory allocation module 126：给每个 shader 下发指示其内存配额的参数（地址信息、指针信息等），不同 shader 可分到不同内存资源。

control module 120 向上述三个模块发出控制信号，使资源严格按 resource allocation 132 逐 shader 供给，实现 "individually tailor"（逐一定制），降低负载失衡造成瓶颈的概率或时长。

**机制三：分配方案的缓存与复用**。因测量与计算有开销（[0017]），control module 120 把 resource allocation 连同 workload identifier 存入 memory 140。再次收到带同一标识符的工作负载时，control module 120 直接从 memory 140 取回存档方案并指挥三个资源模块套用，无需重新测量。权利要求 6/10/20 进一步限定该存储器可为 content addressable memory（内容寻址存储器，CAM），即以标识符直接寻址、加速匹配。

**FIG. 2 示例**：control module 收到 GW 212 与 GW identifier 230，确认 memory 中无此标识符，遂要求 resource allocation module 104 生成 resource allocation 232，并把 (230, 232) 存入 memory 240。方案内容示例：SH1 供电 V1（默认电压）、SH2 供电 V2、SH3 供电 V1、SH4 供电 V4；其中 V2 > V1，V4 > V2——即只对重负载 shader 升压。

**FIG. 3 示例**：resource allocation 332 为每个 shader 给出三元组——SH1：V1/CF1/M1；SH2：V2/CF2/M2（原文此处标注 "not shown"）；SH3：V3/CF3/M3；SH4：V4/CF4/M4；且 V1–V4 中至少一个互不相同、CF1–CF4 中至少一个互不相同、M1–M4 中至少一个互不相同，演示三维资源的差异化配置。

**方法流程（FIG. 4，method 400）**：
1. 402：driver 110 交付工作负载及其标识符；
2. 404：control module 120 查 memory 140 中是否已有该标识符对应的存档分配方案；
3. 命中（YES）→ 406：取回存档方案，向 voltage/clock/memory allocation 三模块发控制信号，按方案向 shaders 150–156 供给参考电压、时钟与内存参数 → 410：把工作负载操作发给 shaders 执行（图中标记为 410 "send graphics workload to shaders"；说明书 [0023] 把此步写作 block 408，与图编号不一致）→ 返回 402；
4. 未命中（NO）→ 408：把工作负载操作发给 shaders 执行（图中为 408；说明书 [0024] 把此步写作 block 410，与图编号恰相反），且此时可让三模块向各 shader 供给 substantially equal（基本均等）的资源——相同参考电压、相同时钟频率、相近内存参数；
5. 412：performance monitor 102 记录各 shader 执行该工作负载的性能信息，resource allocation module 104 据此生成旨在减少瓶颈的资源分配方案；
6. 414（说明书 [0024] 写作 "block 411"，与图中 414 不符，疑为原文笔误）：control module 120 接收生成的方案；
7. 416：control module 120 把方案与该工作负载标识符一并存入 memory 140，返回 402。

**原文瑕疵汇总（忠实标注）**：control module 标号 220 vs 120；memory 标号 240 vs 140；resource allocation 标号 432 vs 332；方法框编号 408/410 在说明书与流程图间互换、411 vs 414；[0012] 出现 "shaders 150-160" 而其余处均为 150–156；说明书中电压模块"提供参考电压供 shader 设置晶体管阈值电压"的表述在电路实现上较含混。以上均以说明书正文语义为准。

## 4. 权利要求摘要

共 20 项权利要求，3 项独立权利要求（claim 1 方法、claim 8 方法、claim 13 装置）。

**独立权利要求 1（方法）**：一种方法，包括：为图形引擎（graphics engine）接收到的图形工作负载确定 shader 资源分配；存储该 shader 资源分配；以及在存储之后该图形工作负载再次被图形引擎接收时，套用该 shader 资源分配。

**独立权利要求 8（方法）**：图形引擎接收第一图形工作负载；为其确定第一资源分配；存储之；并在确定分配之后该第一图形工作负载再次被接收时，按所存的第一资源分配来分配资源。

**独立权利要求 13（装置）**：一种设备，包括：配置为接收第一图形工作负载的 control module；配置为为第一图形工作负载生成第一资源分配的 performance monitor（注：说明书中生成方案的是 resource allocation module 104，此处权利要求措辞与说明书分工不一致，原文如此）；存储第一工作负载标识符与第一资源分配的 memory；以及处理该工作负载的多个 shaders；其中 control module 还被配置为在第一资源分配存储后工作负载再次到达时，取回并套用该分配到多个 shader。

从属权利要求按主题分组：

- 分配方案的确定与资源类型（claim 2–5 / 9 / 17、18、19）：确定=确定每个 shader 执行该工作负载所需资源；资源具体为施加给每个 shader 的 voltage（claim 3/17）、clock frequency（claim 4/18）、cache memory allocation / memory（claim 5/19）；claim 9 表述为施加给"一个或多个图形引擎组件"的电压/时钟/内存分配；
- 存储介质（claim 6 / 10 / 20）：存入 content addressable memory（内容寻址存储器）；
- 标识符匹配触发（claim 7 / 11）：存储工作负载标识符，当所存标识符与后收到的工作负载标识符匹配时套用存档分配；
- 多工作负载扩展（claim 12）：对第二图形工作负载重复"确定第二分配→存储→再次收到时套用"的完整流程；
- 装置细化（claim 14–16）：claim 14 增设 resource allocation module 按第一分配向 shaders 分配资源；claim 15 限定 performance monitor 通过测量每个 shader 的处理需求并据此分配资源来生成方案；claim 16 限定 control module 从 memory 取回方案并发送给 resource allocation module。

## 5. 与专题主题（WDU→SM 与 SPI/SQ）的关系

先作忠实声明：本专利提取文本全程使用 shader、control module、resource allocation module 等通用术语，**未显式出现 CP、SPI、SQ、CU 等 GCN 架构部件名**；以下定位是把专利方案映射到 AMD「CP→SPI→SQ→CU」链路的专题分析。

**本专利在链路中的位置**：AMD GCN 的工作分发链路为 CP（Command Processor，命令处理器）解析命令流 → SPI（Shader Processor Input，着色器处理器输入）把 wave（波前）仲裁、分发到各 CU 的 SIMD → SQ（Sequencer，定序器）管理 wave 状态与指令流 → CU（Compute Unit）执行。当图形与计算负载共存时，SPI 正是图形 wave 与 compute wave 争夺 CU 资源的仲裁点，SQ/CU 侧则按 VGPR/SGPR（向量/标量寄存器）、wave slot（波槽）、LDS 等资源的可用性做 wave 准入（admission）。本专利的 control module 120 + resource allocation module 104 + performance monitor 102 构成的"资源分配器"处于该链路的**策略层/准入配置层**：它在工作负载进入 shader 阵列之前，先决定每个 shader（可对应 shader engine/分区粒度）分到多少资源，并把该分配决策固化为按 workload identifier 索引的表。它不直接触碰 SPI/SQ 的逐 wave 准入判定，而是为其上层的资源划分（含 [0008] 提及的 engine configuration）提供"测量一次、存档复用"的弹性分配策略，属于 SPI/SQ 资源准入与弹性分配专题中的**分配策略缓存化**一环。

**图形/计算共存语境**：本专利以 graphics workload 为对象，但其机制与图形/计算混合场景同构——游戏每帧重复下发相同工作负载、或计算任务周期性进入 GPU，都属于"同一标识符反复到达"；此时存档分配表让 GPU 在 graphics 与 compute 工作负载交替进入时，无需重新测量即可在 shader 引擎之间切换既定的资源划分（电压/频率/内存/引擎配置），实现低开销的动态再平衡。

**NVIDIA 侧对应**：NVIDIA 的 SM（Streaming Multiprocessor）/GPC（Graphics Processing Cluster）同样被 graphics 与 compute 共享，资源划分问题域对应：计算与图形在 SM 上分时复用，或经 CUDA MPS（Multi-Process Service）按百分比划分 SM、经 MIG（Multi-Instance GPU）做硬件级实例分区、以及 green context 类的细粒度 SM 分区机制。差异在于：NVIDIA 路径多偏向软件可见的静态/半静态分区或时间片轮转，而本专利主张由片上性能监视器测量、硬件按工作负载标识自动套用，属于测量驱动的负载自适应分配。

## 7. 评价与启示

**技术亮点**：
- "测量一次、存档复用"是本专利的核心贡献：性能画像与分配计算本身有功耗与速度代价（[0017]），以 workload identifier 为键把分配表存入 memory 140（权利要求进一步限定 CAM），使重复性工作负载（典型如逐帧重复的游戏负载）把测量开销摊销到零，思路与驱动层 shader cache 异曲同工，但作用对象是资源划分而非二进制；
- 资源旋钮多维且逐 shader 独立：voltage（功耗域）、clock frequency（时钟域）、memory allocation（容量域）三类正交资源，加上 [0008] 提及的 engine configuration，覆盖了从电源管理到存储划分的弹性空间；FIG. 2/3 的示例（只对重负载 shader 升压、三资源差异化配置）展示了实际配置形态；
- 直接命中负载失衡这一结构性瓶颈：不追求峰值性能，而是缩短最慢 shader 的完成时间以消除瓶颈，是短板效应导向的资源调度。

**局限性（基于提取文本可推断）**：
- 资源粒度粗：全文未涉及 wave/寄存器级准入（VGPR、wave slot、LDS 等 SPI/SQ 关心的执行资源），"shader"是黑盒处理单元，无法直接指导 CU 内部细粒度准入；
- "same or similar workload"（[0007]）的相似度判定未定义，复用完全依赖 driver 提供的标识符，标识符如何生成、粒度是帧/场景/通道均未说明；
- 适用前提强：方案收益依赖工作负载高频重复，对一次性或高度动态的负载（如通用计算）价值有限；
- 逐 shader 独立电压/频率域的物理代价（调压器数量、时钟树复杂度）未讨论；
- 文本内部不一致较多（见 3.1/3.2 标注）， claim 13 把"生成分配"归于 performance monitor、与说明书的 resource allocation module 分工相左；
- 据在线记录，该申请于 2018-12-10 因未答复审查意见而放弃，未获授权；其思想更多以被引文献与后续实践的形式延续。

**启示**：本专利（2016 年申请，GCN/Vega 时代）反映了 AMD 在"负载感知型资源划分"上的早期探索：与 SPI/SQ 的逐 wave 执行层准入互补，它回答的是策略层问题——"每类工作负载该让每个 shader 引擎拿到多少资源"，并用标识符索引的分配缓存把动态分配的开销降下来。把该思路与图形/计算共存场景结合，即可得到现代 GPU 上常见的工作负载自适应分区雏形；对照 NVIDIA 以静态分区（MIG/MPS）与分时复用为主的路线，本专利展示的测量驱动、按负载自动套用的分配范式，为理解两家公司在资源弹性分配上的不同技术取向提供了直接样本。
