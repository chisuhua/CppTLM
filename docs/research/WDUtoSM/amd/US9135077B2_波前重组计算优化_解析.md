## 2. 发明背景与待解决问题

**执行模型**：GPU 等并行处理器以 SIMD（single instruction multiple data，单指令多数据）方式同步执行一组 work-item（工作项，即线程）；一组代码相同、同步执行、由各自处理单元并行处理的 work-item 称为 wavefront（波前）或 warp。一个 SIMD 核可同时驻留多个 wavefront，当 wavefront 内全部 work-item 完成后该 wavefront 才终止。

**待解决问题**：每个 work-item 的完成时间取决于其自身数据所决定的判据，因此同一 wavefront 内的 work-item 会在不同时刻完成。由于所有 work-item 被作为一个 workgroup 整体调度，先完成的 work-item 所占用的处理单元只能空转，等待整个 wavefront 结束——计算单元起始时满负荷，随 pass（工作遍）推进有效处理单元数持续下降。说明书以人脸识别为例：算法对图像各空间区域并行数十遍分析，四五遍之后仅剩极少数候选区域还在处理，绝大多数处理器已无有效工作，但流程必须持续到全部区域判定完毕。FIG. 2 用 16 个处理器举例：第 1 遍后处理器 4、11 完成，第 2 遍仅 14/16 有效，第 3 遍降至 12，到第 7 遍只剩 3 个处理器在干活、13 个空闲。

**需求陈述**（Summary 原文归纳）：需要一种改进的系统与方法，在 work-item 已被分发到多个计算单元之后（after the work-items have been distributed to multiple compute units），优化并行处理计算单元中 work-item 的处理，把原本浪费掉的算力重新利用起来。

**系统级结构（FIG. 1，unified computing system 100）**：CPU 102 与 APD 104（accelerated processing device，加速处理设备——专利采用比 GPU/APU/GPGPU 更宽泛的术语）可同片或分片集成；系统另含 memory 106、operating system 108、communication infrastructure 109、显示控制器 160 与显示设备 162。CPU 侧运行 KMD 110（kernel mode driver，内核态驱动）、SWS 112（software scheduler，软件调度器）与 applications 111；内存 106 中存 command buffers 125、active list 152、PCB 154（process control blocks）。APD 104 侧关键部件：shader core 122（着色器核，即各计算单元/SIMD 处理核的总称，内含标量/向量浮点单元与 ALU）、CP 124（command processor，命令处理器，从 command buffers 125 取命令并协调执行，可为带微码的 RISC 引擎）、DC 126（dispatch controller，派发控制器，用上下文状态启动一组 workgroup 的 kernel 执行，可并入 CP 124 实现）、HWS 128（hardware scheduler，硬件调度器，从 run list 150 选进程，其 run list 管理逻辑亦称 RLC）、preemption and context switch logic 120、graphics memory 130、interrupt generator 146、interrupt controller 148、memory controller 140。系统侧另有 IOMMU 116（含 TLB 118）。wavefront 136 定义为 workgroup 中在同一 SIMD 上同时执行的 work-item 子集，其宽度由计算单元硬件特征决定；execution mask 与 work-item predication（谓词化）支持 wavefront 内分歧控制流；部分填充（partially populated）的 wavefront 也允许在启动时处理。

**计算单元内的队列结构（FIG. 3，work-item load system 300）**：input buffers 310-1/310-2/310-3 各含一个 job（由多个 workgroup 组成，一个 workgroup 的 work-item 作为 wavefront 运行在单个 SIMD 上）；N-depth queues 320 为多级队列，示例为三级 321、323、325，每级 16 个队列，各级分别保存指向各 buffer 中 work-items 312 的指针；shader processors 330 按遍处理：第一遍处理 queue 321 的 work-items 312-1（输出到输出寄存器/缓冲），随后 321 的内容/指针被 323 替换、队列依次递增，第二遍处理 312-2，依此类推。N-depth queues 320 可为实体硬件寄存器，也可为仅含 work-item 指针的虚拟队列。队列控制数据结构含：队头指针、队尾指针、队列条目计数、可选运行统计；work-item 控制数据结构含：指向实际 work-item 的指针、目的地址指针、迭代计数（0 = 就绪待运行；1–n = 已完成迭代数）、状态字（0 = 首次就绪、1 = 再次就绪、−1 = 已完成）。

### 3.2 关键机制详解

**机制一：queued indirect method 与级联回填（FIG. 4，wavefront reforming system 400）**。系统含 input buffers 402、404、406、408（一个大 job 被切分为多个 tile/缓冲区）、shader processors 410、N-depth queues 420（三级 421、423、425，每级 16 个队列）。queue 421-p 表示处理前状态：每个队列均装有 buffer 402 的有效 work-item。经 shader processors 一个 work pass 后，queue 421-4 与 421-11 中的 work-item 完成。系统不再让这些槽位空等到整个 workgroup 结束，而是把尚未处理的 buffer 404 的 work-item 插入 421-4 与 421-11——即把下一缓冲区的 work-item "increment（递增插入）"进当前级的空槽，使下一遍所有处理器都处理有效数据。该搬移在后续各级产生级联效应（cascading effect）：queue 423 中因 work-item 上移产生的空洞由 buffer 406 填补（423-4、423-11），queue 425 的空洞再由 buffer 408 填补（425-4、425-11）。效果等价于把多个部分填充的 wavefront"重组/再成形"为满负荷 wavefront。（注：原文此处一处写作 "shader processors 416"，疑为 410 之笔误；"works items 412 from the various buffers (421, 423, and 425)" 的编号引用亦不一致，以说明书上下文为准。）

**机制二：FSS 总流程（FIG. 5，method 500）**。502 用 work-item 填满所有队列 → 504 执行 X（正整数）个 work passes → 506 检查队列是否全空：未全空 → 508 以 fill/steal/share 方式重分配 → 510 判断是否有队列已满：无满队列 → 512 再做一次 FSS 重分配，最多重复 Y（正整数）次；之后回到 504 继续执行 work passes。若 506 发现所有队列已空 → 514 判断是否还有工作：有则回到 502 重新填队列，无则 518 结束。

**机制三：FSS 细化流程（FIG. 6，method 600）**，分三段：
- **Fill（填充，步骤 602–608）**：604 判断是否还有 work-item 待加载；606 检查是否有队列空（0）或满（1）；若无满队列则 608 执行 distributed work fill（分布式工作填充）——按 FIG. 3 方式逐级填队列，且可选用随机/伪随机、错峰（staggered）/图案化分布、基于队列反馈或其组合的均衡算法（引用同日的 Ser. No. 13/422,405）。有满队列则跳过以免溢出。加载完毕回 602，无新工作则进入 steal 段。
- **Steal（窃取，步骤 610–620）**：610 判断是否有队列 work-item 偏少——统计各队列条目，收集"低于预定量的队列数、空队列数"等统计量，并比较执行 steal 所需时间与完成一个 work-item 任务的平均时间（若窃取耗时大于完成任务耗时则不值得窃取）；612 设定窃取参数 N（待检查的其他队列数），所有队列同时、同方向查看相同的 N 个邻居（如各队列同时向左看 3 个）；614 各队列近乎同时尝试窃取，逐个做相对比较：目标队列相对"高"、本队列相对"低"时，从目标原子地 dequeue 一个 work-item 并 enqueue 到本队列；616 若仍有低队列，618 递增尝试计数，620 判断是否达到最大 N 次尝试，未达则回 614 再试。
- **Share（共享，步骤 622–632）**：622 依统计量（各队列 work-item 的最小/最大/平均值，以及 share 耗时与任务平均完成时间的比较）决定是否启动共享；624 设定待检查队列数 M；626 各队列同时检查 M 个邻居，方向与 steal 对称——本队列相对"高"、目标相对"低"时，原子地把 work-item 从本队列移到目标队列；628 递增共享尝试计数，630 判断是否达最大 M 次，632 结束。

**FSS 设计准则**（原文列举）：每个队列至少保持一个（最好多个）就绪 work-item；目标是把各队列剩余工作量均衡到"均未满"状态以便均匀加载新负载；尽量减少 work-item 搬移次数；各队列逻辑并行运作；新负载以分布式（每队列一个、错峰或随机）方式加载。且 FSS 的 steal/share 不必在每个 work pass 周期之间执行，而是穿插在多个 work pass 周期之间：设定阈值，每 X 个工作遍周期后动用处理器资源做一次 FSS 负载均衡。

**机制四：方法权利要求对应的流程（FIG. 7，method 700）**：702 把 wavefront 的 work-item 分别入队到计算单元的多个队列（每队列关联一个处理器）→ 704 执行多个 work passes → 706 判定哪些队列的剩余 work-item 低于阈值（含 steal/share 成本收益比较）→ 708 把仍有剩余 work-item 的队列中的 work-item 重分配到低于阈值的队列 → 710 执行后续 work pass → 712 重复"判定—重分配—执行"直到所有队列为空。

**扩展应用**：(a) 超大 job 可切分为多个 workgroup 各自独立调度，即把大输入缓冲切成多个 tile（对应 FIG. 4 的 buffers 402–408）；(b) 针对单个 work-item 需要派生新 work-item 的场景：先让每个数据项产生"需新建多少个 work-item"的计数，再用一个串行 pass 为每个 work-item 分配指向已分配内存的指针，随后新 work-item 列表即可像普通新 workgroup 一样调度。

## 4. 权利要求摘要

共 27 项权利要求，3 项独立权利要求（claim 1 方法、claim 19 系统、claim 26 非暂态计算机可读介质）。

**独立权利要求 1（方法）**：一种在加速处理设备中通过 wavefront reforming 实现计算优化的方法：把 wavefront 的多个 work-item 分别入队到 SIMD 计算单元的多个队列中，每个队列对应单元内的一个处理器；对入队的 work-item 执行若干 work pass；在这些 work pass 完成后，把"仍有剩余 work-item 待处理"的队列中的一个或多个 work-item 重分配到"剩余待处理 work-item 数量低于阈值"的列。

**独立权利要求 19（系统）**：APD 中的 wavefront 处理优化系统，包括：含多个并行处理器、处理 wavefront 关联 work-item 的 SIMD compute engine；每个处理器各关联一个队列；以及一个 scheduler（调度器），配置为在若干 work pass 完成后，使"队列剩余量低于阈值"的处理器把其他队列中剩余的 work-item 重分配到低阈值队列。

**独立权利要求 26（介质）**：存储指令的非暂态计算机可读介质，指令执行时实现与 claim 1 相同的方法。

从属权利要求按主题分组：

- **循环终止与结果输出**（claim 2、3、5、6）：重复重分配与后续 work pass 直到所有队列为空；把结果存入内存；把结果送出显示；在显示器上显示结果；
- **work-item 来源**（claim 4）：从应用接收多个 work-item；
- **重分配的发起方与方向**（claim 7、8、11、12、13 及系统侧 21、22、24、25）：由低于阈值的队列对应处理器执行重分配（拉取式）；或由高于阈值的队列对应处理器决定往哪里分配（推送式）；判定哪些队列高于/低于阈值；确定各队列可用空间量并与阈值比较；从剩余量 ≥ 阈值的队列原子 dequeue、enqueue 到低于阈值的队列；从剩余量最多的队列向低阈值队列搬移；
- **次数限制**（claim 10、23）：重分配次数受 redistribution threshold 上限约束；
- **分配模式**（claim 14、15）：以随机/伪随机方式或错峰（staggered）方式把剩余 work-item 指派到低阈值队列；
- **实施载体与负载类型**（claim 16、17、18、27）：方法由 APD 的 compute unit、SIMD 或 shader processor 执行；wavefront 代表每个 work-item 工作量可变的迭代算法；具体应用于人脸/物体识别、视频运动估计或光线跟踪算法；指令可体现为 Verilog 或 RTL 硬件描述语言。

## 5. 与专题主题的关系（CP → SPI → SQ → CU 链路中的位置）

**AMD 前端派发链路中的定位**：本专利 FIG. 1 完整呈现了 AMD 计算派发链的前半段——CP 124（Command Processor）从 command buffers 125 取命令并协调执行，DC 126（Dispatch Controller，"dispatch"被明确定义为使用上下文状态在一组 compute units 上启动一组 workgroups 的 kernel 执行，功能上对应后来 GCN 架构中 SPI（Shader Processor Input）的波前派发/定位职责），HWS 128 从 run list 150 选择进程；work-item 随后经 shader core 122 内各 SIMD 执行。**本专利的创新点不在 CP/SPI 这一"首次派发"层，而在其下游**：work-item 已被分发进计算单元之后，在 CU 内部以"每处理器一队列"的 N-depth queues 承载，由 fill/steal/share 逻辑在执行过程中持续重分配。这一层正属于 SQ（Sequencer，定序器）波前调度与 CU 执行资源利用层：SQ 在 GCN 中管理 wavefront 在四个 SIMD 间的分配、wavefront slot 与发射仲裁；本专利所述"把部分填充的 wavefront 合并/重排成满负荷 wavefront"，本质就是动态维持每个 SIMD 的发射槽利用率。需要如实标注：**专利提取文本中并未出现 "SPI" 与 "SQ" 字样**，上述对应是基于组件功能（dispatch controller ≈ SPI，shader core 内的队列/调度逻辑 ≈ SQ 管辖的波前槽位）的分析性定位。

**要解决的层级问题**：wavefront 是 SIMD 调度的最小粒度，一旦 wavefront 内部分 work-item 提前完成，该 wavefront 占据的发射槽即产生"气泡"，而 workgroup 粒度的静态调度使这些气泡无法被填补。本专利相当于在 SQ/CU 层引入一个运行时的 wavefront 再成形器：阈值判定 + 原子 dequeue/enqueue 使多个稀疏 wavefront 的有效 work-item 汇聚到少数队列，从而把"多个部分填充 wavefront"压缩为"少量满填充 wavefront"，释放出的处理资源用于级联加载下一 tile 的工作。

**NVIDIA 侧对应**：NVIDIA 的对应概念是 warp 级线程打包与 SM 占用率（occupancy）优化。区别在于路线选择：NVIDIA 不在硬件上重排一个 warp 内部的存活线程，而是依靠每个 SM 子分区同时驻留多个 warp、warp scheduler 在 warp 完成或阻塞时零开销切换到其他就绪 warp，用"warp 间交织"而非"warp 内重组"来维持 SIMD lane 利用率；对分支分歧则用谓词/收敛机制处理。因此本专利的 FSS 重分配在 NVIDIA 生态中更多以软件形态出现（如动态并行/软件工作窃取式的负载再平衡），而 AMD 此专利试图把类似工作窃取/共享逻辑下沉到计算单元内部硬件。

## 7. 评价与启示

**技术重要性**：
- 精准刻画了 SIMD 执行的结构性衰减：数据依赖的提前终止使 wavefront 后期利用率塌缩（FIG. 2 示例从 16/16 掉到 3/16），且该浪费发生在 work-item 已分发到计算单元之后，前端调度器无法挽回；
- 提出"队列间接化 + 阈值触发的 fill/steal/share"作为运行时补救：把 wavefront 从静态绑定的执行容器变为可再成形的动态实体，且各队列逻辑并行、原子 dequeue/enqueue，符合硬件可实现性；
