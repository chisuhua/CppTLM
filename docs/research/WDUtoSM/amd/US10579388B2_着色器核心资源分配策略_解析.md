注：本专利标题为"shader resource allocation"（着色器资源分配），但提取正文的主体是多条 compute pipeline（计算流水线）对共享 shader core（着色器核心）的仲裁与上下文切换机制；"资源分配"主要体现在仲裁策略决定哪条流水线/哪个队列的 wavefront（波前）可被分发进入 shader core，且抢占点选在"work group 尚未分配 shader 资源"之前。

## 2. 发明背景与待解决问题

**应用场景**：CPU+GPU（APU/APD）异构计算兴起，GPU 的性价比与能效使其承载越来越多数据并行负载；OpenCL、DirectCompute 等标准 API 把 GPU 用途扩展到图形之外。专利刻意采用 "APD（accelerated processing device，加速处理设备）"一更宽泛术语统摄 GPU/APU/GPGPU。

**待解决问题**（按文本表述）：

1. **向 GPU 派发工作的开销过高**：计算类命令（如 physics、AI）的结果常被 CPU 快速需要，但由于 dispatch 开销高且须排队等待先前命令执行，把这类命令发往 GPU 的延迟往往不可接受，只能改在 CPU 执行，加重 CPU 负担、拖累系统性能。
2. **传统 GPU 不适合系统软件驱动的进程管理**：进程无法被高效识别/抢占（preempt），rogue process（失控进程）可任意长时间占用 GPU 硬件；上下文切换受严重约束——粒度极粗、只能在程序执行的极少数点发生，根因是不支持保存/恢复必要的 architectural 与 microarchitectural 状态；缺乏 precise exception（精确异常）支持使出错作业无法被切出、稍后恢复，故障线程在故障处理期间占着硬件资源空转，降低硬件利用率。
3. **仲裁发生在两个层级**（原文明确）：① GPU compute pipeline 前端"正在驱动哪个作业"；② 共享资源的利用——多任务同时执行时必须决定任务优先级，即"任务到达 dispatch pipeline 头部并驶向 shader core 时如何排定优先级"。

**目标**：提供改进的仲裁方法与系统，在系统存在多条 compute pipeline 时解决仲裁策略（"What is needed ... are improved arbitration methods and systems that resolve arbitration policies where a system has multiple compute pipelines"）。

**APD 内部（FIG. 1B）**：CP 124 含三条流水线 124a/124b/124c——CP input 0（124a）驱动 graphics pipeline 162，CP input 1/2（124b/124c）转发命令至 compute pipeline 160；controller mechanism 166 控制 HWS 128。graphics pipeline 162 含 ordered pipeline 164（VGT 164a 顶点组转换器、PA 164b 图元组装器、SC 164c 扫描转换器）与 SX/RB 176（shader-export/render-back 单元，做深度与颜色计算后写回 graphics memory 130）；DC 166 对来自 CP 124a 的 work-item 组范围计数，其 compute 工作与 graphics pipeline 半同步。compute pipeline 160 含 shader DC 168、170。各 DC（166/168/170）接收输入范围、拆分为 workgroup 并转发给 shader core 122。graphics pipeline 162 为 fixed function，状态难保存/恢复、难以上下文切换，故上下文切换只适用于 compute 工作及 shader core 122 内的图形工作。**shader core 122 被 graphics pipeline 162 与 compute pipeline 160 共享**，是运行 wavefront 的通用处理器。另有 L2 R/W Cache 174。（注：原文中编号 166 同时用于 "controller mechanism" 与 graphics pipeline 的 DC，属原文编号复用/冲突，如实记录。）

**多流水线仲裁结构（FIG. 2/FIG. 3/FIG. 4）**：示例 APD 200 含 8 条 compute pipeline（CS Pipe 0–CS Pipe 7，CS P0–CS P7），向 shader core 122 提供 input 1 与 input 2，多条流水线便于在计算负载间灵活分配资源。**SPI 202（shader input block，着色器输入块）**为 CS P0–CS P7 与 graphics pipeline 204 之间提交 wavefront 提供仲裁方案；**wave dispatcher 206** 以交替方式连接两条 compute pipeline（两条流水线共享一个公共 DC、alternating），把 wavefront 转发至 shader core 208 执行。每条 compute pipeline 对应一个 **HQD（Hardware Queue Descriptor，硬件队列描述符）**：CS P0↔HQD0 … CS P7↔HQD7；每个 HQD 关联 8 个 memory queue：CS P0↔Q0–Q7、CS P1↔Q8–Q15、…、CS P7↔Q56–Q63（共 64 个队列）。每条流水线配 CP 多线程微处理器引擎 **ME 301** 与 grid DC 计数器 **Cntr0–Cntr3**（图中记 "Dispatch Cntr (GRID-TG)"，即 grid/thread group 派发计数器）处理线程组。每个 HQD 可含 **MQDA（Memory Queue Descriptor Address）**，指向 OS 分配的 **MQD（Memory Queue Descriptor，内存队列描述符）**：OS 用 MQD 存储队列的永久状态；硬件据 MQDA 更新 MQD 的选定字段；当 MQD 与 HQD 断开连接时，硬件用 MQD 的一部分在抢占期间临时保存必要的持久数据；其空间子集还可用于 OS 与 HQD 之间的同步协调（此段提取略有错乱，如实标注）。

### 3.2 关键机制详解

**(1) 两级仲裁框架**。仲裁分两级：① 每条 compute pipeline 内部、其 HQD 所辖 8 个队列之间选队列（queue arbitration，FIG. 5）；② 各 pipeline 已选出最高优先级队列后，跨 pipeline 决定哪个 wavefront 提交给 shader core（pipe arbitration）。多输入场景下采用 multilevel scheduling，把相近优先级的作业关联到同一 compute input，在多级优先级队列间控制资源分配。OS 通过编程 HQD 调度 Q0–Q7；任一 HQD 可承载 active queue；同一 pipeline 的队列可为相互独立的进程。**HQD 使 OS 能抢占 active 进程——抢占点选在"使其不再分发任何尚未分配 shader 资源的 work group"处**；被移出硬件的队列可稍后重调度续跑，也可终止。

**(2) 队列内仲裁（FIG. 5）**。步骤 502：每条 compute pipeline 从 HQD0–HQD7 的 8 个队列中选出 ready 队列与 active 队列（各 pipeline 可并行独立选择）。每 wavefront queue packet 的寄存器控制位：1) Queue Active（1 bit）；2) Queue Priority（4 bit，0–15，L→H）；3) Quantum Duration（5 bit，单位 5000 clocks）；4) Quantum Enable（1 bit）；5) Pipe Priority（2 bit）；6) Ready = 队列 active AND（非空 OR dispatch pipe 非空）AND 未 stall。

步骤 504：选中 ready 队列中 queue priority 最高者；选中后保持，直至发生下列六种 context switch 条件之一：1) 更高优先级队列变 ready；2) quantum 已使能且时长超限、且存在同优先级 ready 队列；3) quantum 未使能、当前队列的 wavefront packet 写入其他队列的优先级寄存器、且同优先级另一队列 ready；4) 当前队列的 wavefront packet 自行从 compute pipeline 抢占（pre-empt），调度 smart wait（如等待计时器到期等特定条件）；5) 当前队列与 compute pipeline DC 206 变空、且同 pipeline 另一队列 ready；6) OS 请求当前队列抢占。

步骤 506：compute pipeline 顶部的 queue arbiter 判定有更优队列时，通知相应 CP ME 301 线程在下一 packet 边界停止；否则继续处理（步骤 508）。步骤 510：CP ME 301 执行上下文切换例程，通知 fetcher 停止取当前队列数据、通知 DC 停止为当前队列分发 wavefront，并可保存相应 grid DC Cntr0–Cntr3 的 restart thread group id。步骤 512：切换 pipeline 的当前持久状态存入相应 MQD 的预定义偏移，供队列重启前 state pre-load；可插入 EOP（end of process）fence 事件；若队列在工作仍驻留 shader complex 时被移出硬件，HQD final read address 存入 MQD，底层驱动比较 top of pipe 与 end of pipe 的 final read address，两者一致即所有工作完成。步骤 514：调度保存前一队列状态、丢弃已预取数据；CP ME 释放 fetcher 选下一队列；若下一队列置位 "first time state" 位，fetcher 先插入从 MQD 加载持久状态、再做队列读写指针设置；预期切换耗时约 500 clocks 后 CP ME 开始处理下一队列。

**(3) Quantum 与优先级写让出（FIG. 6 示例）**。pipe 让出的两种主要方式：时间量子到期；写队列优先级寄存器。quantum 使能且超限的队列允许被同优先级既有队列、或同级/更高优先级新到队列抢占；若它是唯一最高优先级队列，则保有 compute pipeline 所有权直到同级/更高级队列 ready。每个优先级级别维护 last queue executed 记分板，回到该级别时处理下一个 ready 队列，若该级别仅一个队列 ready 则恢复执行。pipe 内队列原生顺序 Q0→Q7（复位时 previous queue 置 7）。FIG. 6 以 T<n>（时钟序号）、QA（Queue Active）、QP（Queue Priority）、QE（Quantum Enable）、QD（Quantum Duration）演示 Q0–Q7 的切换、抢占与同级轮换（部分数值 OCR 提取不清）。替代实施例：对队列优先级寄存器的任意写均可触发仲裁事件，便于用户控制"其他队列取得进展前本队列发出的工作量"，并可按 CP ME 设置特权队列。

**(4) 跨流水线仲裁与公平性（FIG. 7）**。各 HQD 内最高优先级队列决出后，下一仲裁点决定最高 pipe priority 的流水线中哪个 wavefront 提交 shader core；由于两条 compute pipeline 以交替方式共享公共 DC，优先级确定后由共享电路决定提交哪条流水线。参与者可为 graphics pipeline、HP3D 任务（LS、HS、ES、GS、VS、PS）与 GFX 任务（LS、HS、ES、GS、VS、PS、CS），以及 8 条 compute pipeline 中的 4 条。compute pipeline 的 pipe priority 分三档：**CS_HIGH（高于 HP3D）、CS_MEDIUM（介于 HP3D 与 GFX 之间）、CS_LOW（低于 GFX）**；叠加后形成 5 级从高到低：CS_HIGH > HP3D > CS_MEDIUM > GFX > CS_LOW。同档 tie-break 用 least recently issued（LRU 类）电路，如 totem pole 电路：某流水线一旦获选向 shader core 发工作，即被移到电路底部（同档中最低优先级），直到同档另一流水线发出 wavefront，以促进同优先级 work group 分发的公平性；复位后初序 P0→P7（pipe 0 初始最受优待）。FIG. 7 表格中 "bold" 表示参与 wavefront launch 考量的流水线、"bold and underlined" 表示最终获选者；Pn 代表提供 wavefront 的流水线，(-) 表示无工作，H/M/L 表示 pipe priority（原文提及"of the 6 pipelines that are competed"，与表中 4 条 bold 的口径关系提取不清）。

## 4. 权利要求摘要

共 20 项权利要求，2 项独立权利要求（claim 1 方法、claim 13 处理器）。

**独立权利要求 1（方法）**：一种在多个进程间仲裁以选择 wavefront 在 shader core 上执行的方法：为第一 compute pipeline 执行工作（该工作对应第一 memory queue descriptor，使用已加载进第一 hardware queue descriptor 的数据执行）；检测 context switch 条件；响应该条件执行 context switch 操作——把第二 memory queue descriptor 的数据加载进第一 hardware queue descriptor；并使用该数据执行第二 memory queue descriptor 对应的工作。核心语义：**上下文切换 = 把新 MQD 数据加载进同一 HQD**。

**独立权利要求 13（处理器）**：处理器含第一 compute pipeline（内含 first queue arbiter）、与之关联的 HQD、以及 shader core；queue arbiter 检测 context switch 条件并执行上述加载第二 MQD 的上下文切换操作；shader core 执行相应工作。

从属权利要求按主题分组：

- **切换条件定义**（claim 2–5 / 14–17）：更高优先级 MQD 变 ready；当前 quantum 时长超限且同优先级 MQD ready；第一 MQD 对应的 dispatch controller 变空且另一 MQD ready；收到 OS 显式抢占请求（OCR 提取为 "pre-empty"，应为 "pre-empt" 之误）；
- **状态保存与恢复**（claim 6、7 / 18、19）：检测第一 MQD 工作未完成并把第一 compute pipeline 状态存入第一 MQD；执行完第二 MQD 后切回第一 MQD，并从第一 MQD 把状态加载回第一 compute pipeline；
- **多队列轮转**（claim 8）：多个 MQD 分配给同一 HQD，以 round-robin 方式轮转执行各 MQD 的工作；
- **多流水线扩展**（claim 9–11 / 20）：第二 compute pipeline + 第二 HQD 执行同样的第三/第四 MQD 上下文切换；经耦合两条流水线的 dispatch controller 择一选择 wavefront 在 shader core 执行；通过对 work-item 组内范围计数来发射 wavefront；
- **图形流水线参与**（claim 12）：从 graphics processing pipeline 向 shader core 发射工作。

## 5. 与专题主题的关系（SPI/SQ 资源准入控制）

本专题目录 "16_WDU_to_SM_and_SPI_SQ" 关注工作分发单元到计算核心的"分发—资源分配—准入"环节。本专利正是 AMD 侧定义该准入层前端策略的基础文献，落在 **CP→SPI→SQ→CU** 链路的 CP 与 shader core 之间：

1. **链路位置**：CP 124（三输入 124a/b/c，含多线程微引擎 ME 301）→ DC 126/166/168/170（把范围拆成 workgroup 并计数，GRID-TG dispatch counter）→ **SPI 202（shader input block，在 8 条 compute pipeline 与 graphics pipeline 间仲裁 wavefront 提交权）** → wave dispatcher 206（两条 pipe 交替共享 DC）→ shader core 122/208（SIMD compute unit 阵列）。图内标签 "Arbitration/Allocation Probes" 表明该块以探针方式向 shader core 发起仲裁/分配请求——即询问并申领可供 wavefront 进入的资源，这正是 SPI 资源准入的前端入口。
2. **与"SPI/SQ 按策略分配资源"的关系**：专利把准入边界明确放在资源分配之前——HQD 使 OS 能在 workgroup "尚未分配任何 shader 资源"时阻止其继续分发；已入核工作则靠 EOP fence 与 final read address 比对自然排空，无需保存细粒度微架构状态。在后续 GCN 架构中（此为公开架构常识对照，非本专利原文），该块定型为 **SPI（Shader Processor Input）**，它与 **SQ（Sequencer）** 协同，把仲裁选出的 wavefront 落到具体 shader engine/CU/SIMD，并为之分配寄存器（VGPR/SGPR）、LDS 与 wave 槽位；若资源不满足，wavefront 即不能被接收/分发。本专利的 queue priority、quantum、pipe priority 与 totem pole 公平规则，是"按什么策略决定分发谁"的策略层；SPI/SQ 的资源清点与准入判定是其执行层。本专利未展开 VGPR/wave 槽位计数细节，如实标注。
3. **NVIDIA 侧对应**：SM 接收 CTA（Cooperative Thread Array，线程块）时存在同类资源准入——GigaThread engine 把 thread block 分发到各 SM，SM 侧准入逻辑核对每线程寄存器×线程数、每块共享内存、warp 槽位/最大驻留 warp 数等资源，满足才接收该 CTA，否则等待资源释放。本专利的"HQD/MQD 队列仲裁 + pipe 优先级 + OS 可抢占"对应 NVIDIA 侧 GigaThread/work distribution 调度与 SM 资源适配判定的组合。差异在于：本专利强调多 compute pipeline 共享一个 shader core 的时间片与优先级仲裁（面向 OS 可见进程与 QoS），NVIDIA 公开机制强调 CTA 粒度的资源适配与 occupancy。

## 7. 评价与启示

**技术重要性**：

- 确立了 AMD 计算前端"queue → pipe → 公平电路"三级策略栈：队列级 4 bit 优先级 + 5 bit quantum（5000 clocks 粒度）、pipe 级 2 bit 优先级且三档（CS_HIGH/CS_MEDIUM/CS_LOW）与 HP3D/GFX 交错，使计算负载可被精确插队在图形负载之上/之间/之下，为 OS 级 QoS 提供硬件基础；
- HQD（片上）/MQD（内存）两级描述符把"快速换入"与"持久状态"解耦：上下文切换即把新 MQD 数据加载进 HQD（约 500 clocks），持久状态按预定义偏移存回 MQD，并借 EOP fence 与 top/end-of-pipe final read address 比对确认排空——这是 compute pipeline 可抢占、可恢复的核心，绕开了 graphics 固定功能流水线无法上下文切换的限制；
- 抢占点前置于"shader 资源分配之前"，以准入控制式语义替代昂贵的微架构状态保存/恢复，直接回应 Background 对传统 GPU"切换粗粒度、无精确异常"的批评；
- quantum 到期与优先级寄存器写两种让出机制，兼顾高优先级低延迟与同级公平；FIG. 7 的 5 级优先表展示了 APU 时代计算/图形共享 shader core 的动态平衡设计。

**局限性（基于专利文本可推断）**：

- 对 SPI 202 / wave dispatcher 206 如何探查 shader core 内部资源（wave 槽位、寄存器、local memory）未给出具体机制，"Arbitration/Allocation Probes" 仅见于图内标签；标题所称 "shader resource allocation" 主要落在队列/流水线准入层，而非 SIMD 内部细粒度资源计数；
- quantum 粒度 5000 clocks、切换开销约 500 clocks，文中未给出对延迟敏感细粒度负载的量化评估；
- 提取文本存在若干瑕疵：166 编号同时用于 controller mechanism 与 graphics DC；claims OCR "pre-empty"（应为 pre-empt）；FIG. 7 描述 "of the 6 pipelines that are competed" 与表中 4 条 bold 口径关系不清；MQD 段落个别句子截断错乱；附图缩略 OCR 噪声大——均以说明书正文为准。

**对理解 AMD GPU 前端架构的价值**：本专利与其母案 13/325,286 一系共同定义了"OS 编程 MQD → HWS/RLC 选进程 → CP ME 执行队列 → HQD 仲裁 → SPI 分发 wavefront 至 shader core"的 AMD 计算前端原型；后续 GCN/RDNA 公开架构中 SPI（Shader Processor Input）+ SQ（Sequencer）的 VGPR/SGPR/LDS/wave 槽位准入机制，可视为本专利所立策略层的执行层细化。与 NVIDIA 侧 GigaThread/SM CTA 准入对照可见两家在"工作分发到计算核心"环节的异同：AMD 强调多进程优先级 QoS 与 OS 可抢占性，NVIDIA 强调 block 粒度的资源适配与 occupancy 控制。
