## 2. 发明背景与待解决问题

**应用场景**：现代处理器（典型为 GPU）支持多个进程并发运行，每个进程又可能启动（launch）多个 kernel（内核函数）。文本定义：kernel 是一段或多条可执行指令，通常以函数形式出现；当其对多个数据元素并行执行时产生多个实例，每个实例称为 thread（线程）；一组线程称为 warp 或 wavefront（波前）。一个 GPU kernel 通常包含多个 wavefront。

**待解决问题**：来自单个或多个进程的多 kernel 并发执行时，会竞争处理器的共享资源，多 kernel 争抢共享资源造成的干扰会降低整体性能。文本进一步强调：不同 kernel 之间的共享资源竞争比同一 kernel 内部更严重——同一 kernel 的 workgroup（工作组）之间尚有共性，而不同 kernel 的 workgroup 是"完全没有共同点（no commonality）的完全不同的实体"。

**现有技术的不足**：说明书 Background 部分仅列出 D1–D5 五篇学术文献作为改进 GPU 资源利用率的相关工作（thread block 调度、active warp 调度器动态缩放、两级 warp 调度、编译期 TwinKernels 执行模型、超额订阅命令队列），未对任何已有硬件调度器结构作具体批评；本专利要填补的是"CU 内面向多 kernel 并发的、能同时缓解资源竞争并保证前向进展（forward progress）的波前调度机制"这一空白（据 [0007]）。

### 3.2 关键机制详解

**机制一：按 kernel 优先级分组的两级调度（FIG. 4、FIG. 5，method 500）**。一级调度器 310 把 wavefront 按所属 kernel 的优先级（priority）分组为 scheduling group（调度组）：同一优先级的所有 kernel 的全部 wavefront 归入同一调度组（即一个调度组可横跨多个 kernel）；随后一级调度器选出优先级最高的调度组。二级调度器 320 只在被选中的调度组内部挑选 wavefront 发射执行，策略可为 round-robin（轮询）、oldest wavefront first（最老波前优先）或其他；同时阻止（prevent）其余调度组的 wavefront 被调度（block 535）。method 500 细节：wavefront 调度器从命令处理器接收多 kernel 的多个 wavefront（505）→ 按同优先级分组（510）→ 选最高优先级调度组（515）→ 判定该组当前周期是否有就绪 wavefront（520）；无就绪波前则改选次高优先级组（525）并回到 520；有则由二级调度器调度执行（530）并阻止其他组（535）。

**机制二：无优先级信息时的退化策略（FIG. 6，method 600）**。若优先级信息不可用或不考慮，一级调度器把来自同一 kernel 的 wavefront 归为同一调度组（每组只含单一 kernel），并选择 oldest kernel（最老内核，即最早启动的 kernel）对应的调度组进行调度，其余组同样被阻止调度（605→610→615→620→625）。

**机制三：基于资源竞争度量的动态节流（FIG. 7，method 700）**。CU 内 control logic 350 监视指示资源利用率的条件——compute unit stall cycles（计算单元停顿周期）、cache miss rates（缓存缺失率）、memory access latency（访存延迟）、link utilization（链路利用率）等，据此生成 resource contention 度量（measure of resource contention）。节流状态机：初始无节流调度（705）→ 监视资源条件（710）→ 若度量超过第一阈值（715 是；阈值可预定义或可编程），把调度队列 330 中优先级最低且尚未被调度的调度组移入 descheduled queue 340，该组在被移回前不得参与调度（720）→ 等待预定时间（725）→ 再次生成度量（730）→ 若仍超第一阈值，把剩余调度组中次低优先级者移入去调度队列（740）并回到 725（逐级加码节流）；若降到第一阈值及以下（735 否），再与第二阈值比较（745）：低于第二阈值则把去调度队列中优先级最高的调度组移回常规调度队列（750）恢复调度；去调度队列为空则回到 705（755），否则回到 725 继续等待观察。由此形成"竞争过高→自低优先级起逐组去调度；竞争回落→自高优先级起逐组恢复"的迟滞（hysteresis）控制，在降低竞争的同时保证前向进展。

**机制四：最上位方法概括（FIG. 8，method 800）**。CU 接收多 kernel 的多个 wavefront（805）→ 至少基于共同准则/属性（criteria or attribute，如 kernel 和/或 priority）将波前分组为多个调度组（810）→ 从中选出一个调度组（815）→ 仅调度该组的波前执行（820）；某组波前执行完毕后可重复 815/820。

**FIG. 4 调度示例**（kernel 优先级 0–5，时间片 t0–t7）：t0 仅 kernel A（优先级 5）运行，独占调度；t1 kernel B、C（优先级 4）与 D（优先级 3）并存，一级调度器选 B+C 组，D 本周不得执行；t2 剩 E、D（均优先级 3），同组调度；t3 E 未完且新到 F、G（优先级 2），E 组优先；t4 H、F、G 同为优先级 2，合为单组调度；t5 H 未完且 J（优先级 1）到达，选 H；t6 I、J 同优先级（1）合并调度；t7 仅 K（优先级 0）运行。该例演示了"同优先级多 kernel 合并为一组组内共享执行、高优先级组压制低优先级组、被压制 kernel 在高优先级组耗尽后获得执行"的行为。

## 4. 权利要求摘要

共 6 项权利要求，2 项独立：claim 1（系统）、claim 4（方法）。

**独立权利要求 1（系统）**：一种系统 200，包括多个 compute unit 255 与耦合其上的 command processor 235（负责向 CU 分派 kernel）；每个 CU 含：执行 wavefront 指令的一个或多个 SIMD 单元 325A-N（wavefront 表示 kernel 的多个实例）；first level scheduler 310、second level scheduler 320、scheduling queue 330、descheduled queue 340 与 control logic。具体配置：CU 从命令处理器接收多 kernel 的多个 wavefront；一级调度器在调度队列中创建多个调度组（含由至少两个 kernel 的波前组成的组，调度组表示所有同优先级 kernel 的波前之集合），选出最高优先级组，判定其当前周期是否有就绪波前，无则改选次高优先级组；二级调度器在该组有就绪波前时从中调度一个波前到某 SIMD 单元执行，并阻止其他组的波前被调度；控制逻辑以 compute unit stall cycles 作为资源利用率条件进行监视、生成第一资源竞争度量，当停顿周期数超过第一阈值时把最低优先级且尚未调度的调度组从调度队列移入去调度队列（该组在被移回前禁止调度），并在移入后等待给定时间、生成第二度量，若第二度量低于第二阈值则把去调度队列中最高优先级调度组移出恢复调度。

**独立权利要求 4（方法）**：与 claim 1 实质对应的方法版本：各 CU 接收来自 command processor 的多 kernel 波前 → 按同优先级分组（组可含至少两个 kernel 的波前）→ 选最高优先级组、无就绪波前则选次高组 → 二级调度器从该组调度波前并阻止其他组 → 监视停顿周期、生成第一竞争度量，超第一阈值时把最低优先级未调度组移入去调度队列 → 等待、生成第二度量、低于第二阈值时移出去调度队列中最高优先级组。

从属权利要求分组：

- 附加监视条件（claim 2 / claim 5）：额外监视 cache miss rates、memory access latency、link utilization 中的至少一项；
- 逐级加码节流（claim 3 / claim 6）：移入最低优先级组后等待给定时间；若第二资源竞争度量仍大于第一阈值，则把次低优先级调度组也移入去调度队列 340。

## 5. 与专题主题（WDU→SM 与 SPI/SQ 链路）的关系

**在 AMD「CP→SPI→SQ→CU」链路中的位置**：本专利的全部机制落在 CU 内的波前调度层，即 SQ（Sequencer，定序器）层。专利文本的抽象表述是"wavefront scheduler 从 command processor 接收多 kernel 的多个 wavefront"（block 505/605），并描述 command processor 235 经 dispatch unit 250 把 kernel 分派到 compute units 255A-N（[0016]）；提取文本未直接点名 SPI（Shader Processor Input）与 SQ 模块，此为专利的抽象化写法。按 AMD GCN/RDNA 公开架构对应：CP（Command Processor）解析命令流后由 SPI 在 CU 上创建 wavefront（SQ_WAVEFRONT 资源分配），真正在每个 CU 内挑选就绪 wavefront 发射给 SIMD 执行的是 SQ 的 wavefront 调度器。本专利正是对该 SQ 调度层的增强：

1. **多内核并发调度**：SQ 波前调度器不再只服务单一 kernel，而是同时持有来自多个 kernel（乃至多进程、经超额订阅命令队列到达）的 wavefront，并以"优先级调度组"为粒度在它们之间仲裁——这是 CU 上多内核并发执行（multi-kernel concurrency）的调度基础；
2. **资源分区/隔离**：通过"每周期仅一个调度组可发射"实现时间维度上的资源分区，降低不同 kernel 波前对 cache、存储链路等共享资源的交叉干扰；descheduled queue 340 则提供组级别的准入控制（admission control），在竞争过激时把低优先级组整体逐出可调度集合；
3. **竞争反馈闭环**：control logic 350 以停顿周期、缓存缺失率、访存延迟、链路利用率等片上可观测信号构造竞争度量，驱动"节流—恢复"迟滞控制，使 SQ 层调度具备运行时自适应性，兼顾干扰抑制与前向进展。

该专利因此是理解"CP/SPI 只负责把 wavefront 灌入 CU、真正的多 kernel 资源仲裁发生在 SQ"这一分工的关键文献；与同目录族内关注 CP→SPI→SQ 分派接口的专利互补——前者管"波前如何进入 CU"，本专利管"波前进入 CU 之后如何被调度"。

**NVIDIA 侧对应**：NVIDIA SM 上同样存在多任务/多 kernel 并发问题，其对应机制包括：同一 SM 上驻留来自不同 context/kernel 的多个 CTA（thread block），由 SM 内 warp scheduler 在多个 warp 间发射，但传统上以 kernel 为粒度串行占用 GPU（context switch 或时间片 time-slicing 切换进程）；为提升利用率，NVIDIA 提供 MPS（Multi-Process Service，软件层把多进程 kernel 合流到同一 context 以共置到 SM 上）实现进程级 kernel 并发。本专利的差异化在于：AMD 把多 kernel 仲裁下沉到每个 CU 的硬件波前调度器内，以优先级调度组+节流队列在硬件层做干扰管理，而 NVIDIA 侧的类似职能更多位于软件/驱动层（MPS）与 SM warp 调度器本身，硬件化的 CU 级"多 kernel 调度组+去调度队列"结构是本专利的识别特征。学术侧的 two-level warp scheduling（引用 D3）与之形似，但本专利的两级划分依据是 kernel 优先级而非 warp 分组粒度。

## 7. 评价与启示

**技术重要性**：
- 直击多 kernel 并发 GPU 的核心矛盾：不同 kernel 的 workgroup 毫无共性，共享资源干扰比同 kernel 内部更严重；在深度学习推理/训练、多租户云 GPU、图形+计算混跑等场景，CU 级多内核调度是提升利用率与 QoS 的必经之路；
- 两级调度把"跨 kernel 的公平/优先级仲裁"与"组内 wavefront 挑选"解耦：一级按优先级选组（可合并同优先级多 kernel，提高调度机会），二级在组内用 round-robin/oldest-first 等简单策略，硬件复杂度可控；
- descheduled queue + 双阈值迟滞控制是亮点：单阈值会造成调度组在临界点反复抖动，第一/第二阈值配合"等待预定时间"形成滞回环，且节流从最低优先级组逐级加码、恢复从最高优先级组开始，天然保护高优先级负载的前向进展；
- 无优先级退化路径（按 kernel 分组 + oldest kernel first）保证了机制在缺少 QoS 信息时的可用性，也暗示优先级可由 host 软件/驱动按进程或队列赋予。

**局限性与可推断问题**：
- 每周期仅允许一个调度组发射波前，属于粗粒度时间分区：若高优先级组波前持续就绪，低优先级组被完全压制，前向进展依赖竞争节流间接保护，文本未描述防饿死的显式机制（如老化 aging）；
- 资源竞争度量仅给出构成要素（停顿周期、缺失率、延迟、链路利用率），未公开具体加权/合成公式与阈值取值，阈值"可预定义或可编程"但未描述编程接口；
- FIG. 4 描述中 t3 时间槽末尾有一处原文笔误（"executed ... during time slot t2"应为 t3）；权利要求中 "control logic (250)" 与说明书 350 的标记冲突如前述；
