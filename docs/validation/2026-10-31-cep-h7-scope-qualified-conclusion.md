## 1. 为什么需要「范围限定声明」(A-2 形态)

Entry #118 的实测结论是「**H7 不可判**」:P-2 / P-3 都达标(5/5),
但**鉴别力自检(A-1)失败** —— workload 集**只含均匀随机**,
而规则 R-B(`h_0 = min(1, C/W)`)**恰恰只对均匀随机最优**
⇒ **分不清**「模型真准」与「规则恰好蒙对」。

⇒ 两条出路:
| # | 路径 | 状态 |
|---|---|---|
| **①** | 让 workload 集含「**规则失效型**」流 ⇒ A-1 鉴别力自检可满足 | ⛔ **被 gem5 v24 阻塞**(见 §4) |
| **②** | 把结论**显式限定**在已覆盖的范围 ⇒ A-2 范围限定声明 | ✅ **本轮采用** |

⚠ **A-2 不是「口头免责」**:它把「结论的适用边界」变成 **verdict 里必须携带的字段**
(`applicability` + `limitation`)⇒ **缺任一 ⇒ FAIL**
⇒ 任何只给「PASS」而不声明范围的产物**不可入库**。

## 2. 本轮实测(A-2 形态下的完整判据)

| 判据 | 内容 | 结果 |

| **P-2a** | A-1 鉴别力自检 / **A-2 范围限定声明** | A-1 ✗(规则失效型流 0/5)⇒ **走 A-2 ✓** |

### 2.1 verdict 携带的范围声明(**强制字段**)

**`applicability`(适用范围)**:
> 均匀随机(uniform-random)访问分布;工作集 W ∈ {4, 8, 16, 32, 128} KiB;
> gem5 classic cache = 16KiB / 2-way / LRU;访问规模 = 1e5 量级;
> 本仓侧命中/未命中延迟常数 = 5 / 50 cycle @ 1GHz

**`limitation`(局限 + 解除条件)**:
> **未覆盖**:非均匀/带热点(非 uniform-random)的访问分布 —— 而规则 R-B
> (`h_0 = min(1, C/W)`)恰恰**只对均匀随机最优** ⇒ 在未覆盖分布上该规则
> **未被证伪** ⇒ 结论**不得**表述为「H7 已验证」。
> ⚠️ **解除限定的前置条件**:需能喂**非均匀离线 trace** 的 gem5 驱动 ——
> gem5 **v25.0.0.0 已重写 `src/proto/protoio.cc`**(改用 `io::FileInputStream` +
> `ReadMessage`,消除 v24 的提前 EOF)⇒ 技术前置**已具备**,待构建。

## 4. ⛔ 解除限定的前置条件 —— gem5 v25 已修(调研结论)

**调研(2026-10-31,GitHub API 实测 `src/proto/protoio.cc`)**:

| 项 | gem5 v24.1.0.0 | gem5 **v25.0.0.0** |
|---|---|---|
| 流实现 | `io::IstreamInputStream`(**零拷贝**) | `io::FileInputStream`(**非零拷贝**) |
| 读单条消息 | `ReadVarint32` + `PushLimit` + `ParseFromCodedStream` | `codeStream->ReadMessage(&msg, limit)`(**整条读**) |
| 总字节限制 | 无显式设置 | `SetTotalBytesLimit(...)` |
| gzip | 不支持 | **支持** |
| ⇒ 提前 EOF | ⛔ 有(实测 1000 条读到 966) | ✅ **根因已消除** |

⇒ **技术前置已具备** ⇒ 只需**构建 v25** 即可用 `createTrace` 喂**非均匀离线 trace**
⇒ **A-1 鉴别力自检可满足** ⇒ **H7 的限定可被解除**。

⚠️ 未做的部分(需后续):v25 的构建(~1.5h + 数 GB)+ `MemCmd` 枚举语义复核
(v25 的枚举可能变动 ⇒ `Packet.cmd` 取值需重新核对)。
