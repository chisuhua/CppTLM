## 二 · 决策依据缺陷(不阻塞,但结论的「理由」站不住)

### F-04 【中高】撤销 `:71` MODIFIES 的理由建立在「flit 路径」上,而 D-11 声明该路径不存在

- `ADR-CEP-19:395`(`:71` 行):「⛔ 不 MODIFIES … 拓扑 B 的 **flit 只产生于 miss / request**(及 snoop / writeback)路径 ⇒ 不冲突」
- `07 号:2162`(①-c):「⛔ **不**宣称 flit 级路径(**仓内不存在** Router+flit 路径)」
- `07 号:2152`(①-b):桥「`src/` 中**零调用点**」

⇒ `:71`(**WHEN 命中 ⇒ net_side 不产生 flit**)不被触发的真实理由是「仓内根本没有 flit 路径」,而不是「flit 只出现在 miss 路径」。当前措辞**预设了一条 D-11 已否定的路径**。结论(`:71` 不动)可能仍正确,但**依据错误**,且会被后续实施者当作「拓扑 B 有 flit 行为」的许可证。

**修法**:追加 SU 把理由改写为「本仓无 flit 数据路径(桥零调用点)⇒ `:71` 在本轮改动下不被触发」。**归属:architect**。

### F-05 【中】D-0 与自己引用的「拓扑准入判据」逻辑不一致,且「协议中立」与「可配发 Snoop」互相拉扯

- 判据(`07 号:2185`,用户逐字):「JSON 拓扑代表真实物理存在的;如果响应者元素是**物理上不存在、只是为了测试而创建** ⇒ 那就**不进** JSON 拓扑」
- 推理(`07 号:2148` / `ADR-CEP-19:414`):「home 在真实系统里**物理存在** ⇒ 它进 JSON 拓扑」
- 但 D-0 对同一模块的定义(`07 号:2148`):「home 应答端的**协议中立替身**(消费 CohIf `Request`/`Writeback`、经**参数化延迟**回 `Completion`、**可配发 `Snoop`**)」

⇒ 判据约束的是「**该元素**是否物理存在」,不是「它扮演的角色是否存在」。一个「替身 + 参数化延迟 + 零协议语义声明」的模块,按判据字面就是「为测试而创建」⇒ 应**不进** JSON。当前推理把「角色的真实性」偷换成「实例的真实性」——这正是审查包 §六.4 第 2 条质疑所指。

且「**协议中立**」与「**可配发 Snoop**」存在实质张力:要决定「哪些读请求触发 snoop」必须知道 CHI 的 op 语义 ⇒ 该模块至少承载**最小协议语义**。文档一边把它放进契约面(`include/tlm/cep/`),一边声明「⛔ 不产生协议语义声明」,口径难以自洽。

**修法(二选一,须显式裁)**:
- (甲)**如实定位为「真实 home 的简化模型」**(如 SLC home slice / 目录切片),承认其承载**最小协议语义**并给出边界,⇒ 进 JSON + 进契约面成立;
- (乙)**如实定位为 testbench 夹具**,⇒ 按判据**不进** JSON 拓扑(拓扑 A 的「全绿」由 `tools/ab_compare.py` baseline 侧承载)。

**归属:architect(用户裁决 D-0 的定位)**。
