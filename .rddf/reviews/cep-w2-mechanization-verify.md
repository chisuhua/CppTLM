## 关键设计（为什么这样切，而不是更省事的做法）

| 设计点 | 取舍 |
|---|---|
| §0.1 的**行文本形态**是契约（形态不符 ⇒ `STRUCTURE-ERROR` 而非跳过） | ⛔ 否则「改一句文案」就能让判据失效（v5 的 S3-6 就是这么漂的） |
| ⛔ **不查 HEAD sha / 实测日期** | 每次 commit 即漂移 ⇒ 会把闸变成噪声源；它们是**人工刷新点**（planner 阶段收口） |
| ⛔ **不查需外部 CLI 的行**（`openspec validate --strict` 的 WARNING 去重计数） | 那不是「枚举」而是「一次 CLI 判定的产物」⇒ 纳入会让闸依赖工具版本语义（P-11 ③）。未覆盖行在输出里**点名**（可审计） |
| W2-b 的**排除窗自身可验证**（尾部快照标记不存在 ⇒ exit 2） | ⛔ 否则「删掉标记行」就能让判据静默失效 —— 这条正是 F-2（`${!arr[@]}` 恒空）教训的机检化 |
| 排除 §0.2 历史节 + §6.3.2/§6.3.3 判据定义面 | 不排 §0.2 ⇒ 假红（旧计数在那里）；不排 §6.3.2 ⇒ 抓到自己（旧串是判据定义） |
| 尾部「v5 实测依据」块按**历史快照**排除 | 其字节/字符误标属 **G-7 / W4-e** 残余 ⇒ ⛔ 本闸不代裁；但**要求该块标记存在**（B3 变异）⇒ 不许删标记消音 |
