## 3. 与 `§0 DoD 7` 的**声明冲突**（C1 必须一并裁）

`§0 DoD 7` 的表后注写：

> 「本表『机器检查落点』= **口径校验**所在位置；**66 条 invariant 的逐条断言统一落 `test/test_cep_canonical_invariants.cc`**」

**实测该文件的实际内容**（13 cases / 687 assertions）全部是**编号体系完备性检查**：

| 检查项 | 性质 |
|---|---|
| 15 组 owner ADR 均已定义 | 编号完备性 |
| 永久跳空编号确实未定义 | 编号完备性 |
| 全仓无未登记 / 无孤儿定义 | 集合完备性 |
| 实际定义数 = 66 | 计数 |
| `07 号 §4` 总表与契约集合相等 / ID 区间列相等 | 跨文档一致性 |
| ID 形态合法 / owner 前缀唯一 | 格式 |
| ADR owner 映射覆盖全部 ID | 映射完备性 |

⇒ **没有一条**验证某 invariant 的**语义**在实现/行为上成立。

**所以**：「逐条断言统一落该文件」这一句**与实现不符** —— 实现是「编号级完备性」，不是「逐条语义断言」。C1 若不裁这一句，B2 的口径永远悬空。

## 4. 三个候选口径（供 C1 选择；成本为量级估计）

| 口径 | 含义 | 当前状态 | 剩余成本 | 风险 |
|---|---|---|---|---|
| **① 编号级** | 66 条**编号**全部被登记且定义、无孤儿 / 无未登记、`07 §4` 与契约集合相等 | **已 100%**（13 cases / 687 assertions 绿） | **0d** | ⛔ **弱**：编号被登记 ≠ 语义被验证；与 §0 DoD 7 那句「逐条断言」字面冲突 |
| **② 组级（15 组 × 落点）** | §0 DoD 7 表的 **15 组**逐组有「机器检查落点」文件，且该文件的测试通过 | **已 100%**（15 组落点全部存在且绿） | **0d** | 中：组内个别 invariant 仍可能只被组级口径覆盖 |
| **③ 判定级（逐条语义）** | 每条 invariant 有**针对其语义**的断言（正控 + 反控） | 29 strong / 8 weak / 29 none（含 ≥5 假阴性 ⇒ 真实缺口 **~20-25 条**） | **2-3d**（每条 0.5-1h × 正反控） | 高：需人工逐条语义映射；可能触发新装置；建议独立 change |

**估算依据**：29 条 none 中已确认假阴性 ≥5 ⇒ 真实缺口上限 ≈24、下限 ≈19；按每条 0.5-1h（含反控）⇒ **10-24h ≈ 1.5-3 天**，与 `Entry #230` 规划的 C2 估时一致。
