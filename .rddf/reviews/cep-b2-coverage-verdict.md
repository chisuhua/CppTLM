## 1. 三个被否的口径（附否决理由）

| 口径 | 否决理由 |
|---|---|
| **① 编号级**（67 编号全登记、无孤儿、`07 §4` 与契约集合相等） | **编号被登记 ≠ 被守**。`test_cep_canonical_invariants.cc` 的 687 assertions 全是编号体系完备性，无一条验证语义 ⇒ 满足它也不满足 B2 的**意图**（「机器在守」） |
| **② 组级**（15 组各有落点文件且测试绿） | 组级绿会**掩盖条级缺口**（例：组 2 的 7 条中若 2 条无载体，组级仍绿）。这正是 B7 已修过的漏洞形态（证据存在 ≠ 结论已登记；计数处须内嵌限定） |
| **③ 纯 grep 判定** | 假阴性已实证 ≥17%（`INV-CEP-15-IC1/IC3` 标题不含完整 id 串；`INV-SC2~6` 的断言在 case 体内）⇒ grep 只能当**线索生成器**，不能当判定工具 |

## 2. 裁决：三子规则

### 规则 A —— **逐条**（不是组级、不是编号级）

66 条实际编号（67 编号位 − `INV-CEP-04-IC4` 永久跳空）**逐条**须有载体；15 组只作**汇报组织**，⛔ 不得作判定粒度。

### 规则 B —— **载体必须有牙**

每条登记的载体须满足其一：

| 档 | 要求 | 适用 |
|---|---|---|
| **(a) 反向 fixture** | 破坏该 invariant ⇒ 断言**变红**（有证据） | 行为类 invariant（推荐） |
| **(b) 结构校验 + 负控** | 锚**落在** Catch2 `REQUIRE/CHECK` 宏或脚本**非零退出路径**上；负控要求：**脚本类载体（组 6/14/15）100% 负控**（可枚举，个位数）；**不可枚举**的载体才抽样，参数钉死为「抽样率 ≥20% + 首末各 1 + 其余随机」，且**每次新增载体后重抽** | 契约/文档类 invariant |

⛔ **不算载体**（死形态）：注释提及、解析器编号表（`cep_adr_parser.hh`）、恒真表达式、无退出码语义的脚本 echo。
⚠️ **同样不算载体**（**活形态但 vacuous** —— 只靠「邻域含断言宏」检不出，须人工审计识别）：
① **活路径上的平凡真断言**（如 `REQUIRE(x.size() >= 0)`）；
② **有真退出语义但条件永真**的 shell 分支（锚在 `exit 1` 上、判定条件恒真）；
③ **从不执行的载体**（被 tag 过滤 / 不在标准 runset 的 case）。
⇒ **残余风险声明**：①②③ 的识别依赖规则 B(a)/(b) 的负控与动作 1 的人工审计，(b) 档**接受较低证据强度**。
依据：**Entry #217 §④ S6**「builder 不得先落 schema 并把校验写成**恒真占位**」+ `scripts/test/cep_gate_selftest.sh` 的变异 fixture 文化。

### 规则 C —— **机器可查的刚性标记**

载体点加刚性标记，**与断言同址共置**：

```
// INV-CARRIER: INV-CEP-09-IC2      （C/C++，紧邻断言）
# INV-CARRIER: INV-CEP-NUM-IC1     （shell，紧邻退出码判定）
```

映射表（`test/cep_invariant_assertion_map.json`）由标记**生成**（派生视图），**不是**口径源 ⇒ 避免成为第 5 处手写口径源。
ctest 闸校验四项：① 每条 id ≥1 项 ② 标记存在 ③ 标记**邻域 `±8` 行**内含 C/C++ 断言宏（`REQUIRE` / `CHECK` / `static_assert`）**或** shell 非零退出式（正则 `exit\s+[1-9]` / `return\s+[1-9]`）④ 标记 id 集合 == 66 条集合。

## 4. 现状判定与动作序列

**B2 = 未达成。** 缺口按盘点量级估 **19–28 条**（29 none − ≥5 确认假阴性），审计后收敛。

| 序 | 动作 | 依赖 | 成本 | 可否并行 |
|---|---|---|---|---|
| 1 | **映射审计**：29 none + 8 weak 逐条人工确认载体，产出精确缺口清单（纯只读，grep 只作线索） | 无 | **1d** | ✅ 可与 2 并行 |
| 2 | 本裁决 oracle+critic 双审 → objective 表注 + 台账 Entry | — | 0.5d | ✅ |
| 3 | 按清单补缺口断言（每条 0.5–1h，含正反控） | 1 | **1–3d** | — |
| 4 | 映射闸（ctest 四项校验） | 1 | 0.5d | — |
| 5 | B2 登记 | 3+4 | — | — |

⇒ **不得**在订正生效前按编号级登记 ✅（那是「文本要求逐条断言、却按编号级宣称达成」= DoD 降格后仍宣称达成）。

**合法中间态**（供 planner 选择）：若需在缺口补齐前给 B2 一个 verdict 行，可登记
「**N/66 载体已登记（含 M 项有牙证据）+ K 条待审计**」（形态先例 = `§6.2 B3b` 的诚实 ⏳ + 触发条件），
⛔ 不得写成「已达成」。

## 5. 风险与防回归

| 风险 | 防护 |
|---|---|
| **滑坡**：把「无载体」改叫「豁免」 | 规则 A 逐条 + 规则 C 的集合相等校验（66 条集合硬编码）；豁免须逐条登记理由 |
| **映射自证**：映射指错（指向无关断言） | 标记**与断言同址共置**（不是自由文本锚）+ 邻域校验 + 规则 B 的有牙条款 |
| **组级掩盖** | 登记格式硬钉「66/66」，⛔ 禁「15/15 组」 |
| **手写映射表成为第 5 处口径源** | 映射表为**生成物**（由标记生成），不入口径源 |

**回滚路径（显式）**

| 阶段 | 回滚动作 |
|---|---|
| **未落地**（表注 / Entry 未落） | **拒签即回滚**，零成本 |
| **已落地**（标记 / 映射闸 / 部分断言已加） | ① 新裁决回退 objective 表注（append-only 追加订正 Entry）；② 移除 `INV-CARRIER` 标记与映射闸；③ **已补断言保留**（纯增量、无害）；④ 台账追加一条订正 entry |
