# design —— `cpptlm-cep-invariant-gate-teeth`

> **定位**:本 design 是 **C3-B 解析器** 与 **C3-C `### ⑥` 重述块格式** 的**同批定稿件**（per 台账 Entry #361 ③ D-6 注：「因 C3-C 写进冻结件后不可改，**块格式必须与 C3-B 的解析器在同一份 design.md 同批定稿**」）⇒ 本文件一旦落盘，**重述块格式即冻结**，解析器必须与之逐字一致。
> ⛔ 本 design **不新增裁决**：D-1~D-9 已由 Entry #359 / #361 落定;本文只把已裁裁决落成**可执行形态**（契约 / 正则 / 常量 / 签名 / 变异构造）。
> ⚠️ 唯一一处**口径澄清**（由用户硬约束推导，非新裁决）= **D-3.6 的围栏危险标记**，见该条。

## D-2 · 影子树 helper 的抽取（接口契约）

**文件**：`scripts/test/cep_test_shadow.sh`（**新增 · 非闸 · 不注册 ctest**）

```bash
# 用法: cep_shadow_reset <shadow_dir> [extra_cp...]
#   <shadow_dir>  = 影子树根（⛔ 会被 rm -rf 后重建）
#   extra_cp...   = 额外复制项（相对真实仓根），形如 test/cep_adr_structural_deferrals.json
cep_shadow_reset() {
    local shadow="$1"; shift
    local extra
    rm -rf "$shadow"
    mkdir -p "$shadow/docs" "$shadow/test"
    cp -r "$SHADOW_HELPER_ROOT/docs/adr" "$shadow/docs/adr"   # ← 两闸共用的必复制集合
    for extra in "$@"; do
        mkdir -p "$shadow/$(dirname "$extra")"
        cp "$SHADOW_HELPER_ROOT/$extra" "$shadow/$extra"
    done
}
```

> ⚠️ 函数名取 `cep_shadow_reset`（**不取** `reset`）—— `source` 进既有闸脚本后，通用名 `reset` 有**命名碰撞**风险（shell 无模块系统 ⇒ 全局函数表共享）⇒ 前缀化是共享 helper 的必要纪律。
> ⚠️ helper 以**自身位置**推导真实仓根（`SHADOW_HELPER_ROOT`）⇒ 调用方的 CWD 无关。

| 契约点 | 规定 |
|---|---|
| **必复制集合** | `docs/adr`（两闸都要）⇒ **单一真源**，⛔ 不得各闸自定 |
| **差异复制** | `extra_cp...` 参数化（structural 需 `test/cep_adr_structural_deferrals.json`;新闸不需要 ⇒ **⛔ 不得把 deferrals 复制进新闸的影子**） |
| **抽取方向** | 由 `cep_adr_structural_check.sh:52-57` 的 `shadow_reset` **提取** ⇒ 该文件改为 `source scripts/test/cep_test_shadow.sh` + 调 `cep_shadow_reset "$SHADOW" test/cep_adr_structural_deferrals.json` ⇒ **两份复制集合由同一实现参数化**（消除隐性分叉） |
| **共享契约登记** | helper 头注显式写「本文件是 `cep_adr_structural_check.sh` 与 `cep_decision_block_check.sh` 的**共享影子树机制** ⇒ 改动须同步两闸」 |
| **⛔ 禁止** | 新闸**自带** 4 行复制逻辑（= 被 oracle 判为隐性分叉的路径，per D-8） |

## D-3 · R-d 的 §2 提取（Python 实现 · **受控重复登记**）

> ⚠️ **受控重复登记**（per D-8 第 2 点）：本节的 §2 提取逻辑与 C++ 版 `test/cep_adr_parser.hh:250` 的 `read_section` **构成受控重复**（Python 无法调用 C++）⇒ 在 `cep_decision_block_check.py` **头注显式登记**本登记（先例 = `cep_adr_parser.hh:169-173` 对 `no_inv_adr_files` 的双实现自登记）;⛔ **不改** C++ 版。

### D-3.1 四步（**顺序是判据的一部分**，per D-1）

| 步 | 动作 | 实现 |
|:--:|---|---|
| ① | **先剥围栏** | `re.sub(r'^```.*?^```', '', text, flags=re.S\|re.M)` ⇒ **全文**剥 |
| ② | **再取 §2 章范围** | `re.search(r'^## 2\b.*$', text, re.M)` ⇒ 从该标题**之后**到**下一个** `^##\s`（`re.M`） |
| ③ | **仅 `###` 级** | 决策标题 = `^(#{2,6})\s*决策\s*(.*)$`;层级 ≠ 3 ⇒ **显式红 ①** |
| ④ | **匹配编号** | `re.match(r'\s*(\d+(?:\.\d+)?)', rest)` + **终止符校验**（D-3.2） |

> **为什么顺序不可换**：② 若先于 ①，则 §2 内围栏块的**行首 `## `**（举例 / 伪代码）会被「下一个 `^##\s`」截断 ⇒ 后续 `### 决策 N` **整体静默少计**。实测：22 份 ADR 的 §2 内**确有围栏**（13 份共 15 个），故该顺序**必须**先剥围栏。

### D-3.2 块 ID 契约（per D-2）

| 规则 | 说明 |
|---|---|
| **全匹配** | ID = `^\s*(\d+(?:\.\d+)?)` 之后**必须**是终止符（`空格` / `tab` / `:` / `：` / `(` / `（` / `-` / `—` / `、` / `,` / `。` / `/`）⇒ 否则 = **前缀 / 子串匹配** ⇒ **显式红 ②** |
| ⛔ 禁前缀 | `决策 1a` ⇒ ID 不是 `1` ⇒ 红（⛔ 不得 `stoi` 归一 / 不得 `grep -c "决策 1"` 双命中 `决策 10`） |
| ⛔ 禁整数归一 | `2.1` ≠ `2`（子决策**独立计块**，per D-2）⇒ 块 ID 是**字符串** |
| 实测形态 | `决策 1:…`（`ADR-CEP-00`）/ `决策 2(精简):…`（`ADR-CEP-02`）/ `决策 2.1` / `决策 2.2`（`ADR-CEP-06`）⇒ 终止符集须覆盖 `:` `(` |

### D-3.3 两条显式红 + 一条围栏危险标记

| # | 签名 | 触发 | 依据 |
|:--:|---|---|---|
| ① | `决策块标题非 ### 级` | 决策标题层级 ∈ {2,4,5,6} | **D-1 明列** |
| ② | `决策块编号非法` | 编号非 ASCII 十进制（例 `### 决策 Ⅻ`）**或** 非全匹配（例 `### 决策 1a`） | **D-1 明列**（非十进制）+ **D-2**（全匹配） |
| ③ | `围栏内含行首 ##` | §2 内的围栏块**内容**含行首 `## ` | ⚠️ **口径澄清**（见下） |

> ⚠️ **D-3.3③ 的口径澄清（本 change 唯一的实现级新增规则）**
>
> **问题**：D-1 的四步是「剥围栏」⇒ 围栏内容对计数**不可见** ⇒ 「围栏内含行首 `## `」这一变异在**正确实现下不会改变计数** ⇒ 若把 AC-4 写成「鉴别性变异」（正确实现绿 / 错误实现红），则与用户硬约束「**每条变异必须按正确原因红**」冲突。
> **裁决**：AC-4 取**显式红**形态 —— 闸**主动标记**「§2 内存在含行首 `## ` 的围栏块」。
> **理由（非任意）**：C++ 版 `read_section`（`test/cep_adr_parser.hh:250`）在 `^##\s` 处截断且**不能**剥围栏 ⇒ 该围栏对**既有消费者**是**活雷**（一旦被 `read_section` 消费 ⇒ §2 截短 ⇒ 决策块静默少计）⇒ 闸须把它**暴露**出来，而不是依赖每个消费者的健壮性。
> **基线**：实测 22 份 ADR 的 §2 内**危险围栏数 = 0** ⇒ 该红**基线绿**，不产生历史债。
> ⛔ **不新增计数口径**：③ 只标记**危险围栏**，不改变任何决策块的计数结果。

### D-3.4 基线实测（立项前已完成 · 22/22）

| 口径 | 结果 |
|---|---|
| 全文件 `^### 决策` 计数 | 合计 **125** |
| **①剥围栏 → ②取 §2**（本闸口径） | 合计 **125**，**逐份**与上表相等 |
| ②取 §2 → ①剥围栏（错误顺序） | 合计 **125**（今日恰好同值 ⇒ **变异④ 是唯一能鉴别顺序的探针**） |
| 显式红 ①② | **0** |
| 危险围栏 ③ | **0** |

## D-4 · 计数快照的格式与授权式更新

**文件**：`test/cep_decision_block_snapshot.json`（**闸只读**）

```json
{
  "schema": "cep-decision-block-snapshot-v1",
  "authorized_by": "Entry #N",
  "count": 22,
  "total": 125,
  "files": { "ADR-CEP-00-platform-charter-and-governance.md": 4, "...": 3 }
}
```

| 契约点 | 规定 |
|---|---|
| **键** | `files` = **逐份 basename → 计数**（22 键）;⛔ **不得**用聚合值单键（否则无法定位偏离文件） |
| **`total`** | 必须 == `sum(files.values())` ⇒ 闸校验（不一致 ⇒ 签名 `快照文件非法`） |
| **`count`** | 必须 == `len(files)` ⇒ 闸校验 |
| **`authorized_by`** | 形如 `Entry #N` 且台账**存在**该 Entry ⇒ 闸校验 ⇒ 「更新须带台账 entry id」成为**机器约束**（per metis P0-4） |
| **更新方式** | **⛔ 闸不写快照**（只读）;更新 = 手工改文件 + 台账登记授权号 ⇒ 任何快照变更都**必然**带台账痕迹 |
| **⛔ 禁止** | 期望值从**被检对象自身**或 `NUMBER-MAP` 派生（= 自证复燃，per D-6） |

## D-5 · R-c 双向对账的实现

### D-5.1 闸内常量（⛔ 期望值的唯一来源）

```python
CARRIER_ADR = "ADR-CEP-00-platform-charter-and-governance.md"
CANONICAL = [
    "ADR-CEP-01-fabric-collective-plane.md",
    "ADR-CEP-02-coherence-barrier-semantics-clarification.md",
    "ADR-CEP-03-fabric-collective-plane-internals.md",
]
RESIDUAL_TOKENS = ["ADR-CEP-01", "ADR-CEP-02", "ADR-CEP-03"]   # 反向对账的 3 个完整编号
```

### D-5.2 正向（文档语料根）

| 判据 | 规则 | 红因签名 |
|---|---|---|
| 三份存在 | `CANONICAL` 每份 basename 必须在语料 `docs/adr/` 内 | `三份 ADR 缺失` |
| **无同号拆出件** | 语料内任一 basename 满足 `re.match(r'^ADR-CEP-0[123](?![0-9])', basename)` 且**不属** `CANONICAL` ⇒ 红（⛔ `A/a` 后缀视为拆出件） | `存在同号拆出件` |

> ⚠️ **作用域极限（必须写进 design.md 的诚实边界）**：`^ADR-CEP-0[123]` 只覆盖**同号**派生件（`ADR-CEP-02a` / `ADR-CEP-01-addendum`）⇒ **新编号拆出件不在 R-c 覆盖内** ⇒ 靠 ①`cep_adr_structural_check.sh` 的分区完整性 + ②`ADR-CEP-00 §3` supersede 表兜底 ⇒ ⛔ 不得写成「R-c 全覆盖」（否则未来会当误红报）。

### D-5.3 反向（文档语料根 · carrier）

**重述块定位**（⛔ 与 C3-C 写进冻结件的格式**逐字一致**）：

| 步 | 规则 |
|:--:|---|
| ① | 在 carrier 文本中找 `^## Status Update` 标题行**含 `2026-11-12`** 的那一则 SU |
| ② | 在该 SU 内找 `^### ⑥` 标题（**全角数字 ⑥**） |
| ③ | 块 = 从 `### ⑥` 标题**之后**到**下一个** `^#{2,3}\s` 之间的正文 |
| ④ | 块内 bullet = 以 `- ` 开头的行 ⇒ **必须恰 3 行** |
| ⑤ | 每行**恰含 1 个** `RESIDUAL_TOKENS` 中的完整 token（正则全匹配 `ADR-CEP-0[123]` 边界）⇒ 否则红 |
| ⑥ | 三个 token **各 ≥1** 次 ⇒ 否则红 |

| 红因签名 | 触发 |
|---|---|
| `重述块缺项` | 三个 token 未各 ≥1（反向对账缺项） |
| `重述块格式不符` | bullet 数 ≠ 3 / 某行 token 数 ≠ 1 / 定位不到 `### ⑥` |

> ⚠️ **定界理由**（metis P0-1）：`ADR-CEP-00` **全文**今已含 `ADR-CEP-01`（12 处）/ `ADR-CEP-02`（5 处）/ `ADR-CEP-03`（6 处）⇒ 若闸做全文 grep，删掉重述块一行**永不红**（闸无牙）⇒ 必须定界到 `### ⑥` 块。

### D-5.4 触发条件（**表**取文档语料根 · **引用解析**取真实仓根）

> ⚠️ **双根读法**（per D-7 的兼容澄清，登记于台账 **Entry #362 ③ 订正-2**）：**表本身**在 carrier ADR 内 ⇒ 属**文档语料** ⇒ 取 `--root`（否则「清空某行判定方式」的变异**永不红**）;而表内 code span 的**被指物存在性** ⇒ 取**真实仓根**（影子树不含 `test/` 与台账 ⇒ 在影子根解析会**恒红**）。

| 步 | 规则 |
|:--:|---|
| ① | 找 `^## Status Update` 标题行含 `2026-11-11` 的 SU（**既有** SU ⇒ 今日即可判） |
| ② | 该 SU 内找 `^### ②` 标题 ⇒ 其下**第一张** Markdown 表 |
| ③ | 解析表头 ⇒ 必须存在含「判定方式」的列 ⇒ 否则红 `触发条件表结构不符` |
| ④ | 数据行（跳过分隔行）⇒ 必须**恰 3 行** ⇒ 否则红 `触发条件表结构不符` |
| ⑤ | 每行的「判定方式」列 ⇒ 必须含 **≥1 个 inline code span** 且**≥1 个可解析**（4 类，见 D-6）⇒ 否则红 `引用解析缺失` |

## D-6 · 4 类引用的可解析判定

| 类 | code span 形态 | 可解析条件（**真实仓根**） | 今日命中 |
|:--:|---|---|---|
| **(a) 仓内路径** | `^[\w./-]+\.(md\|hh\|cc\|h\|py\|sh\|json\|tsv\|yaml\|yml\|txt)$` | `os.path.exists(REAL_ROOT / span)` | T3 行 `test/cep_adr_parser.hh` ✅ |
| **(b) 台账 Entry** | `^Entry #\d+$` | 台账含 `^### Entry #N` | 今日无命中（无妨） |
| **(c) ADR 短名** | `^ADR-CEP-[0-9A-Z]+$` | glob `docs/adr/<span>-*.md` ≥1 命中 | T1 / T2 行 `ADR-CEP-01` ✅ · T3 行 `ADR-CEP-02` ✅ |
| **(d) 符号** | `^[A-Za-z_][A-Za-z0-9_]*\(\)$` | 取**同格内最后一个 (a) 类路径** ⇒ 该文件内命中**定义式** | T3 行 `owner_specs()` ✅ |

**定义式判定**（per metis P0-3「归属写死」）：

```python
DEF_RE = r'^\s*[\w:<>,\s\*&~]*?\b' + re.escape(name) + r'\s*\([^)]*\)\s*(?:const\s*)?(?:\{|;|->)'
```

⇒ 要求**行首声明形态**（类型前缀 + `NAME(...)` 后接 `{` / `;` / `->`）⇒ ⛔ 排除裸调用行（`owner_specs()` 独占一行 ⇒ 前缀为空 ⇒ **不**命中 ⇒ 不误判）。

> **今日实测**（per D-6 的 4 类表）：T1 行唯一 code span = `ADR-CEP-01` ⇒ 类 (c) ⇒ glob `docs/adr/ADR-CEP-01-*.md` = 1 命中 ⇒ 可解析;T2 行同;T3 行 = `test/cep_adr_parser.hh`(a) + `owner_specs()`(d) + `ADR-CEP-02`(c) ⇒ 可解析 ⇒ **三行全绿**。
> ⚠️ **勿忘 metis P0-2**：若只实现三类（无 (c)），T1 / T2 行**首日红** ⇒ 实施者极可能把判据 weaken 成接受简写（§13.1 警告的退化路径）⇒ (c) **必实现**。

## D-7 · 双根语义（⛔ 必须显式，否则变异② 永不红）

| 语料类别 | 根 | 理由 |
|---|---|---|
| **文档语料** = ADR 集合（`docs/adr/**`）· 重述块 · §2 计数 · **触发条件表** | **`--root`（影子树）** | 否则影子树里的 `ADR-CEP-02a-*.md` **永远看不见** ⇒ AC-13 的变异② **永不红** ⇒ 闸无牙;同理「清空某行判定方式」的变异③ 也**永不红** |
| **被指物存在性** = (a) 仓内路径 · (b) 台账 · (c) ADR 短名 glob · (d) 符号定义式 | **真实仓根 `REAL_ROOT`** | 影子树**只含** `docs/adr`（+ 可选 `test/`），⛔ 不含台账与闸外文件 ⇒ 若在影子根解析 ⇒ 全部不可解析 ⇒ 恒红 |
| **快照读取** | **真实仓根** | 快照是**闸外**的期望值载体，⛔ 不是语料 |

> ⚠️ 本条是对台账 **Entry #361 ⑤**「`--root` 只作用于文档语料，存在性/台账解析固定真实仓根」的**兼容读法澄清**（登记于 **Entry #362 ③ 订正-2**）：「存在性」读作「**被指物**存在性」，**不是**「ADR 语料存在性」⇒ 两者不再冲突。

## D-8 · 红因签名表（判据 ↔ 稳定签名）

> wrapper 断言的是**签名**，⛔ 不是 rc。签名一旦发布即**冻结**（与重述块格式同理）。

| 签名 | 归属 | 触发 |
|---|---|---|
| `决策块计数快照偏离` | R-d | 逐份计数 ≠ 快照（含文件名 / 期望 / 实得 / 差值） |
| `决策块标题非 ### 级` | R-d | 决策标题层级 ≠ 3 |

## D-9 · 变异执行框架（bash wrapper）

```
① 基线正控（rc=0）              ← AC-1
② R-d 变异①~④（各带签名断言）   ← AC-4~AC-7
③ R-d 还原（rc=0）              ← AC-8
④ R-c 变异①~③（各带签名断言）   ← AC-12~AC-14
⑤ R-c 还原（rc=0）              ← AC-15
```

| 规则 | 说明 |
|---|---|
| **影子树** | ⛔ **全部变异只在影子树**（真实仓零改动）⇒ 用 D-2 的 helper |
| **断言形态** | `rc ≠ 0` **且** 输出含该变异的**签名** ⇒ 二者缺一即判失败（⛔ 不以 rc 充数） |
| **还原必绿** | 每条变异**独立**还原并复跑 ⇒ 4/4 与 3/3 还原后 rc=0（⛔ 否则闸有副作用） |
| **双闸并验** | 变异②（同号拆出件）⇒ **同时**跑 `cep_adr_structural_check.sh`，两条闸**各报各的签名**（AC-13） |
| **基线正控** | 变异前先跑一次基线，**必须绿**（AC-1） |
