# Design — cpptlm-cep-canonical-flow-parser-scope

> **口径**: 台账 **Entry #149**(裁决 + 陷阱条件精确化 + 验证矩阵)· **#142**(陷阱登记)· **#141**(诱因)
> **范围**: **1 个 inline 函数**的解析范围 + **4 个合成用例** —— **零 ADR 改动 / 零 ABI / 零 invariant 编号**

## 1. 根因(代码实测)

```
    std::istringstream in(adr_text);
    while (std::getline(in, line)) {          // ← 对**全文**逐行,无范围约束
        ...
        bool all_digit = true;
        for (char c : num)
            if (c < '0' || c > '9') all_digit = false;   // ← **ASCII** 判据(圈号 `①` 不算)

```

调用点 `evaluate_canonical_flows`(:439-443):`flows.size() != 10` ⇒ **FAIL** + detail「权威源格式已变」。

**canonical 10 流表的权威位置**:`ADR-CEP-02` 的 `## 2. 决策:…` 段,行 **40 ~ 49**(`| 1 | `request` | … |` ~ `| 10 | … |`)。

## 2. 触发条件(精确化 —— 本 design 的核心贡献)

Entry #142 ④ 记的是「SU」。**实测复核后精确化**:

| 条件 | 精确表述 | 依据 |
|---|---|---|
| **触发面** | **不止 SU** —— 现行实现扫**全文** ⇒ `## 3.` 之后**任意段**(§3 ~ §7 / SU / 未来附录)追加同类表格**同样触发** | 现行实现无范围约束 |
| **触发条件 ①** | 首格为 **ASCII 数字**(C++ 判据 `c < '0' \|\| c > '9'` ⇒ **Unicode 圈号 `①` 不触发**) | 代码实测 |
| **触发条件 ②** | 第二格为**新标识符** —— 解析结果是 `set` ⇒ **同名去重** ⇒ 第二格若是 `request` 等已有流名则**不触发** | 代码实测 |
| **当前规避的有效性** | Entry #142 的文档侧规避(首格改圈号)**仅因圈号不是 ASCII 数字**才有效 ⇒ **纯人肉约定** ⇒ 不可持续(ADR 只能追加 SU ⇒ 必然复发) | 代码实测 |
| **副产物** | 现行实现对**真实 ADR** 实测得 **10** 条 ⇒ 与 `size()==10` 断言一致 ⇒ **当前无既存红**;⚠️ 用 Unicode `isdigit()` 语义复刻会得 **13** 条 ⇒ **复刻实现必须逐字对齐 ASCII 判据** | PoC 实测 |

## 3. 方案对比(3 选项)

| # | 方案 | 挡住 SU? | 挡住 §3+? | 结构异常 | 评价 |
|---|---|:---:|:---:|:---:|---|
| **A** | **只解析第一个 `## Status Update` 之前**(Entry #142 ④ 登记的「正确修法」) | ✅ | ❌ **挡不住** | 安全失败 | ⚠️ **覆盖面不足** —— §3 ~ §7 的表格仍会触发 ⇒ 不选 |
| **B** | **只解析 `## 2.` 段**(本 design 选定) | ✅ | ✅ | **安全失败**(0 条 ⇒ FAIL) | ✅ **覆盖面完整**;范围 = canonical 10 流表的**权威位置** |
| **C** | 只解析「第一张含 10 个反引号名字的表」 | ✅ | ✅ | 静默通过(可能取错表) | ❌ **静默失败风险** —— 结构异常时不报错 ⇒ 不选 |
| **D** | 保留全文扫描 + 要求流名必须是反引号标识符 | ✅ | ✅ | 静默通过 | ❌ 与 B 覆盖面相同,但**不解决「解析了错表的表」**且**放宽了流名格式约束** ⇒ 不选 |

**选定 B**,理由:
1. **一次性堵一类**(§2)—— 挡住**全部**非 §2 段,而不只是 SU;
2. **失败方向安全** —— 若 ADR 结构变了(§2 段改名 / 移位)⇒ 解析得 0 条 ⇒ 判据**红** + detail 提示「权威源格式已变」
   ⇒ **不引入漏检**(方案 C / D 会静默通过 ⇒ 危险);
3. **改动面最小** —— 只加一个「截取 §2 段」的辅助,其余判据逻辑**零改动**。

## 5. 判据形态的**反向**说明(须显式登记)

既有 `*_reverse_verify.sh` 的语义 = 「**毒化载体 ⇒ 判据必红**」(鉴别力:证判据会生效)。

本 change 修的是**误报**(判据因 ADR 正常追加而**假红**)⇒ 正确形态 = 「**毒化 ⇒ 判据仍绿**」
⇒ **不新建** reverse_verify 脚本;改为在 `test/test_cep_collective_plane_contract.cc` 内
用**合成 ADR 文本**做 4 个用例 ⇒ **同源、随 ctest 跑、无额外脚本**。

⚠️ **铁律 ② 仍满足**:每个毒化用例都断言「解析集 == 10」**且**「**不含**注入名」
⇒ 若解析器退化为「仍收 SU 表格」,用例**必红且归因命中**(缺 1 条 ⇒ size 变 11 ⇒ 集合大小断言红)。

## 6. 后果 / 代价

| 面 | 后果 |
|---|---|
| **判据严格性** | **放宽**(从「全文任何数字表格」收窄到「§2 段」)⇒ **等价于**「只对权威位置负责」⇒ **更对**,不是更松 |
| **漏检风险** | **无** —— 结构异常 ⇒ 0 条 ⇒ FAIL(安全失败) |
| **ADR 面** | **零改动**(`ADR-CEP-02` / `ADR-CEP-01` 正文与清单均不动) |
| **其余判据** | **零改动**(`evaluate_canonical_flows` 的 collective 侧扫描逻辑不动) |
| **测试面** | 既有用例**零改动** + 4 个合成用例(不碰真文件 ⇒ **零副作用**) |
| **遗留** | **B5**「闸边表 ≠ SU 边表」—— **显式登记**,不改代码(Phase 3) |
