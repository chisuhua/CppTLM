## Goals / Non-Goals

### Goals

- **G1** S1 / S3 两个场景 spike 落地,**判据可执行**且**注册为 ctest 回归门**
- **G2** 3 个场景的判据固化为 **delta capability**(`cep-poc-spike-verification`)→ 归档后进 main specs,成为系统契约
- **G3** **S1-1 ~ S1-5** 在本 change 内**可寻址**(逐项带消费时机 / 触发条件)
- **G4** 消除「Stage 1 准入判据只能靠纸面辩论」的状态

### Non-Goals

- **NG1** ❌ 不实现 Stage 1 的任何协议插件 / stub cache / fabric(那是队列 #3 ~ #8)
- **NG2** ❌ 不改任何既有契约(per C1:「不是架构变更」)—— 只**新增**一个能力;**且不承载 S1-5 的映射表规约**(该规约已在 `ADR-CEP-12 §8.3` 闭合,缺的只是「表体 + contract test」,二者均需 adapter)
- **NG3** ❌ 不进 `ModuleFactory` / 不注册 ABI / 不暴露公共 API
- **NG4** ❌ 不在本 change 内**消费完** S1-1 的**建图层** / S1-2 / S1-3 / S1-4(见 D4 的逐项三层判定与 owner 重指向)
- **NG6** ❌ 不把 S3 的「顶点集 == 散文」当机器判据 —— 判据必须是**机器可导出的集合**(per D6)
- **NG5** ❌ 不引入新依赖

## Decisions

### D1:落地形态 = **正式 openspec change + 1 个 delta capability**

**决策**:建立 `openspec/changes/cpptlm-cep-poc-spike/`(4 件套),其 delta spec 新增 capability **`cep-poc-spike-verification`**。

**理由**(裁决「落地形态待 DRI 裁决」):

| 备选 | 评价 |
|------|------|
| **(a) 只留 `examples/` 里的 spike,不开 change** | ❌ 判据仍是「某次会话的产物」—— 无契约、无 tasks、无归档语义;S1-1~S1-5 无处安放;队列 #2 的「承接」承诺落空 |
| **(b) 正式 change,但**无 delta spec**(纯实现型 change) | ❌ 归档时**无 delta 可合并** → 判定判据留在 change 目录里,归档即失联;与 umbrella 的做法不一致 |
| **(c) 正式 change + delta capability** ✅ | ✅ 判据进 **main specs** → 归档后仍是**系统契约**;S1-1~S1-5 有 tasks.md 承载;与 `umbrella` 的「契约层 / 实现层分离」风格一致 |

**关键洞察**:spike 本身「零生产影响」,但它**产出的判据**有长期价值 —— 那就把**判据**而不是**代码**做成契约。代码留在 `examples/`(可丢弃),契约进 main specs(不可丢)。

**代价**:需要维护一份 delta spec(3 场景 × 判据 × 反向验证)。**接受** —— 否则「Stage 1 准入判据靠纸面辩论」的现状原样保留。

### D2:S1 / S3 各自**独立单文件**,与 S2 同形

**决策**:`examples/cep_poc_spike_s1.cc` / `cep_poc_spike_s3.cc`,各自 `main()` + 退出码即判定。

**理由**:S2 已确立先例(`examples/cep_poc_spike_s2.cc` + `examples/CMakeLists.txt` 的 `add_test`)。**三场景同形** → 读任一个都能立刻明白「spike 是什么形态」;退出码即判定 → ctest 直接用。

**排除**:合成一个 `cep_poc_spike` 可执行文件跑 3 场景 —— ❌ 会让「某场景失败」变成「整个文件失败」,定位成本上升,且偏离 S2 已验证的形态。

### D3:判据的**反向「有牙」**验证是**硬要求**(每场景 ≥ 1 条)

**决策**:S1 / S3 各**必须**含至少一条「若判据实现退化 → 该用例必须变红」的反向断言。

**S3 的强制形态**(per 规格 §3.3):把顶点**降级**回 `(协议实例, vc_id)` 重建依赖图 → 环检测器**必须报出环**。只跑正向的 S3 = 没跑。

**S1 的形态**:把期望 `perm` 序列**故意改错一项** → 逐序列点比对**必须报出不一致**。

**理由**:本仓已有「反向验证」文化(`scripts/test/cep_decl_reverse_verify.sh` 的 12 条反向断言)。**没有反向验证的判定器 = 恒绿** → 等于没跑。

> **过强且漏项**。审查发现:S1-1 的原文义务是**「建立**」而非「定义」;另有 3 项**从未被任何 S1-x 覆盖**的孤儿前置。

#### 4.5 「已判定不触发」≠「可以忽略」—— 复核节奏

| 项 | 度量口径(须钉死) | 复核节奏 |
|---|------|------|
| S1-2 | `protocol_instance.schema.json` 中 `status == "implemented"` 的**声明数**(当前 **0**) | 每次新增协议实例声明时 |
| S1-3 | 同上文件中 `status != "excluded"` 的**声明数**(当前 **2**) —— ⚠️ 不可用「adapter 实例数」(`07 号:676` 登记 **16** 个 adapter 实例,会让该条件**早已满足**) | 每次新增网络 / 实例声明时 + 每次 §4.0 排期复核 |
| S1-4 | `fabric.json` 是否**已被非 spike 的回归门消费** + 是否已纳入 M1 冻结集 | 每次新增消费方时 |

> **纪律**:「已判定不触发」是**带度量、带节奏**的判断,不是「忽略」。每项的触发条件一旦满足,**必须**在当次排期复核中显式记录。

### D5:S1 判定**只比 `perm` 投影**,不判定协议插件内部瞬态

**决策**:S1 的比对对象是「实际投影 `perm`」与「由 6 态机推导的期望 `perm`」,**逐序列点**比对。

**理由**:per 规格 §3.1 —— Stub Cache 对外**只暴露 4 个稳定态**,协议插件私有瞬态态 `T` **不泄漏**(`INV-CEP-05-IC1`)。判 `perm` 投影即覆盖该不变量;判内部瞬态则是越界(且会因实现细节漂移而误报)。

### D6:S3 的顶点集 / 边集须**机器可导出等值**,且报环**成因必须标注**

**决策**:S3 的判据不得是「顶点集 == ADR 散文」,而应是**可从仓内机器面导出的集合**:

| 对象 | 机器可导出定义 | 实测真源 |
|------|--------------|---------|
| **顶点集** | `∪_{n ∈ fabric.json.networks} {(协议实例, n, vc) : vc ∈ vc_binding[n].values()}` → **8** 个 | `include/tlm/cep/fabric.json`(非冻结)· `examples/cep_poc_spike_s2.cc:32-35` 的引用来源行先例 |
| **依赖边集** | ArchForge `32 号 §6.0.3` 的**逐网络**边表并集 → **8** 条,**跨网边 = 0** | `compute_noc`: VC0→1/2/3, VC1→3, VC3→2 · `ualink_fabric`: VC0→3, VC1→3, VC2→3 |
| **降级后** | 顶点并为 4 个 `(协议实例, vc_id)` → 边集并集出现 **2↔3** 环 | 推导自同一张边表 |

**② 报环的成因标注(硬要求)**:该环的成因 SHALL 标注为「**网络别名造成的假环**」——
两网共享 `vc_id` 值域 0-3,扁平化把**网内**边误并为跨网边 → per `ADR-CEP-09:223-224`「合并边既可能制造**假环**,也可能掩盖真环」。

> **必须修正的既有错误因果**:规格 §3.3 的失败含义 ① 写「报环 ⇒ per-network 顶点下**存在真实的跨网依赖**」——
> 按权威边表**跨网边为 0**,该结论**不成立**。若沿用,这条**错误因果**会随 delta spec 归档进 `openspec/specs/`(永久契约)。

**③ verdict 粒度**:S3 输出 SHALL **逐 `(network, vc)` 标注**无环结论,不得只给全局结论(per `ADR-CEP-09:223-224`)。

**④ 反向断言的生命周期**:一旦出现**第 3 张网**(S1-3 的触发条件),扁平化可能**掩盖真环** → 「降级后必须报环」这条反向断言**可能失效**(降级后不报环,而那恰恰是更危险的情形)。⇒ 该断言的**有效期**止于第 3 张网出现之前,届时必须重新设计(否则恒红)。**此项当前无人登记 → 本 change 登记**。

### D7:「判定结论」与「判据退化」分离;S1-5 规约**不**进本 capability

**D7-a 判定语义分离(结构性修正)**:

| 情形 | ctest 用例 | 交付物 |
|------|:---:|------|
| **判据实现退化**(恒真 / 漏检) | 🔴 **红** | 缺陷报告 |
| **判定结论为红**(S1 失败含义 / S3 失败含义) | 🟢 **仍绿** | **结论作为交付物登记**(这是本 change 的**产出**,不是失败) |

> **为什么必须分离**:`ADR-CEP-05:296` 登记「判据 2 状态 ✅ **已触发**(2026-10-22)—— `moesi_gpu` 有静默 `E→M`,判据 (b) 成立 → **4 值 `perm` 确无法表达**」→
> **R-2 已经命中** ⇒ S1 的**设计结局本就是「投影表达力不足」**(规格 §3.1 失败含义原文:「`perm` 4 值投影的表达力不足 → R-2 的**需求本体**成立」)。
> 初稿的验收口径「3 个用例全绿」会**把这个正确结论变成不可归档** → 且因 KPI slot 无法释放而**级联阻塞整个 Stage 1**。

**D7-b S1-5 的规约不进本 capability**:

- 规约**已闭合**于 `ADR-CEP-12 §8.3`(分层纪律 + 「映射表由 adapter 承担(非恒等)」);缺的是**表体 + contract test**,而二者**都需要 adapter**;
- spike 硬边界**无 adapter** → 在此写表 = **凭空发明**(6→3 映射无 canonical 答案);
- 「6 类词表不落传输层」**已有机器强制**(`cep_docs_sync_check.sh` 第 10 组)→ **无需新闸**;
- 放进本 capability 会与它自身的「**恰好有 3** 个判定场景」文本冲突,且制造「声称可自动化却无自动化」的同款结构。
